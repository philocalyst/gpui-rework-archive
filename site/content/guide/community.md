A framework grows through the people who use it. GPUI-CE welcomes questions, issue reports, and contributions, including first attempts that need discussion and revision.

## Join the conversation

The [GPUI-CE Discord](https://discord.gg/vNdskJSfWd) is the place to talk through an idea, ask a question, or find the people working on the next part of the framework. For a reproducible bug or a concrete proposal, [open an issue](https://github.com/gpui-ce/gpui-ce/issues).

A useful issue includes what you expected, what happened, your operating system, the revision or crate version, and the smallest example that demonstrates the problem. Screenshots help with rendering problems; a runnable example helps even more.

## Contribute with context

Describe the problem before describing the patch. Explain the behavior you want to change, how someone can exercise it, and how you checked the result. For API changes, include the effect on existing applications.

The project’s README describes GPUI as a framework “Made by Humans” and links to the Rust Foundation’s AI policy. Read the current [contribution expectations in the README](https://github.com/gpui-ce/gpui-ce/blob/main/README.md) before submitting a contribution. Be prepared to understand, explain, and maintain the work you submit.

## Improve the field guide

Documentation lives in Markdown under `site/content`. Shared templates handle navigation, code highlighting, and interactive examples. A correction to an explanation is as welcome as a new example.

See the [colophon](@/colophon.md) for how the site is made, and the [source repository](https://github.com/gpui-ce/gpui-ce) for the code behind it.
