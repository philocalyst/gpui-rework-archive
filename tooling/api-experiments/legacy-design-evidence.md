# Element API design evidence

These experiments compare API shapes for reflecting, selecting, and mutating erased GPUI elements.
Standalone prototypes exercise Rust typing and dispatch; they are not substitutes for GPUI behavior
or performance tests.

## Design evidence matrix

| Area | Evidence and commands | Design choice and limits |
| --- | --- | --- |
| Shape | Current isolated prototype passed `CARGO_TARGET_DIR=tooling/api-experiments/shape/target cargo run --release --manifest-path tooling/api-experiments/shape/Cargo.toml`. Its generic compile-fail fixture exited 101 with the intended explicit-registration diagnostic: `CARGO_TARGET_DIR=tooling/api-experiments/shape/target cargo check --manifest-path tooling/api-experiments/shape/compile_fail/Cargo.toml`. | Keep the aggregate `Element` derive for lifecycle delegation, builtin opt-ins, and per-element capability registration. Do not fold field description into behavioral reflection: derives cannot enumerate arbitrary downstream trait impls or safely infer a callable trait adapter from fields. Generic custom capabilities need explicit registrations because trait bounds can differ by monomorphization; selected builtins are inferred by the aggregate derive. |
| Composition | Production verification passed: 436 GPUI library tests and 21 macro tests, including composition and inheritance cases. The isolated proof examples are available with `cargo check --manifest-path tooling/api-experiments/composition/Cargo.toml --example positive` and `... --example indexed_positive`; `... --example indexed_negative_repeated` is expected to fail. | Start groups with tuples and add requirements with `.and(...)`; keep `trait_set![...]` as an optional named/ad hoc group. A plain `AllOf<A, B>` cannot prove arbitrary native trait bounds. Indexed trees can prove membership, but repeated tokens and shared supertraits make inferred proof paths ambiguous. Umbrella traits are useful reusable groups, but do not supply adapters for erased elements. |
| Lenses | The typed projection and erased-registry prototypes are in `lenses/`. Their documented checks are `cargo test --manifest-path tooling/api-experiments/lenses/Cargo.toml` and `cargo run --manifest-path tooling/api-experiments/lenses/Cargo.toml --example registered_consumer`. The standalone checks are prototype evidence, not a fresh GPUI validation. | Use `Capability<Target, Key>` with an explicit typed projection on each concrete element. A key distinguishes two views with the same trait object type. An exact-type lens alone cannot discover a capability across heterogeneous erased elements; runtime matching still needs a schema registry. Mutable projections are lent one at a time. Generic methods, GATs, and unfixed associated types need membership-only registration or an object-safe companion trait. |
| Components | With the shared root target directory, `frontier-scenarios` passed both `cargo check --example frontier` and `cargo run --example frontier`. `components --test wrapper` ran 3 tests, all passed: pre-render borrowing/consumption, component identity and one-time consumption, and derived `Element` delegation. | `Select::component::<Type>()` borrows a `RenderOnce` component before its one-time render; its rendered root remains a separate node. Use a durable derived `Element` when capability state must stay on the receiver after conversion. The retained outer wrapper prototype changes lifecycle/ownership and is not the selected API. |
| Bindings and dispatch | The standard-library-only `frontier-dispatch` tests and release executable passed: `cargo test --manifest-path tooling/api-experiments/frontier-dispatch/Cargo.toml --target-dir /tmp/frontier_dispatch_trial_target` and `cargo run --release --manifest-path tooling/api-experiments/frontier-dispatch/Cargo.toml --target-dir /tmp/frontier_dispatch_trial_target`. In one stable-schema, one-call sample, the measured values were 9.67 ns/element for hash lookup, 2.53 ns for prebound, 2.51 ns for trait-object dispatch, and 2.96 ns for dense index. | Keep safe typed adapters and bind selector table groups once per schema. The toy results are directional measurements of a std-only model; they are not GPUI performance claims. Dense indices require a global schema ordinal contract. A universal trait object weakens the per-capability access boundary. Avoid adding redundant cached table slots without production measurements. |

Use keyed capabilities for multiple projections, and object-safe traits for callable lenses. Selector examples compile here; the fixture does not open a window to exercise layout callbacks. |

## Current API shape

The production design combines concrete `of::<Type>()` queries, authored component queries,
object-safe keyed capability views, tuple and `.and(...)` requirement composition, and an aggregate
`Element` derive. `select_mut` lends a temporary view while preserving the matched element. Existing
selector callbacks can run again during measurement or layout retries, so mutation should be
idempotent and local to the matched element.

The external consumer experiments above used the shared workspace target directory on this checkout. None of the isolated timing results should be used as a GPUI
performance claim.

The final GPUI timings, typed table sizes, allocation counts, traced histogram-growth outlier,
and baseline comparison limits are recorded in
[`docs/element-query-performance.md`](../../docs/element-query-performance.md).
