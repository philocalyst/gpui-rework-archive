Backend observations (separate from timing results)
====================================================

The observer was run once per app on private Xvfb :97 with LUNA_STAGES=1.
Those runs validate startup/pixel and expose the selected path; their startup
and click values are diagnostic and excluded from any timed comparison.

GPUI: the fixture requested RendererPolicy::Auto; its first acknowledged frame
reported `LUNA_PRESENT,ReferenceCpu,0,0,14599`. The Xvfb host did not select a
GPU renderer.

MyGo: with MYGO_GPU unset, its first frame reported `drawn in memory`. This is
the software rendering/pixel-present path, not the GPU renderer. The log does
not independently name the GTK widget subtype or a driver.

NanoUI: the pinned Linux source uses its CPU/Cairo path. The first view callback
ran; this is source-backed backend identification, not a runtime GPU report.

Accessibility: GPUI was built with the x11 feature and AccessKit backend
dependencies. A separate session-bus check ran:

```text
busctl --user get-property org.a11y.Bus /org/a11y/bus org.a11y.Status IsEnabled
Failed to get property IsEnabled on interface org.a11y.Status: The name is not activatable
```

This observed session had no activatable `org.a11y.Bus` service at probe time;
it does not prove that AccessKit was absent from the binary, and the benchmark
does not claim an active assistive-technology client. MyGo's GTK/ATK support is
available in its Linux build; NanoUI's pinned snapshot has no accessibility
support. Do not treat these unequal accessibility configurations as matched.
