# Interior caret pair without constructing `Cluster`

Read-only review pin: `1a1206f1c5ebe9162830c16049dd27b1fba31074` from `/tmp/gpui-caret-pair-root`'s Git object database. I used `git show <pin>:<path>` for source; I did not edit a checkout or build. The review is limited to the proposed interior-boundary branch in `CursorGeometry::geometries_at` and its exact compatibility with current Parley cursor geometry.

## Result

The proposed interior-only branch is supported by the pinned source, provided it uses the byte map as a proof of source contiguity, validates both entry indices, requires one line and one run plus actual direction-ordered visual adjacency, and leaves every failed predicate on the existing fallback. This is a stronger and cleaner formulation than constructing two `Cluster`s, reading their ranges/directions/hard-break flags, and then proving they share an edge. It can avoid both `Cluster` reconstruction and the geometry callback on the common branch. The endpoint and exception behavior should stay on the current path for the first slice.

## Source proof

`CursorGeometry::new` in `reactivity/vendor/parley/src/editing/geometry.rs:43-75` walks each line/run and emits one `Entry { path, offset }` per `run.visual_clusters()` item. Within a run it pushes the current f32 `offset`, then executes `offset += cluster.advance()` before the next visual cluster. For each nonempty cluster text range it fills every covered byte with that entry index. It rejects overlapping source ranges. Entries in a run therefore remain in exact visual iteration order; source-byte-to-entry mappings are complete over every byte assigned to a cluster, and no assigned byte belongs to two entries.

For an interior byte `0 < b < text_len`, let `p = bytes[b - 1]` and `n = bytes[b]`. Both must decode to valid `entries` indices and `p != n`. Since `b - 1` is covered by `p`, `p`'s half-open source range ends at or after `b`. If it ended after `b`, it would also cover `b`, contradicting the non-overlap map value `n`; hence it ends exactly at `b`. Similarly, `n` covers `b`; if its range began before `b`, it would overlap `p` at byte `b - 1`; hence it starts exactly at `b`. This is enough to prove the canonical cursor's byte index without constructing a `Cluster`: `Cursor::from_source_cluster` in `reactivity/vendor/parley/src/editing/cursor.rs:21-42` uses `cluster.text_range().start`, so both affinities retain `b` when `n` starts there. When the byte map has the same entry on both sides, a gap/sentinel, or an invalid index, the fast path must not run; same-entry bytes are snapped to an earlier cluster start by ordinary Cursor construction.

Require `p` and `n` to have the same `ClusterPath::line_index()` and `run_index()`, then resolve only that run for its direction (`ClusterPath::line/run` in `reactivity/vendor/parley/src/layout/cluster.rs:496-543`; `Run::is_rtl` in `reactivity/vendor/parley/src/layout/run.rs:156-159`). The exact visual-adjacency predicate is `p + 1 == n` for LTR and `n + 1 == p` for RTL, using checked integer addition. The entry vector is emitted in line/run/visual-cluster order, so this proves that no emitted cluster intervenes. Same-run entries cannot have an InlineBox inserted between their visual clusters. Empty-source-range entries still consume entry indices, so they break adjacency rather than being silently skipped.

The shared x coordinate follows directly from the constructor's stored f32 recurrence. For LTR, `n.offset` is the result of the same `p.offset += p.advance()` operation that the upstream cursor would perform. For RTL, visual order is reversed and `p.offset` is the result of the same `n.offset += n.advance()` operation the downstream cursor would perform. Selecting the cached resulting offset preserves the exact f32 bits, including signed zero, without assuming advances are positive or nonzero. The line path is shared, so both geometries use identical line metrics.

This matches cursor policy in `reactivity/vendor/parley/src/editing/cursor.rs:293-318,406-423`. Upstream geometry ordinarily uses the logical previous cluster and `!is_rtl` to choose its trailing edge; downstream uses the next cluster and `is_rtl` to choose its leading edge. For LTR, both reduce to the cached next offset; for RTL, both reduce to the cached previous offset. The existing `geometry_with` hard-break branch is also compatible without a hard-break exclusion: if `p` is a hard break, upstream falls through to the same downstream cluster used by downstream affinity; if `n` is a hard break, the ordinary LTR/RTL recurrence gives the shared edge. A line/run mismatch is a necessary fallback because soft wrapping or bidi/run transitions can give two geometries or different metrics.

A zero-origin helper extracted from `cursor_rect` can construct the single rectangle from the resolved `Line`, `x`, and width. Preserve the current operation order: `x as f64`, `f32::min`/`max` of the two metrics before `as f64`, and `(x + width) as f64`. Do not use y-position hit testing to recover a line; zero-height line layouts make that ambiguous. For the first slice, factor the helper privately into the existing cursor module (`pub(super)` visibility only), use it only in the proved branch, and keep the current pair fallback intact.

## Adversarial cases and fallbacks

- **Byte within one Parley Cluster / non-caret boundary:** both bytes map to one entry; the ordinary cursor snaps to `text_range.start`. Reject the fast branch and preserve the existing `None` result.
- **UTF-8 continuation byte:** all bytes of an assigned cluster range map together, so the entry does not change inside its text. If a byte has no mapping, reject. This cannot turn a scalar/grapheme interior into an accepted caret.
- **Gap, invalid source byte, or malformed overlap:** one side is sentinel/out of range, or constructor returned `None` on overlap. Keep fallback behavior; never assume `u32::MAX` names an entry.
- **Source-adjacent but visually non-adjacent/bidi:** same source indices are insufficient. Require exact global entry adjacency in the correct direction and same line/run; otherwise fallback.
- **Soft wrap and hard-line transition:** line indices differ when geometry belongs to different lines. Keep both affinity results on fallback. A hard-break exclusion is unnecessary only for the same-line/run cases, as shown by `geometry_with`'s policy.
- **Empty text and synthetic empty-layout cluster:** byte zero/EOF is excluded from the interior branch. `text_len == 0` construction deliberately leaves the byte map empty. Use the existing endpoint fallback and `last_line_cursor_rect` semantics.
- **Zero/negative advances, aligned runs, inline boxes before a run:** no sign or monotonicity assumption enters the proof. Within-run recurrence uses the actual emitted `Entry.offset` values, while line/run checks prevent sharing across inline-box/run offsets.
- **Zero line height and same-y lines:** the direct path resolves `ClusterPath.line`; it must not infer line ownership through y. This preserves exact per-line metrics even when y cannot identify a line.
- **NaN/infinite metrics or widths:** the path reads the same line metrics and uses the same f32-to-f64 rectangle construction. The cached edge is produced by the same f32 addition as the ordinary neighbor edge. Still compare all output components with `to_bits` and include at least signed-zero/subnormal/overflow cases in a test-only synthetic recurrence; do not add a finite-only fallback that changes acceptance unless needed to guarantee payload-bit behavior.

The existing `reactivity/crates/canvas/src/text/cursor_pair_tests.rs` at this pin is a meaningful independent oracle: it compares every byte offset against two direct `Cursor::from_byte_index(...).geometry(...)` results and compares all four `f64::to_bits` components. Fixtures include empty and trailing-break text, ligatures, combining marks, ZWJ, mixed RTL/LTR, explicit bidi isolates, U+2028, CRLF, wraps, zero line height, negative and signed-zero spacing, style boundaries, and four alignments. It exercises `usize::MAX` and widths `-0`, `1`, `-1`, and `1e20`. It does not prove that the new path is taken, does not explicitly construct a layout with a negative cluster advance or NaN/Inf offset, and does not expose whether every hard-break case passed the branch. Keep a branch census or test-only selected-path assertion separate from this oracle, and add recurrence-focused synthetic extremes rather than claiming those cases from ordinary font fixtures.

## Minimal implementation and audit gate

A compact safe formulation is:

1. Enter only for `0 < byte < text_len`.
2. Read `prev_i` from `bytes[byte - 1]`, `next_i` from `bytes[byte]`; resolve both with `entries.get` and require different indices.
3. Require equal line and run path keys. Resolve one `Line` and its indexed `Run`, read `is_rtl`, then check checked directional adjacency.
4. Select `entries[next_i].offset` for LTR or `entries[prev_i].offset` for RTL; return `[line_cursor_rect(line, x, width); 2]`.
5. On every other case, execute the current implementation unchanged.

That predicate removes the present `Cluster::text_range`, `Cluster::is_rtl`, and `Cluster::is_hard_line_break` work; direction is read once from the common run. It also removes the downstream Cursor and both geometry callbacks from the fast branch. A second borrowed-`Cluster` refactor is still a reasonable small fallback-only follow-up if assembly shows the rare path's 136-byte copies dominate, but it is not needed to validate the stronger branch.

No assembly or performance conclusion is claimed for this unimplemented formulation. After root implements it, compare linked release assembly for one Entry lookup, one line/run resolution, adjacency and bounds branches, one rectangle construction, and absence of the `path.cluster`/geometry callback calls on the fast route. Record stack-frame, copied bytes, `.text` and `.rodata` deltas, then use a real-font branch census and the existing direct bit oracle. Keep timing attribution separate from the independent segment-count prepass and from borrowed-fallback changes.
