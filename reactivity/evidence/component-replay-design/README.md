# Local description: existing authority and one additive contract

**Design comparison only. No implementation, new timing campaign or adoption.** Existing mapped properties can replay closed property outputs. None of the inspected existing mechanisms authorizes replaying an arbitrary structural component while omitting its caller. The proposed addition is one opt-in component region with a closed caller recipe and an explicit parent independence contract. Legacy `View` and `direct_component` retain their semantics and full-root fallback.

Source baseline: `773cd5d4543a130f071a830782b01bbae746c2d6`. [DESIGN.md](DESIGN.md) gives the concrete API sketch, admission law, state transition, application changes and unresolved implementation costs. The sketch is not implemented or compile-checked. [SOURCES.md](SOURCES.md) identifies the inspected production boundaries. The frozen source files and manifest support this source audit, not execution evidence.

The prior [contract witnesses](../component-description-contract/README.md) remain decisive: omitting an equal-valued caller width setter caused 1,152 wrong pixel bytes; omitting a later external-input decoration caused 1,536. Both preserved the component root identity and moved the following sibling incorrectly. A repeated component produced two child descriptions for one source edit. These were full-root versus counterfactual public models, not an implemented local engine.

| Mechanism | Existing replay authority | Same structural child edit | Decision |
| --- | --- | --- | --- |

| Questions + `Reader::project` | Declared/versioned task inputs and stale-result authority; projection itself consumed in ordinary description | No retained visual callback/caller independence contract | Reuse version concepts, preserve current task and projection semantics |
| `ItemSource` | Pure coherent borrowed snapshot during a description, explicit item keys | No retained row recipe or caller authority across turns | Existing list boundary remains separate |
| Proposed local component | Explicit parent law + existing component route + one opaque occurrence + closed root-width recipe + exact predecessor | Re-describe child and replay caller width, then existing reconciliation rules/global layout/paint | Candidate design only; smallest meaningful structural origin, not a local rendering guarantee |

The deliberate application tradeoff is explicit opt-in registration and a different child insertion call. An external mutable read must become a declared owner input, or the application stays on the legacy full-root route. A falsely declared purity/independence contract cannot be detected generally; this proposal does **not** claim automatic fallback for invisible reads. Adding an arbitrary stored callback would not fix that problem.
