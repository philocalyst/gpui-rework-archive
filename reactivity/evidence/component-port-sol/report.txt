Reusable public API

The crate depends downward on ordinary gpui interfaces. Its modules provide
Button, controlled Checkbox, editable Input, Label, textual Badge, Field,
Theme, shared sizes/layout helpers, and concrete FnOnce Recipe composition.
No production Rc/Cell/RefCell, property TypeId registry or macros were added.
The unchanged closed14 typed property catalog remains the deliberate runtime
inspector boundary; arbitrary component/schema/theme reflection is not claimed.

Example ordinary public syntax:
  Button::new("Finish invitation", &theme)
      .on_click(default_finish).on_click(app_finish)
      .style(|element| element.w(180))
      .build()
  Checkbox::new("Hang the lanterns", checked, &theme)
      .toggle(Self::LANTERNS).on_change(Self::app_lanterns)
      .parts(|parts| parts.indicator(|element| element.rounded(4)))
      .build()
  Input::new(&name_signal, "Guest name", &theme)
      .parts(|parts| parts.frame(|element| element.w(320)))
      .build()
These are illustrative method combinations; the compiled exact application and
ordinary external tests are in crates/component/examples and tests/contracts.rs.
The last on_click/on_change owns one activation route. Recipes refine actual
Els immediately, retain no callbacks, and accept typed named compound parts.
Theme snapshots belong to the app. Halloween uses semantic Oklch palette tokens.

Core semantic contracts

A checkbox remains one real controlled semantic CheckBox, now with named-part
children. Disabled is packed Content bit22 (Content::BITS23); it inherits across
named descendants and revokes logical activation, focus, text editing and old
presentation authority immediately. Physical handler-slot membership remains
separate so callback retirement/re-enable are correct. Part.disabled reflects
acknowledged state. Serialized semantics and native AccessKit expose disabled.
The final no-op reconcile compares semantic route eligibility and produces no
spurious changed-node count for disabled descriptions retaining a callback.

The opt-in focus_indicator draws an inset underline with existing transformed,
clipped rectangle geometry. Focus transitions damage old/new indicators and
obey preparation/ACK. Rounded outlines are future shared graphics work.
ControlAppearance uses the existing56B ElementExtra envelope: a stock rounded
Button with focus is one56B allocation. Optional annotations share that record;
there is no extra per-ControlAppearance box or new per-node header.

Remaining scope is explicit: no overlays/select/menu/dock/table/tree, switch,
radio or slider facades; no fake controls. Badge is a textual status subset,
not the reference count/dot/icon overlay. Input lacks the reference full rich
editor/validation/clear/masking API. Theme is a borrowed app snapshot, without
an extra theme cascade. The natural-size fixture has no fill-parent support:
resize can expose the window clear and the headless fixture has a narrow edge.
A separate typed relative Length slice is planned to address that shared core
layout limitation rather than patching only this app. This seal does not
include that slice and must be reviewed/integrated independently.
