BoolInput accepts bool, &bool, &Signal<bool>, and concrete typed bool mappings.
By-value bool remains an honest Rust snapshot. If a view branches or computes
other descriptions from that snapshot it must retain Sources::field and its
containing component dependency. Direct intrinsic operands require a registered
source even when their initial value is false; an unregistered intrinsic returns
UnregisteredControl. Existing style-only unregistered snapshot behavior is not
silently redefined. No public bind scope or allocated group is required.

The real Party app now binds both Preparation checkboxes directly. Its parent
still declares field(TITLE).component(PREPARATION), because ready(), help text
and finish policy use ordinary Rust snapshot branches. The actual Preparation
test proves a direct checkbox write needs zero child owner reruns/descriptions;
the parent test proves the mixed ready/disabled branches still refresh.
The measured child schema saves one allocation/32 retained bytes: direct 3/144
versus conservative 4/176. This does not remove every parent dependency.

Checkbox::on_change now reports the next value from the current logical checked
state through the same activation path used by keyboard and pointer. It does not
capture !initial_snapshot. A later on_change/on_click replaces the default route;
custom controlled callbacks report intent once and only the owner changes state.
Contained routes retain their lexical component projection. Removed identities
and old targets remain retired. Explicit named parts remain static Rust types.

Recipe composition and lowering

Mapped keeps concrete &Signal<T> and F until the element consumes it. A zero-
capture mapped operand is 8 B. BoolInput::select(false_color,true_color) returns a
concrete Copy SelectedColors<T,F>, 40 B for a zero-capture predicate. It owns token
values and retains no theme borrow. Foreground/background share the same closed
IntoColor boundary. Existing explicit PropInput<T> stays Copy and 48 B; explicit
ColorInput erasure owns its new descriptor. Wrong property types and forged
selectors remain compile failures; the style catalog still has 14 properties.
Checked/disabled are semantic sinks, not a claim of arbitrary component schema.

The one existing source/binding/fanout accumulator now admits private Sink values
for checked and disabled. Destination remains 4 B; no per-control registry, TypeId
table, additional retained bool vector or parallel palette bank was introduced.
The two selected endpoints are interned in the existing canonical color bank.
The retained recipe captures two color codes (8B) plus the predicate inside the
existing 16 B capture bound. A 20 B composed capture is rejected at ordinary mount;
there is no heap callable fallback. Exceptional oversized diagnostic payloads
alone can allocate their original full-width error. Literal/default overwrites
release obsolete bindings, including previously rejected capture descriptors.

Each mapped destination evaluates once at initial admission and once at source
publication. The admitted initial value travels through MapDraft to avoid a
second predicate poll during lowering. Arbitrary separate sinks do not share
predicate evaluation: no cross-sink CSE/cohort is promised. Closures are ordinary
pure Copy+Send+Sync+'static mappings. All scalar/map outputs are admitted before
the first sink mutation, preserving the shared failure barrier.

Checked updates preserve text/flags and change the existing checkbox content
kind. Effective disabled inheritance is recomputed only for disabled changes;
own-disabled survives an ancestor's disable/enable cycle. Content uses 24 bits,
including own-disabled bit 23 and effective-disabled bit 22, within the existing
u32; Main's 24 B Node is unchanged. This does not depend on the unadopted Node16
prototype. Installed physical route membership remains separate from semantic
eligibility. Disabling prunes focus before ordinary reconciliation/preparation,
rejects logical input/actions immediately, and leaves old acknowledged Part
semantics honest until the next ACK. No IME successor is present in this base;
that independent lane is not falsely claimed tested here.
