Avoid sibling scratch allocation for an empty or one-node old tree

Represent empty, single-root and indexed sibling runs explicitly. A one-node
admitted old tree has exactly one virtual-root child and no child run of its
own, so a promoted immutable [0] slice answers that query without constructing
prefix and child arrays. Larger trees retain the same one-buffer algorithm.
The enum still occupies 24 bytes on the measured Rust 1.97.1 x86-64 target.
No retained Runtime field, public API, dependency or unsafe code is introduced.

The existing exact-map oracle covers all shapes through 100,000 rows. Its
allocator assertion now requires zero requests for both empty and one-node
inputs. Those two private tests, the ordinary public owner allocation control
and strict all-target GPUI Clippy pass. The optimized public owner reproduces
27 requests/2,772 requested bytes across three tiny updates versus the indexed
control's 30/2,820, with unchanged 832-byte peak and zero retained delta. Every
larger owner row is unchanged. The frozen release fixture and allocation oracle
prove this is the new implementation rather than a reused Cargo artifact.

This is an isolated successor to the integrated CSR source. Paired timing and
linked code costs remain to be measured before main adoption; no native frame,
startup or RSS improvement is inferred from eliminating one temporary buffer.
