# Component path authority

This path is a declaration relative to the Win explicitly selected by the caller. It is not a durable row/component-instance handle. Scope identity comes from the already mounted ComponentEntry tree, independently of any Signal revision or allocation address.

1. Read/set/action admission finds the registered component by its local declaration ID and concrete child type. Wrong/missing components fail through existing BindError paths. The declared read projector must return the same current child as the registered read projector. Recursion resolves the child declaration against that entry's existing Sources and qualifies its FieldId with the mounted scope.
2. The leaf reuses Source::borrow_registered, including its registered Signal/type/projection checks. No read-only model address or resolved identifier is cached in the path. `Win::read` borrows the current logical Signal value under the Win lifetime; closing prevents further reads.
3. Before invoking a mutable leaf callback, every component's existing project_mut checks read/write agreement, and Source::modify checks leaf read/write agreement. A mismatched writer cannot expose the leaf value to the callback. A route first performs ordinary Target/source admission and then invokes the same path under existing operation/fault rules. The ordinary route invoke ABI is unchanged.
4. Set resolves the qualified field before transferring the payload. Rejected admission returns the payload; accepted mutation retains existing committed-error semantics. A failed new description/layout does not publish through old P. The previous complete candidate remains independently acknowledgeable, and subsequent admitted edits can repair logical state.
5. Question mount resolves each declared input against the actual mounted model/schema before starting its worker. Fabricated same-ID declarations with a different component or leaf projector are rejected at mount, before filtering can be used. `contains` is schema-only scope qualification, never mutable access authority. It follows existing stable-projector/direct-source contracts: projectors select the same stable field until remount and cannot depend on external mutable selection state. It does not prove arbitrary Rust projector purity.
6. A projected Question stores (qualified FieldId, Revision). Identical local IDs in repeated child schemas are distinct. Reflection reports the same qualified source used for filtering. Borrowing a declaration delegates resolve/filter/version/reflection/Reader/pair behavior exactly; it does not erase earlier-Reader dependencies or grow the underlying version pack. Worker input is frozen owned Send data; model/source borrows do not cross worker boundaries.
7. Worker cancellation, completion credit, ticket/namespace admission, closed owner and old-P text/Target rules remain the existing ones. A reference to a static declaration grants no owner lifetime. It can intentionally describe the corresponding current slot in two different Wins because each operation explicitly chooses and validates its own Win.

This slice does not establish arbitrary64-bit row-key authority, removed/reused-key admission, stable dynamic Source allocation identity, automatic parent-view dependency inference or a new component ownership tree. Those require a separate explicit model/description boundary. Existing Sources allocations and Question-status coarse invalidation are charged, not hidden by projected access.
