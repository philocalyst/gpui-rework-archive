# Later consumer-build artifact boundary — not implemented

Current a871 still requires the optional host Naga SPIR-V generation/reparse
features, SHA2 and external spirv-val. Its measured complete host closure is
49,178,077 logical bytes larger than default; this is not a compile-time result.
The published generator/proof source and generated bytes remain charged even if
later moved into a developer/CI-only tool.

A bounded follow-up could check in the five unique validated binaries/aligned
word arrays, exact expected typed-generated WGSL, generated interface/layout and
profile revision manifest. An ordinary optional consumer build would generate
its WGSL as today, compare its exact bytes to the expected source, verify artifact
integrity/revision and consume those fixed bytes. A source/profile/interface or
artifact mismatch must fail the build with an explicit regeneration instruction.
It must never accept stale words or silently retry after runtime creation errors.
The runtime sealed exact-Device profile and canonical fresh-BGL certificate stay.

The manifest must bind every profile/stage artifact hash, entry point, ABI/layout,
Naga version/features/options, generator revision, validator version/target and
expected WGSL identity. WGSL equality alone does not detect changed artifact
bytes. A small retained host digest dependency may still be needed for integrity;
removing it as well requires an equally explicit byte/provenance check, not an
assumption that checked-in files are valid. The existing unsafe passthrough proof
would cite the reproducibly regenerated/validated bundle and fail-closed build
admission. No runtime immutable hash scan or new cache is needed.

The full generator, reflection/interface/guard proofs, strict SPIR-V reparse and
external validation would become an explicit pinned developer/CI tool. CI must
regenerate into a fresh directory, compare every output byte, exercise all four
profiles and rejection fixtures, and reject manual/stale artifact/manifest edits.
Review must cover supply/provenance, tool/version availability, licensing and
cross-platform reproduction. Moving source is not a line-count reduction; report
all retained tool code, checked-in data and development dependencies separately.

Default builds already use host Naga WGSL validation/output through wgsl-rs. This
proposal could remove the optional SPIR-V frontend/output delta and ordinary
external spirv-val requirement, not all host Naga or driver compilation. It could
also avoid requiring a Vulkan validator just to cross-compile the Metal/DX12
fallback. Measure actual clean/warm consumer build time and host bytes on matched
configurations before claiming a compile-time improvement. No proposal is mixed
into the current a871 source, runtime results or native-memory measurements.
