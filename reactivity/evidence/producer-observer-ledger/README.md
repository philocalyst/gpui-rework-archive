Two different kinds of global work coexist: library semantics/implementation reconstruct full descriptions, and the test executable maintains six diagnostic cold stores plus semantic-emission snapshots. ## Compiled configuration, not just source labels

Recorded Cargo artifacts show GPUI itself was a test target with `layout-preservation-lab,native-core,x11-minimal`, while canvas and GPU were non-test libraries with `emission-trace` and `packet-trace` enabled through GPUI dev-dependencies. Thus `profile.test=false` alone does not mean an uninstrumented dependency. The experimental layout State and core mutation counters were also present in every selector, including Automatic.

A normal library consumer does not get GPUI's cfg(test) fields/modules or dev-dependencies merely by depending on GPUI. Normal `x11` also includes accessibility and the default feature enables SIMD; the measured no-default `x11-minimal` configuration intentionally omits those. The production ledger below identifies library work, not the exact cost of all supported shipping profiles. Runtime `Counters`, core `LayoutStats`, GPU `Stats`, and declared accessibility/inspection functionality are real library machinery, not automatically disposable test observers.

## Why an ordinary structural field currently requires description

`Signal::deref` returns `&value` without read tracking. `Sources::field` explicitly registers owner dependency for branches, formatting and structural reads. `direct` is a declared absence of those snapshot dependencies and patches only mounted operands. Switching a structural field to `direct` would violate that contract; it is not an optimization.

`Sources::direct_component` declares absence of parent snapshot reads of child state, but `ComponentEntry::invalidates_owner` currently returns `parent_dependency || child.invalidates_owner(...)`. A child `field` therefore still escalates to the whole root description even through a direct_component. This is an actual granularity boundary, separate from the layout-handle seam. Ordinary `component` deliberately retains conservative parent dependencies.

`Component::view` executes the child View, maps handlers through its typed projection, then attaches a boundary check. Admission collapses that boundary to its innermost scope; the retained Node keeps scope, not an independently replayable description closure or caller-modification recipe. Caller code may then decorate/extend the returned El. Direct component registration alone does not prove that re-running only child View would reproduce that decorated root. Multiple appearances, nested boundaries, remints and current parent ownership also need qualification. The existing scoped source identities help locate ownership; they are not already a subtree journal.

## Outside the cost clock

Counter reset occurs before clock. Cost snapshots, O(slots) layout/cache storage scans and copying scalar samples occur after endpoint; same placement across selectors can still condition next-frame caches. Preallocated sample storage is benchmark state. Post-timing allocation_counter wraps two Source updates only; subsequent rendering, fresh-layout/CPU/GPU oracles, readback and file/JSON serialization are outside that wrapper. Earlier correctness captures copy complete layout/style/child arrays and build comparison maps outside Source; their allocation records are retained separately. They never feed candidate decisions.

Runtime `structural_observation()` formats/report-scans the observers when explicitly called; those report-time maps and additional verification reads are distinct from the observers' begin/push/finish work already inside Source. In the closed cost loop, the full structural report getter is not called every frame; the scalar cost snapshot is. Do not charge all report formatting to Source or overlook finish-time work because reporting is outside.

## Gap map and one next hypothesis

| Target connection | Existing machinery | Genuinely missing |
| --- | --- | --- |
| source→semantic subtree | Scoped FieldId/component schema, semantic Node identity/parent/preorder | Qualified local description origin and replay authority, caller decoration provenance, affected occurrence set |
| subtree→ordered storage update | Contiguous current nodes, keyed remint rules, compact identity runs | Structural delta/extents surviving edits without global reconstruction; fragmentation/relocation costs |
| update→dependency/damage closure | Core layout invalidation, clips/transforms, old/new presentation/damage, eligible slot certificates | A structural/dependency journal that composes these facts; subtree range is not closure |
| storage→GPU consumption | Original ordered tile traversal, raw packets, staged writes, exact predecessor authority | Stable semantic emission/resource mapping across structural versions, compressed representation and synchronized publication |
| cache/compression benefit | Existing caches and prior sealed representation counterexamples | A new measured production baseline and complete cost proof; no adopted codec or coherent shared memory |

The evidence selects **qualified component-local description origin** as the next hypothesis, not another layout or paint fast path. Investigate whether an already declared direct_component child field can emit an old/new semantic subtree transition from existing scope/root identity while preserving current public semantics. Start with a single unadorned occurrence and explicitly reject/fall back for unqualified caller decorations, repeated/nested appearances, parent-dependent schemas or lost authority. Trace decorations that happen after Component::view as the decisive counterexample; do not infer an immutable child recipe from the surviving scope number. The whole root description remains the oracle/fallback.

A first executable connection would preserve existing identity/remint rules, emit actual local reconciliation events and keep layout/paint/resource dependency processing global until its closure is represented. Contiguous splicing/rank repair may still be O(N) and must be charged. This would advance source→semantic-subtree journaling, a missing link in the user's connected storage/damage/GPU model. It would not establish GPU publication, compression, O(1) total updates or permission to ignore moved siblings. **No implementation or new performance campaign is included in this ledger.**

Before any later timing, define a fresh non-test or explicitly reduced-observer source/profile and retain correctness observations outside the measured interval where possible. Do not strip production counters/accessibility/resource checks indiscriminately, quietly change renderer authority, or subtract117,977B/observer work from the sealed campaigns. Their verdicts stay immutable.
