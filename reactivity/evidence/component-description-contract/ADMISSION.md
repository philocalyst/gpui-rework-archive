# Minimal admission obligations for component-local description

No local replay engine is implemented here. Existing `direct_component`, current El appearance, surviving component scope, unchanged current style, and a typed source path are individually and jointly insufficient to authorize skipping the caller for arbitrary future updates.

The required equality is about the **next output**, not just old bytes: for every admitted child transition and relevant environment state, a locally re-executed child composed with the admitted caller contribution must produce the same ordered description and resource/handler ownership as full root View at that transition. Current observations establish only one execution. The public View contract exposes borrowed operands and no mutable runtime; it does not provide general tracking of arbitrary Rust reads or a replayable parent program.

## Falsified certificates

1. **Equal old style ⇒ no caller contribution.** Parent calls CHILD.view(self).w(24); child initially returns width24. On a child field update it returns width40. Replaying only child loses the explicit24 override. The initial values are equal, but write intent is different. Root identity/scope survival does not recover that intent; following sibling placement can change too.
2. **Observed unadorned + direct_component ⇒ future parent uninvolved.** Parent reads an external AtomicBool, initially false, and then conditionally adds width16 after CHILD.view(self). Changing that external value before an ordinary child field update makes full root description apply the decoration. Parent never directly reads child state, satisfying the stated direct_component parent-read restriction. A one-time unadorned observation does not exclude that later contribution. The atomic is a test environment input, not a proposed production ownership mechanism.
3. **One qualified source scope ⇒ one semantic subtree occurrence.** A parent may call the same registered CHILD.view(self) twice. One child field edit must update both distinct visual occurrences. A source path identifies model ownership, not unique visual placement.

The first two compare actual full-root updates against counterfactual public models that omit the caller contribution. They are negative models for insufficient authority, not measurements of an implemented subtree updater. Exact public snapshots/pixels and view-call counts identify the behavioral difference. No cross-backend or timing claim follows.

## Sufficient representation and proof boundaries

A usable region certificate would need all of the following, with each retained byte and construction/update visit charged:

- **Declared replay semantics.** A stored recipe for the component and its caller composition, or a new explicit opt-in contract that excludes undeclared caller dependence. A stored arbitrary Fn pointer alone is not sufficient: it neither lists its reads nor proves their stability. Sealed recipe primitives can make dependencies closed; an opaque callback needs an explicit semantic contract, analogous to existing projector/direct-port contracts. None is inferred from this fixture.
- **Caller provenance, not value diffs.** Exact property-write intent and order, including setters equal to existing values; appended/reordered children; handlers, semantic metadata, style/resource bindings, transforms/clips and root replacement. If these remain arbitrary caller Rust, the fallback is full caller/root execution. Merely caching the last decorated El loses future behavior and borrowed ownership.
- **Complete dependency input authority.** Every input affecting the recipe or whether/where it is instantiated must be a declared/versioned operand or constant under the opt-in contract. An untracked environmental read must be brought into that contract or force full root description; it cannot be presumed unchanged because no parent Source was set. Parent-dependent `Sources::component` remains conservative.
- **Occurrence/context authority.** Existing component/source namespace plus exact semantic root identity and scene/description epoch, admitted parent/order context, and the complete affected occurrence set. Repeated appearances and nested boundary chains are unsupported until represented. Current admission collapses boundary checks to the innermost scope, so that number alone cannot reconstruct outer wrappers. No new semantic identity registry is required to state this obligation.
- **Borrow/lease discipline.** Re-execute through existing validated typed projections during an exclusive live owner turn. Do not retain borrowed El/text/image/model references across that turn. Move/clone owned handlers/resource leases only under existing lifetime rules; a CPU region certificate is not a submitted GPU content version.
- **Transition and failure authority.** Bind a plan to the exact predecessor logical/completed state, recipe version, root/remint namespace and new source epoch. Losing logical authority, reminting/reparenting beyond the admitted context, a failed newer preparation or owner poison revokes local reuse. Existing full reconstruction/presentation rules remain the oracle; older coherent Canvas eligibility does not revive a stale logical region.
- **Dependency closure after local description.** Reconcile identities using existing parent/key/kind/component rules; preserve old/new support and affected ancestor/sibling layout, clipping, transforms and resources. Initially keep whole layout/paint processing. A contiguous structural span cannot substitute for these closures or authorize retaining old GPU output.

These are sufficient *obligations*, not a proven concrete implementation. The minimally useful first restricted representation would bind one explicitly declared replay recipe to one qualified component occurrence and its caller composition/dependencies, with exact predecessor authority. It would emit an actual old/new structural transition while using existing global layout/paint. A directory/extent/paged representation is a later choice; rank repair and contiguous splicing can still be O(N).

## API consequence

Current arbitrary View plus direct_component does not establish the required replay contract. A safe design needs an explicit stored declarative recipe and dependency model, an additional opt-in semantic contract/API, or a compiler-proven restricted description subset with conservative fallback. This is an actual API/contract decision; it must not be hidden as an automatic interpretation of existing direct_component. Existing applications may continue unchanged on full root description. No automatic subtree-local guarantee for them is promised.

Unadorned/single-occurrence fixtures would only be useful after such admission exists. Rejecting obvious decorations is not enough to admit the remaining arbitrary parent code: absence of a mutation in one execution does not prove absence later. The two pixel counterexamples target exactly that gap.

## Connection to the architectural goal

Existing scoped sources and semantic identities locate model/visual facts; contiguous Node storage and identity runs already exist. The missing connection is a valid source→structural transition with complete caller/dependency authority. That transition could later feed reusable ordered extents, old/new damage and version-consistent GPU packets. It does not itself implement compression, eliminate layout/paint work, provide shared CPU/GPU memory, or imply constant total work. BBTree-style cache scheduling cannot supply missing declaration dependencies; Solid/Ripple-style versioning can reject stale results only after the input/recipe boundary is sound.

Before a later cost decision, use a fresh representative non-test/reduced-observer configuration with correctness captures outside timing. The previous observer-heavy campaigns and NOT ADMITTED verdicts stay unchanged. This contract trace neither reopens them nor starts another performance campaign.
