# Existing layout authority and the smallest next experiment

This is a source/trace finding, not a retained-layout implementation or speed result. Address encodings remain NOT ADMITTED at9e349796; this branch starts from original raw41a986b3. No GPU parity rerun or replacement of the inherited FAILED mixed gate.

The exact loss is between reconciliation and `present_walk`. Reconciliation successfully matches semantic identity using parent identity, kind, component scope, keyed-list semantics and unkeyed-run rules. It then compares the complete old/new ordered identity vectors; length or any rank difference sets `topology_changed`. `present_walk` tests `rebuild_layout || topology_changed || layout.is_poisoned()` and assigns a new `LayoutTree`, clears the rank→NodeId vector and reinserts every node. A surviving semantic node therefore loses its arena-qualified layout capability and cache solely because structural shape/rank changed elsewhere. This is a broad conservative invalidation boundary, not missing semantic identity.

The retained path already exists when topology is unchanged. Reconciliation inserts changed text/image identities and layout-style changes into `layout_dirty`; font changes also clear shaped text. Before layout, viewports whose immediate parent flow changed are added because their effective row style depends on that flow. For each dirty identity GPUI resolves the existing handle, calls set_style and explicitly mark_dirty. That explicit mark matters even if Style equality makes set_style return false: the measurement callback reads external text/image/composition data. Reusing a function pointer or own style is not authority to reuse a prior answer.

Core LayoutTree already supplies generational, arena-qualified capabilities and retained caches:

| Existing operation | Invalidations / costs already present |
| --- | --- |
| insert | Allocates/reuses a slot, interns style, initializes layout/cache; invalidates affected out-of-flow ancestor contexts, increments parent child count and marks parent dirty. |
| remove | Traverses removed subtree, releases style/cache/measure/pending/viewport entries, retires core generations and marks surviving parent; out-of-flow ancestor references are invalidated first. |
| reparent | Validates cycles up the ancestor chain, moves to the end of the requested parent's children, invalidates old/new ancestor contexts, updates child counts/depths (subtree traversal if depth changes), clears moved-root viewport and marks old/new parent/root. |
| set_style | Compares full core Style, interns/releases on change, marks node and its parent because flex/grid parents read child style directly. |
| set_measure | Compares installed function pointer; changing it marks dirty, but identical pointer does not certify external data equality. |
| mark_dirty | Marks measured/container node, or parent for a cheap leaf. |
| compute | Validates capability/root/viewport, filters pending changes by root with ancestor walks; skips only when viewport unchanged and no selected pending edits. Builds the existing incremental scheduler and propagates dirty/cache dependencies. Viewport change clears root cache; changed query inputs still matter below. Panic poisons the adapter, with no layout rollback. |

Three separate facts must remain explicit: the node may keep its handle; some cached query answers may remain valid; computation may still be necessary because ancestors, constraints, ordered children or content changed. Same-style following-sibling movement and width-constrained text demonstrate why these facts cannot collapse into one reuse bit. Layout output is not presented-sheet authority: GPUI retains old coherent canvas/presentation state on failed preparation and forces rebuild on the next attempt. Any retention implementation must preserve that fallback.

There is a second concrete seam: the current measurement callback finds the semantic rank by binary_search over `layout_nodes`. Fresh arenas append in preorder, so that vector is sorted by complete capability. Preserving handles through reorder breaks that assumption. Reordering the semantic vector to preserve sort is forbidden because it changes painter/child order; sorting capabilities separately needs a charged reverse route. A candidate can build a measured-node-only sorted `(qualified NodeId, semantic rank)` directory from the same reconciliation/layout installation events, allocating nothing for a text/image-free tree. It is a reverse route for existing capabilities, not another semantic identity registry. Complete keys, current version, construction/comparison/scratch and invalidation costs must be measured; do not silently replace the binary search with a full scan per measurement.

Ordered child edits also need an explicit choice. Existing `reparent` only appends. Blindly reparenting every desired child restores final order but performs global link/invalidation work even for unchanged sibling lists. A prefix insertion can force many append moves. Before selecting handle preservation, compare a small ordered-before primitive using the existing linked topology and invalidation rules with the append-only fallback; charge cycle checks, depth/ancestor work and exact child-sequence maintenance. This is not permission to replace Cephal or invent a second owning tree. Unchanged own style does not bypass child-sequence or intrinsic dependency updates.

Smallest executable proposal after this trace: carry the already-authorized previous-index correspondence from actual reconciliation into a pending rank→existing-NodeId assignment; insert only genuinely new nodes, retire removed nodes and apply exact ordered-child/style/measure invalidation using the existing core LayoutTree. Preserve current semantic remint rules and full reconstruction on poison/failed/unsupported authority. Build the measured reverse route only if needed. Keep full producer/render as oracle and the zero-insertion resource case as a control. All description/reconciliation may still be O(N), and comparisons/metadata must stay charged: this could reduce reconstruction and preserve caches, not yet deliver local structural description, closed damage or O(1) GPU work.

The trace's old/new captures, full Styles, child vectors, identity comparison maps and JSON are diagnostics outside Source. They are not proposed retained metadata or an optimized mirror-diff. Allocation counters separately record capture, comparison and report formatting. Core storage reports known topology/lane/cache bytes; style-table/allocator metadata is not complete RSS. Source allocation and original producer visits stay visible. The software renderer timing was completion-wait dominated, so no performance conclusion follows a reduction in insertion counts alone.
