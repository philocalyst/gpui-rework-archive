== 1M-NODE SCANS — record width is the frame bill
========================================================================
   4 B/node:    126 µs/scan  0.126 ns/node   31.7 GB/s
   8 B/node:    129 µs/scan  0.129 ns/node   61.9 GB/s
  16 B/node:    537 µs/scan  0.537 ns/node   29.8 GB/s
  32 B/node:   1448 µs/scan  1.448 ns/node   22.1 GB/s
  · Same loop, same visited field — only record width changes. Past LLC the scan is a
  · bandwidth product: bytes/node × N. Inline 'harmless' state multiplies the frame bill.

== LANE SPLIT — a flags-only pass should read a flags-only lane
========================================================================
  8 B record scan reading flags : 129 µs   1 B flags lane: 127 µs  (1.0x)
  · Kind-segregated SoA already side-tables payload; this pushes further: per-PASS lanes.
  · (The 1B lane autovectorizes too — treat the ratio, not the ns, as the finding.)

== CHAINED: subtree_size + dirty-epoch lane -> skip clean subtrees (the big one)
========================================================================
  tree: N=1000000, max depth 28
  full 8 B scan baseline: 129 µs
     0.01% dirty (   100 leaves): mark   48371 ns  visit    24730 ns (    968 visited,    4429 skips)  vs full 129223 ns  =>    5.2x
     0.10% dirty (  1000 leaves): mark  232365 ns  visit   142744 ns (   6958 visited,   24309 skips)  vs full 129223 ns  =>    0.9x
     1.00% dirty ( 10000 leaves): mark 1366861 ns  visit   717127 ns (  46142 visited,  106645 skips)  vs full 129223 ns  =>    0.2x
    10.00% dirty (100000 leaves): mark 3852348 ns  visit  2487817 ns ( 247409 visited,  291452 skips)  vs full 129223 ns  =>    0.1x

  full scan WITH per-node work (1.0 ns/node): 1002 µs
     0.01% dirty: skip-visit WITH work    24340 ns   vs full-with-work  1002003 ns  =>    41.2x
     0.10% dirty: skip-visit WITH work   133853 ns   vs full-with-work  1002003 ns  =>     7.5x
     1.00% dirty: skip-visit WITH work   720516 ns   vs full-with-work  1002003 ns  =>     1.4x
    10.00% dirty: skip-visit WITH work  2541128 ns   vs full-with-work  1002003 ns  =>     0.4x
  · Even with work that pipelines to ~0.4 ns/node, the skip wins 20x+ at 0.01% dirty and
  · crosses over near ~1% dirty (the skip walk is branchy dependent loads at ~3.5 ns/step,
  · the full scan is streamed). LAW: the scheduler PICKS the traversal by dirty count —
  · dirty < ~1%N: skip-walk the closure; else: one streamed full pass. Both endpoints are
  · measured, so the crossover is a constant the runtime can hardcode per record width.
  · Publish marking is memory-latency bound (~1 µs per cold dirty path at 1M: random
  · 4 B epoch-lane + parent[] misses x depth); a 1-bit dirty lane (128 KB, L2-resident)
  · would mark cheaper but needs an O(N/64) word clear — epoch vs bit is a real trade.
  · For pure property patches (no traversal) round 1's SoA queues stay O(patches).
  ·
  · Publish already walks ancestors (O(depth) per dirty node, epoch-deduped: a second dirty
  · leaf under the same parent stops at the first stamped ancestor). Clearing is epoch+=1 —
  · no O(N) reset pass, the same trick as readset.rs' epoch-stamp dedup. CHAIN:
  ·   paint-order SoA (linear scan) + subtree_size (O(1) subtree skip)
  ·   + epoch dirty lane (no clears) + parent[] (publish marking) = O(dirty) frames.
