# BBTree follow-up: preserve facts across value edits

Read-only follow-up against upstream HEAD observed2026-10-28,
`1c72bd27994ed0a38694b029618e80115e22644f`, compared by complete tree diff with
the previous pin `1b0201087102f81189da0c4cd5054a91c8d97d62`. The previous
checkout remains at its original pin. No upstream benchmark was rerun and no
unsafe concurrent memory access is proposed for GPUI.

The important new evidence is more specific than replacing tree traversal with
async tasks. A value update used to discard BBTree's remembered rightmost leaf,
although it cannot move or free a node. `find_mut` now reads the root page through
the shared accessor while the caller still owns an exclusive map borrow. This
preserves the existing append certificate. Entry handles and operations capable
of structural mutation still invalidate it. The map gains no new field or queue.

Their reported insert+update time is about103→54ns on one Ryzen run; that is
upstream evidence, not a GPUI result. More persuasive for transfer is the
deterministic comparison-count test: ascending insertions separated by value
updates perform exactly as many insertion comparisons as ascending insertions
alone. It also checks hit/miss/separator cases and the next split. The structural
invariant checker verifies the remembered pointer is the actual last leaf.

The new extraction shortcut similarly preserves a valid path to the next entry
when removal leaves a sufficiently populated leaf, instead of repairing and
rediscovering it. Tests cover leaf end, separator, borrow/merge/root lowering,
early iterator drop and panic. The condition is a structural proof, not a size
heuristic selected from successful timing runs.

The new `first_copied` read gathers at most three entries, checks versions after
reads and falls back for long ties/changed leaves. A separator match must still
confirm the head copied from the leaf. This reinforces the distinction between
a routing hint and authority. GPUI already has exclusive ownership: introducing
BBTree's racing reads, latch protocol or unsafe representation is unnecessary.

For GPUI, the next question is which *already established facts* are forgotten
by unrelated edits. The existing local-publication work does this for exact text
destination, acknowledged geometry and old/new glyph support. Its large stream
signal survives two experiments, but both fail their complete fixed cost gates.
The source-epoch/image-token bug also demonstrates why preserving a cache without
the right invalidation domain is wrong. Source version, topology, material/glyph
identity, acknowledged image and async request generation are distinct facts.

Solid and Ripple add the complementary rule: preserve dependency identity and
advance only the ready affected closure. They do not authorize replaying arbitrary
Rust callbacks or treating a pending external task as a memory stall. Existing
progressive Reader behavior stays unchanged. Their earlier pinned compiler,
generation, ordered-link and staged-publication analyses remain in LOCALITY.md
and SCHEDULING.md; this follow-up does not relabel them as newly reproduced wins.

Before another optimization, measure the actual native component path with equal
compiler profiles. Protocol20919cb160f6fcc5ab85eca607b97d4173739409 compares the
corrected baseline, the failed sparse variant and pinned ZGX descriptively on
software Vulkan. All libraries keep their existing APIs. The sparse variant is a
diagnostic control, not an adopted winner. Automatic modes inject no wheel events;
manual smoothing/gesture parity, render quality and physical hardware remain open.
This avoids adding a new input API merely to obtain a diagnostic CPU observation.
