# Monotonic caret emission: bounded Parley/Canvas proposal

The main sources are:

- `reactivity/crates/canvas/src/text/planner.rs:436-508`: `append_carets` consumes `GraphemeClusterSegmenter::segment_str(content)` in increasing UTF-8 byte order. For more than eight yielded boundaries it builds a bulk index; for each boundary it either asks the index for both affinities or performs ordinary `Cursor::from_byte_index` plus `Cursor::geometry`, rejects cursors whose canonical index differs from the byte, converts the full rectangle to `f32`, checks all four components finite, and emits stops in source order.
- `reactivity/vendor/parley/src/editing/geometry.rs:17-76, 89-159`: `CursorGeometry` is a scoped random-query index over one immutably borrowed layout. It stores one `{ClusterPath, offset}` entry per scalar-capacity slot and one `u32` owner for every source byte. The comment prices requested payload as 16 bytes per source scalar plus four bytes per source byte. The common-edge branch is deliberately narrow: same line/run and direction-correct visual adjacency.
- `reactivity/vendor/parley/src/editing/cursor.rs:16-45, 301-325, 414-439`: canonical cursor construction replaces an in-cluster byte with `cluster.text_range().start`; byte zero is forced downstream; a missing cluster becomes the text endpoint. `geometry_with` attaches affinity to logical source neighbors and falls through a hard break. `line_cursor_rect` takes the actual line metrics and exact supplied `f32` x.
- `reactivity/vendor/parley/src/layout/line.rs:111-139` and `reactivity/vendor/parley/src/layout/line_break.rs:1811-1815, 1981-2019`: line items are exposed in stored order, and mixed bidi lines reorder those items visually. Therefore a line's `runs()` order cannot be treated as source order.
- `reactivity/vendor/parley/src/layout/run.rs:138-159, 199-206, 383-460` and `reactivity/vendor/parley/src/layout/cluster.rs:51-58, 158-190, 222-225`: a run's `advance` includes spacing/justification; logical and visual cluster iterators differ for RTL; cluster source ranges and advances are available without materializing a cluster map; and hard breaks are identifiable.
- `reactivity/vendor/parley/src/layout/layout.rs:176-189, 230-246`: layout lines are stored/iterated in line order, while random byte lookup binary-searches the line then scans its runs.

The vendored source is the primary evidence for this exact GPUI build. The upstream project is [Linebender Parley](https://github.com/linebender/parley); no behavior claim below depends on a newer upstream version.

## Strongest formulation

Keep `CursorGeometry::new` and its random `cursor`/`geometry` APIs unchanged for arbitrary lookup. Give Canvas's bulk-only lowering path a small Parley source-ordered visitor that accepts the existing sorted boundary iterator and emits one optional upstream/downstream pair per input byte. Do not add a retained field, font/layout cache, global cache, or stop-order sort.

The visitor can merge the sorted ICU byte stream with source-ordered Parley clusters. Lines are already traversed in layout order. For each line, make one visual item pass to reproduce the existing line origin recurrence exactly: start at `line.metrics().offset`; for an inline box add its width; for a run save its item index and current origin, then add `run.advance()`. Keep a reusable per-line `RunOrigin` scratch vector, sort that small vector by `run.text_range().start`, and visit text runs in logical source order. Sorting is required because the line item vector may have been bidi-reordered. Inline boxes still affect run origins even though they have no caret byte.

Within an LTR run, visit `run.clusters()` and advance `x += cluster.advance()` in that exact order. This is also the visual order used by `CursorGeometry::new`, so no prefix lookup or per-cluster path is needed. Within an RTL run, first visit `run.visual_clusters()` and save each current x into one reusable `Vec<f32>`, advancing with the same `f32` addition after each cluster; then visit logical clusters and read the saved offsets in reverse order. Never derive RTL positions by subtracting advances from a run total: that changes rounding and can change signed-zero bits.

Consume boundaries and clusters as a merge. At a boundary equal to a cluster start, use the one-rectangle fast path only when the preceding source cluster is contiguous, both clusters are in this same run/line, visual adjacency has the expected direction, and neither cluster is a hard break. Use the exact shared edge already used by the pinned `CursorGeometry::shared_edge`: LTR uses the current cluster's visual offset; RTL uses the preceding source cluster's visual offset; build the rectangle with `line_cursor_rect`. That reuses the existing source-affinity proof and exact recurrence rather than inventing a coordinate formula. At run/line edges, hard breaks, gaps, endpoints, and any ambiguous case, call the existing ordinary two-affinity cursor path unchanged. A byte strictly inside a Parley cluster can be skipped: `Cluster::from_byte_index` finds that containing cluster and `Cursor::from_source_cluster` canonicalizes to its start, so the current `cursor.index() != byte` admission rejects it. Keep the supplied ICU segmenter as the sole boundary source; this does not replace shaping, font fallback, or language/profile admission.

Because the visitor consumes each requested byte once in source order, it can append directly to the existing `Vec<Stop>` in the same order as today. It needs no byte bitmap, temporary stop vector, or final sort. Preserve the `CursorGeometry::new` size guard (`characters().len() > u32::MAX` or line count over `u32::MAX`) on this large-layout branch if identical failure admission is required: Canvas currently maps that `None` to `Error::InvalidFont`. Keep `append_carets`'s existing `InvalidGeometry` conversion and finite checks for every emitted affinity. Empty layouts, final empty lines, byte zero, and `text_len` must continue through ordinary cursor geometry, not a cluster-derived approximation.

The smallest API seam is one public associated callback method in the existing Parley editing module, taking `&Layout`, a caller-supplied iterator of byte offsets, width, and a callback of the form `FnMut(byte, Option<[BoundingBox; 2]>) -> Result<(), E>`. This lets Canvas propagate its existing `InvalidGeometry` result without a new result-owner type. To preserve the current `InvalidFont`-before-callback order, the method must finish any required range preflight before invoking the callback; that extra pass is the costed unresolved item below. The callback form adds no retained layout field. Document the monotonically nondecreasing input contract; a defensive implementation may switch to the ordinary direct path for all remaining values if it observes a decreasing byte. Keep the Canvas grapheme iterator and its existing `<= 8` direct branch untouched. Do not route random `CursorGeometry` queries through this visitor.

## Scratch and work cost

The current bulk index requests `16*C + 4*B` bytes for entry and byte-owner payload, where `C` is the shaped character count and `B` is UTF-8 source bytes, plus two local `Vec` headers and allocator slack. For 32,768 ASCII bytes this arithmetic is 655,360 payload bytes before allocator effects. It is transient, but it is still built for one bulk stop-emission pass.

The source-ordered visitor requests a reusable per-line `Vec<RunOrigin>` of `R_max * size_of::<RunOrigin>()` bytes and, only for RTL, a reusable `Vec<f32>` of `4*K_max` bytes where `R_max` is the maximum number of runs in one line and `K_max` is the maximum grapheme count in one RTL run. The two `Vec` headers are call-local; no part of this scratch survives the borrowed `Layout`. In a long one-run LTR line there is no RTL heap buffer. In a long RTL line the per-run offsets are the intentional lower-bound scratch needed to preserve exact visual-order `f32` additions while consuming source order. For 32,768 one-byte graphemes in one RTL run, the requested offset payload is 131,072 bytes plus one run record, rather than the current 655,360-byte index payload; these are formula-derived payload estimates, not allocator or RSS measurements. Measure `size_of::<RunOrigin>()`, actual Vec capacities, and peak allocations in the implementation before publishing a byte win.

The visitor still walks all line items to recover origins and all clusters to emit boundaries. LTR cluster order is one pass; RTL needs a visual offset pass plus a logical merge pass. If exact invalid-range error precedence needs a preflight, add another full source-cluster walk. It removes the per-byte owner fill and retained `ClusterPath` entry array, but does more work than the index on complicated fallback-heavy text: every run/line edge or hard-break boundary still uses ordinary cursor lookup, and a highly fragmented line still needs a run-origin sort. It can regress relative to the indexed path on many short bidi/font/style runs. No speedup follows from the representation alone.

There is one exact error-order adversary to settle before treating this as a drop-in: `CursorGeometry::new` validates every cluster source range and overlap while constructing the index, before Canvas queries the first caret; a failure is returned as `InvalidFont` before any finite-geometry check. A streaming visitor that discovers a malformed/overlapping range late could already have emitted stops or returned `InvalidGeometry` for an earlier boundary. Keep the existing `characters().len()`/line-count `u32` guard before emitting, and either prove/test that every Parley-produced layout has in-bounds, non-overlapping cluster byte ranges, or add a source-ordered range preflight and measure its extra full cluster pass. Do not silently weaken the map's range validation. Canvas drops all partially built `Details` when `shape_inner` returns an error, but the new public callback itself would still need a documented partial-callback contract unless it preflights.

The tempting bitmap alternative (`ceil((B+1)/64)` words) is much smaller than the byte-owner array, but scanning visual clusters would discover fast stops out of source order. Sorting the final stops adds a whole output pass; staging a per-boundary result adds another payload vector. The source-order merge is the better formulation because it writes the existing output directly and keeps the only necessary offset scratch scoped to one RTL run.

## Correctness gates for a first implementation

Run the existing direct-cursor oracle against the visitor for every admitted ICU boundary and both affinities, comparing the complete `BoundingBox` bits and then the emitted stop byte/x/affinity sequence. Also compare the current indexed implementation as a second reference; do not rely only on `Rect` `PartialEq`, which considers signed zero equal. Include at least: empty and trailing-empty lines, hard newlines and U+2028, soft wraps and two-affinity aliases, same-run LTR and RTL, mixed bidi run reorder, font/style run boundaries, leading/trailing whitespace, ligature continuations, combining/ZWJ/emoji clusters, hard-break fallback, zero line height, zero/negative advances, signed-zero offsets, and non-finite geometry rejection. Check exact source-byte admission both at cluster starts and in-cluster ICU boundaries, and retain the >u32 `InvalidFont` guard on the bulk branch.

The first bounded implementation should change only the bulk Parley/Canvas seam and its differential tests. Keep the current random index as the control and fallback oracle. Gate a later production adoption on matched allocator captures for tiny labels, long LTR, long RTL, mixed bidi, wrapped text, and fallback-heavy text, plus release assembly and the existing full behavior matrix. No performance claim is made here.
