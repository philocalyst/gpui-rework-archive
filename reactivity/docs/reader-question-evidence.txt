The first declared u64/Infallible question allocates one owner scope,
Remote's bounded channel/notification/staging and one shared controller.
The complete plan is inline static storage; 880B is allocator request bytes,
not RSS or allocator usable-size. Questions::new itself makes zero allocations.
Ordinary Win remains its existing one-pointer 8B owner; Runtime/Node/Presented
gain no fields. El remains176B, its existing cold ElementExtra remains56B.
Per projection: projector32B + ElementExtra56B = two allocations/88B on every
description, even when the render closure is a zero-sized method/function item.
Optional annotation/component mapping closures can add their existing cold
allocations. Each projection also adds a fixed status/content region to the
real description; this is not free graph plumbing.

Each logical request clones a RequestStamp owner-scope lease. Each physical
dispatch separately clones the controller lease. Both are reference-count
operations; no per-job allocation is made for either lease. The channel and
staging reuse reserved storage. Generic frozen input/result allocation is an
application cost, not hidden by these figures. Native EventLoopProxy/OS wake
allocation is unmeasured; no zero-native-allocation claim is made.
