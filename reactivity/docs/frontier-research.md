# Frontier research: compact retained trees and sublinear presentation work

Research date: 2026-10-20. This is a design investigation, not an implementation or benchmark result. “Verified” means the cited primary text/source states the mechanism; “derived” means the equations or byte counts below follow from those mechanisms; “hypothesis” means an experiment is still needed. Links to source repositories are pinned where a revision is available. Local roadmap references describe intended choices, not measured facts unless the cited document says so.

## Decision in one page

Keep the existing page-based retained representation as the correctness baseline, but add an experimental **instance-page rope** that combines (1) immutable reusable template skeletons, (2) sparse mutable instance overlays, (3) lazy *group-space* affine deltas, (4) support-function bounds summaries held in each page’s own coordinate frame, and (5) a typed presentation descriptor consumed by layout, hit testing, damage, and backends. Do not repeatedly transform an AABB and store the resulting AABB: rotation and shear inflate boxes at every level. For truly arbitrary per-node local-matrix replacement and reparent, evaluate a rooted link-cut path-product structure separately; it solves path products, not a complete subtree spatial index.

This design can make a group translation/transform mutation and its conservative bounds update logarithmic in the number of pages, and can make culling/damage discovery proportional to visited tree pages plus intersecting leaves. It does **not** by itself make a flat renderer upload or repaint unchanged descendants in sublinear work. Sublinear end-to-end presentation additionally requires a backend that can retain a group transform, draw from cached group surfaces, or reference stable GPU primitives. If the selected renderer needs one world matrix per primitive every frame, that flattening cost remains Θ(subtree size); record it as a capability and benchmark, not as a hidden assumption.

The canonical representation is therefore a hybrid, selected per mounted region:

```text
immutable Template (shape + default typed descriptors + local geometry)
        │ instance key + template revision
        ▼
Instance pages (256-ish records, overlays, order links, generational directory)
        │ split/concat by subtree and lazy group-space affine action
        ├── support-summary hierarchy (local-frame hull summary + error budget)
        ├── descriptor deltas (typed style/behavior/impact; no string hot path)
        ├── old/new damage and compositing dependency query
        └── backend Surface capability: group transform | retained layer | flatten
```

All public node identities remain owner-scoped, generational handles. A template ordinal or page-local offset is never a durable identity. All edits are applied transactionally to a candidate epoch; only after frame borrows end are page roots, descriptor versions, hit/layout state, and presentation epoch published together.

## What the existing plan already says, and what it does not

The runtime doc chooses a flattened paint-order SoA hot record of 8 bytes, 256-node pages and a Fenwick tree for counts; it keeps balanced-parentheses topology cold because the local notes report 3 bits/node versus 64 bits but slower navigation. It has a 64-pixel tile damage bitset and order/extent indexing. These are the established baseline choices in [08-runtime.md §4](/root/designs/reactivity/final/08-runtime.md:150). It also proposes compile-time constant subtree opcode templates plus patch offsets in [§7](/root/designs/reactivity/final/08-runtime.md:304), but those templates are a copy-at-description optimization, not a shared runtime skeleton with per-instance overlays.

The roadmap asks for an order sum-tree, localized splice/move, adaptive spatial damage index, transform-only paths, and retained fragments in [11-roadmap.md §Phase 3](/root/designs/reactivity/final/11-roadmap.md:78). It does not define the aggregate algebra for arbitrary affine transforms, what a structural split does to a pending tag, how summary approximation error is bounded, or whether renderer commands preserve group transforms. The local prototype is a useful oracle: [`spatial.rs` (`damage_subtree`, `refresh_subtree`, local workspace at HEAD `2014cdf6d37dccd87d2ed7d22ea9726face20164`)](/root/gpui-reactivity-tree/reactivity/crates/core/src/spatial.rs:194) iterates every descendant; [`damage.rs`](/root/gpui-reactivity-tree/reactivity/crates/core/src/damage.rs:1) has the 64px conservative tile bitset. These are local workspace paths, not published commit links; the workspace also has an untracked `reactivity/vendor/` path. The prototype therefore establishes O(k) traversal on a k-node affected subtree; it does not show the asymptotic lower bound for a lazy group transform.

## Design 1 — template skeletons with sparse instance pages

### Evidence and shape

Roslyn’s compiler tree uses immutable “green” nodes without parent/absolute-position data and a contextual “red” facade that supplies parent and position; immutable structure is shareable and a change copies the path while reusing unaffected nodes ([Roslyn design note, current main; retrieve and pin before implementation](https://github.com/dotnet/roslyn/blob/main/docs/compilers/Design/Red-Green%20Trees.md)). Rowan is a Rust implementation of immutable green nodes plus syntax-node facades; its v0.17.0 docs describe `SyntaxNode::replace_with` as copying the path and sharing unaffected structure ([rowan 0.17.0](https://docs.rs/rowan/0.17.0/rowan/)). These are source-backed examples of separating shared immutable shape from instance context. They do not establish that a UI’s mutable identity, GPU residency, or per-window state can be shared without an overlay.

Store a template as an immutable, topologically ordered skeleton: child counts/order, node kind, default style/behavior descriptor IDs, local geometry and semantic defaults. The runtime instance stores an `InstanceKey { owner_generation, template_revision }` plus sparse overrides in 256-slot pages. Ordinary node state lives in an overlay only when different from template defaults. Structural instance changes are a persistent page-rope overlay (insert/delete/move spans); never rewrite the shared template in place. Periodically compile frequently reused stable overlays into a new template revision at an idle maintenance point. This preserves multiple windows’ independent state and avoids invalidating existing template ordinals.

For a template tree of N nodes, a sparse overlay with k overridden nodes costs `k × (override bytes + local key/index bytes)` plus page/directory overhead. Lookup is O(1) if the template ordinal maps directly to a template column and an overlay bitmap/rank directory resolves changed slots; a balanced page map is O(log_B P), where P is the overlay page count. A persistent structural edit is O(log_B P + moved boundary-page work) by split/concat, assuming subtrees remain contiguous intervals in the instance’s preorder rope. The template itself remains O(N) shared once per template revision.

### Illustrative footprint, derived not measured

Take N=50,000 nodes, 50 instances, 1% instance-specific changes (k=500), 3-bit/node BP template topology, and a 16-byte override payload per changed node. One shared BP topology is 150,000 bits = 18,750 bytes. The sparse payloads are 8,000 bytes/instance = 400,000 bytes total, so about 419 KB before page headers, keys, directories, descriptor payloads, and alignment. A dense 8-byte/node per-instance hot overlay would be 20,000,000 bytes. This comparison deliberately excludes both designs’ shared properties and stable ID directories; it is not a whole-runtime memory estimate. At 25% overrides, a dense column/page representation may be smaller and faster; choose representation per page with hysteresis, not globally.

### Identity and adversarial cases

Runtime identity is `(owner/window namespace, slot, generation)`; template identity is `(template revision, local ordinal)`. The mounted node handle combines the instance identity with its instance-local generational slot. Do not key signal subscriptions, accessibility IDs, focus, async completions, or GPU primitive residency by template ordinal alone. Two instances of a button share its template ordinal but must not share its focus or click state. A template rebuild creates a new revision; explicit remapping is needed for overlays and durable semantic IDs. Unknown or unremappable overrides fail closed to a default with a diagnostic, never alias by numeric coincidence.

**Experiment:** compare current `const` opcode memcpy with shared skeleton+overlay for 1/10/50/500 instances and 0.1/1/10/50% overrides; include mount, diff, edit, removal, memory RSS, ID lookup, and cold/warm traversal. Trace a template schema change while instances retain old revisions. Correctness oracle is the existing full instance tree and identical paint/hit/a11y output. Reject if instance key/directory cost erases savings or if sparse-to-dense transition thrashes.

## Design 2 — page-local preorder rope with support-function summaries

This is the primary experiment for a subtree transform that should not touch descendants. Replace the flat-only sequence index for promoted regions with a B+ rope over preorder pages. Each page stores a bounded number B of records, subtree interval metadata, a lazy group affine tag, and a conservative local-frame convex support summary. Interior rope nodes aggregate child summaries. Splitting, concatenating, inserting or cutting a subtree first **pushes the pending affine tag to both children**, then changes topology and recomputes summaries bottom-up; this prevents a tag attached to an old interval from leaking onto replacement occupants after slot reuse or split. Structural semantics must be explicit: insertion inherits transforms through the new parent’s ordinary transform chain, not by accidental inheritance of an old interval tag. Cutting can mean “preserve local transform” or “preserve current world transform”; the latter materializes the pending tag at the cut root, and can fail if preserving-world requires inversion of a singular parent. These laws must be tested against eager per-node transforms.

### Affine algebra and bounds

Represent 2D affine `D(x)=Ax+t`. For a geometric set K, define its support function as `h_K(u)=max_{x∈K}(u·x)`. Then exactly:

```text
h_(D K)(u) = h_K(Aᵀu) + u·t
```

Proof: `max_{x∈K} u·(Ax+t) = max_x (Aᵀu)·x + u·t`. This holds for any real affine matrix, including singular A; it uses no inverse. It is the key reason to carry summaries in their local coordinate space and transform the *query direction*, rather than repeatedly taking `AABB(D·AABB(K))`. An AABB is only four extrema and loses the correlations that rotation/shear need; repeated reboxing compounds looseness. The support identity is a derivation, not a claim that any fixed small set of directions gives exact arbitrary-direction support.

For exact axis-aligned bounds, query `h_K(±e_x), h_K(±e_y)` and derive min/max. If the transform maps these directions onto the supported axes (translation, axis-aligned scale/reflection, 90° rotations), a small exact directional summary suffices. For arbitrary rotation/shear, maintain a bounded conservative support polygon or direction table. If bins have maximum angular gap Δ and the represented convex set lies within radius R of its origin, a circumscribed regular-direction approximation’s radial excess is bounded by `R(sec(Δ/2)-1)` in the centered isotropic case. General anisotropic/translated summaries need an explicit outward rounding calculation; do not reuse that simple bound blindly. Float rounding, unbounded coordinates, and repeated hierarchy levels add error. Store a per-summary error radius; when error or loose-area ratio exceeds budget, rebuild from child/page geometry or promote damage/culling to the containing group/viewport. Keep the source hull in local coordinates and query it through composed transforms so every ancestor rotation does not re-approximate it.

There are three concrete policies to compare:

1. **Exact common transforms:** retain exact local AABBs and exact composition for translation/axis-preserving linear maps. Arbitrary affine mutation takes the conservative path. No summary error; smallest and fastest hot case.
2. **Fixed m-direction support bins:** store m support extrema plus an outward error. With m=32 and f32 scalar supports, that is 128 bytes per summary. Directions can be evaluated at arbitrary `Aᵀu` only if the summary’s interpolation/outward bound is mathematically conservative; alternatively use queried bins and expand by the bin error. Repeatedly resampling bins after each transform can grow loose, so never do that. Keep a canonical local-frame summary and a composed tag.
3. **Bounded hull vertices:** store up to H convex vertices (e.g. H=8 or 16) in local coordinates, evaluate max dot products exactly against that polygon, and record an outer-approximation error relative to actual source geometry. Hull merge/reduction is only invoked after geometry/topology changes, not on transform-only updates. It gives tighter support at O(H) query, but H overflow requires deterministic conservative reduction/rebase. Geometry added after an old lazy group tag is pushed before insertion.

For a page with B=256 nodes, m=32 f32 support values cost 0.5 bytes/logical-node if one such summary is charged to each leaf page; a 24-byte affine tag adds 0.094 bytes/node. These are leaf-only averages. B+ internal summaries, child pointers, error bounds, capacity slack, and support polygons add memory and must be in the benchmark ledger. With fanout F=16, a transform range update touches O(log_F P) interior nodes and at most O(B) boundary records/pages, i.e. O(log_F P + B) metadata work under standard split/concat assumptions. A fully covered subtree node composes one lazy tag and transforms/reuses its summary; a partial overlap pushes and descends. Culling is O(log_F P + q) for q visited/intersecting summaries in favorable spatial/order clustering, but worst case remains Θ(P) when the query intersects everything or summary error is too loose.

### Transform mutation and paint semantics

A range action is an explicit typed `GroupDelta { space, affine, epoch }`, applied in a named coordinate space. Compose in one documented convention, e.g. column vectors and `D_new ∘ D_old`; test noncommuting transforms and singular matrices. The range action changes presentation space, not each child’s authored local transform. The renderer can consume a nested transform/group command, a retained layer, or a flattened packet. If a backend only accepts flat per-primitive world transforms, it still needs O(k) writes for k descendants even though tree metadata is O(log P). The fast path can still avoid layout and use GPU instancing or a retained group surface; it cannot claim zero work without that capability.

An arbitrary replacement of one node’s local matrix does not always equal a left-multiplied common delta, especially if code changes parent-relative semantics or needs to preserve children’s world positions under reparenting. The API should distinguish `set_local_transform` (local state changes, descendants inherit resulting world transform) from `move_preserving_world` (requires parent relation and possibly invertible parent transform) and `apply_group_delta` (left action on an entire range/group). Singular transforms are legal for rendering but cannot be inverted for preserving-world reparent; return an explicit failure or use a documented fallback. No code may silently use `inverse()` to “undo” lazy tags.

### Damage and culling

The summary tree supplies conservative old and new group bounds. Damage must include both epochs. Candidate selection queries the damage region against summaries, then replays every visible contributor intersecting the chosen region in painter order, not just changed nodes. A destination-reading blend, backdrop filter, group opacity/isolation, blur or shadow can expand the dependency closure; the descriptor for such an effect supplies a conservative sampling radius or forces whole-layer invalidation. If query summary looseness means nearly every page intersects, use a measured full-region threshold and record why.

**Experiment:** compare eager O(k) world refresh and exact descendant bounds (oracle) against exact common transforms, 32-bin support, H=8/16 hull, and local-frame cached group layers. Workloads: deep nested rotations, alternating 0°/45°/90° transforms, nested non-uniform scales and shears, repeated huge translations, singular maps, adversarial points near all bounds, and insert/cut/reparent at a tagged boundary. Measure (a) mutation ns and pages visited, (b) summary false-positive area and error after 10^3/10^6 actions, (c) culled pages/primitives, (d) paint/replay/upload bytes, (e) full-region fallback rate, and (f) p50/p99 present. Property test every bound contains every eager-transformed vertex. Rebase thresholds must be selected from these curves; do not ship an unmeasured “epsilon.”

## Design 3 — rooted link-cut paths for arbitrary transform replacement

The Sleator–Tarjan dynamic-tree structure supports link/cut in logarithmic amortized time ([Sleator & Tarjan, JCSS 26(3), 1983](https://www.sciencedirect.com/science/article/pii/0022000083900065)). A link-cut tree stores a path aggregate; for a rooted UI tree define the ordered aggregate from root to v as `M(root) · … · M(v)`. Affine matrices form an associative monoid under composition. This product is **noncommutative**; retain order explicitly. No inverse is required to replace M(v) and query a world transform, so singular transforms are fine. Reroot/reversal variants need both forward and reverse aggregates, with reversal swapping child order and those aggregates. Link-cut link/cut and path aggregate operations are O(log N) amortized under the standard structure, but splay operations have latency variance and matrix-query results are O(log N) each.

This solves “update one local transform without eagerly refreshing all descendant world matrices,” but it does not provide subtree bounds: a subtree is not a single preferred path. Top trees maintain dynamic clusters with constant-size boundaries and O(log N) updates for suitable cluster summaries ([Alstrup et al., “Maintaining Information in Fully-Dynamic Trees with Top Trees,” arXiv version](https://arxiv.org/abs/cs/0310065)). A top-tree can carry a bounded hull summary only after the summary’s merge/recompression/error law is specified; a citation to top trees does not prove arbitrary affine bounds are a constant-size exact monoid.

Footprint estimate: a basic LCT needs left/right/parent links and vertex payload/indexing; estimate +12–20 bytes/node after alignment, before summaries. A 2D six-f32 affine aggregate is 24 bytes; a second reverse aggregate adds another 24 bytes if reroot is used. At 1M nodes, 36–68 MB extra is plausible before allocator/page overhead. These are layout estimates, not measured Rust struct sizes. Prototype first for parent-stable trees and local-transform replacement, measure p99 splay access, and compare against the page-rope group-delta lane. Do not put both LCT and full child/sibling links in the default hot record unless measured queries require both.

Current Rust code is not turnkey proof. `lctree` 0.3.4 documents link/cut/path operations as logarithmic amortized and exposes a `Path` aggregate trait ([docs.rs/lctree 0.3.4](https://docs.rs/lctree/0.3.4/lctree/), [trait source](https://docs.rs/lctree/latest/src/lctree/path.rs.html)); its public examples/types must be checked for ordered affine composition and reversal before reuse. If `aggregate` is only commutative or orientation is not represented, write a tiny private structure with tests rather than adapting incorrectly.

## Design 4 — compressed page-local topology without weak identities

The baseline’s 64-bit generational slot `[index:32 | generation:32]` is a good external identity contract in [08-runtime.md §4](/root/designs/reactivity/final/08-runtime.md:153). Compress *internal references*, which are shorter-lived and remappable, while retaining that public handle and owner validation. For 256-slot pages, an in-page offset needs 8 bits. A 24-bit page ordinal plus 8-bit offset makes a 32-bit `NodeRef`, addressing 2^24 × 256 = 2^32 positions. For a configured cap of 16M nodes, at most 65,536 pages require only a 16-bit page ordinal plus 8-bit offset, so a 24-bit/3-byte packed reference can address them; a 20-bit page ordinal covers 268M positions. Use a versioned internal encoding and promote to 32-bit when capacity is exceeded. Do not pack by assuming max trees are small without a checked promotion/error path.

More aggressive topology is page-local: parent/first/last/prev/next are `u8` when they refer inside the same page; cross-page edges use a compact escape table or 32-bit NodeRef. Child order and subtree intervals can use page rope ranks. A realistic node must include its cross-page escape probability and alignment, so “five one-byte links” is not a credible whole-record estimate. Page-local refs are valid only within the page generation; compaction atomically rewrites directory entries and all exposed derived indexes before publishing a new epoch. No reference into a moving `Vec` may escape the borrow.

Expected cost: public-handle-to-page resolution is one slot-directory load (possibly generation and owner checks); same-page traversal uses byte offsets; cross-page traversal takes one escape load. Topology shifts are bounded by B within a page; page split/merge updates O(B) boundary records plus O(log_B P) rope metadata. Memory wins depend on locality; report bytes/node, cross-page edge fraction, cache misses, ID-directory bytes, relocation work and p99. Compare 24-bit packed fields against plain aligned u32: bit packing may lose in decode cost and unaligned loads even when it saves 1 byte/link. No change to the public generation width is justified by this optimization.

## Design 5 — descriptor deltas, styles, behavior overrides, and typed reflection

Treat a node’s authored element, effective style, and behavior capabilities as separate typed layers. A generated schema can expose closed field IDs and typed accessors for fields explicitly marked styleable/overridable; each field declares merge, reset, precedence, serialization, and invalidation impact. Runtime style resolution produces an immutable `ResolvedDescriptor`/delta from (template defaults, theme, inherited style, instance override, state pseudo-class), and publishes it as one epoch. Built-in style uses closed enums/IDs and dense arrays; strings are used only at parse/plugin boundaries. Behavior replacement is a typed capability or registered function with an owner/lifetime and declared input/output/effects, not mutation of arbitrary app fields during `view`.

This fits the frame-borrowed pure `view(&self)->El<'_>` contract in [00-model.md §2](/root/designs/reactivity/final/00-model.md:48) only if override resolution finishes before describing/borrowing, or feeds typed destination ports. Reflection cannot make an immutable `&self` mutable or make borrowed frame values live longer. A derive can eliminate repeated metadata plumbing; it cannot infer whether a private field should be themeable, how style merges, or whether behavior is safe to replace. Near-zero macro burden is credible as one opt-in derive plus a small number of semantic attributes and builder calls; zero annotations for arbitrary Rust structs is not.

Generated IDs must be version-stable where persisted and dense per build/runtime where hot access matters. Use a descriptor schema version + explicit migration for serialized overrides. Unknown ID/type mismatch rejects the override and reports a located diagnostic. Descriptor cache keys include owner/template revision, style ancestry revisions, state bits, and scale/environment inputs actually read; cache invalidation is dependency-driven. The UI thread owns mutable page overlays; background style parsing builds an immutable typed delta and posts it to the UI thread. Do not expose mutable aliases across a frozen frame.

**Adversarial matrix:** malformed/unknown style IDs, duplicate fields, two derived schemas with same field name, a `DerefMut` source that publishes without semantic change, parent style change affecting a nested inherited field, behavior override that emits an effect, descriptor change during a held `El<'f>` borrow, stale async style result after owner reuse, and serialized override across schema version change. Each must either resolve correctly or reject before publication.

## Design 6 — explicit incremental sources instead of ambient dependency magic

Bevy’s ECS change detection uses ticks on mutable access and access declarations for scheduler conflict analysis; its tick answers “changed since the consumer’s last run,” not “which arbitrary values did this Rust closure read.” See [Bevy 0.20 change detection](https://docs.rs/bevy/0.20.0/bevy/ecs/change_detection/) and [system access](https://docs.rs/bevy/0.20.0/bevy/ecs/system/). For the reactive UI graph, retain per-consumer epochs/read sets, but make dynamic capture explicit or generated. A static Bevy-style access set is attractive for parallel passes but cannot predict branch-dependent view reads without rerunning or conservative declarations.

Adapton’s PLDI 2014 paper distinguishes an inner incremental computation from outer demand and reuses named computations according to demand ([paper and authors’ project page](https://matthewhammer.org/adapton/); DOI [10.1145/2594291.2594324](https://doi.org/10.1145/2594291.2594324)). This matches retained components and lazily-demanded derived regions, provided identity/naming and effect boundaries are explicit. Differential Dataflow tracks indexed differences with partially ordered logical times for nested iterative data-parallel computations ([McSherry et al., CIDR 2013, primary PDF](https://www.cidrdb.org/cidr2013/Papers/CIDR13_Paper111.pdf)); DBSP provides incremental computation for rich stream/relational queries ([Budiu et al., PVLDB 16(7), 2023](https://www.vldb.org/pvldb/vol16/p1601-budiu.pdf)); DBToaster recursively materializes higher-order query deltas ([Ahmad et al., PVLDB 5, 2012](https://www.vldb.org/pvldb/vol5/p968_yanifahmad_vldb2012.pdf)). These are strong options for a query/collection subsystem, but their difference algebras, timestamps and retained indexes are not a justified default for ordinary view invalidation.

Rust borrow-safe dynamic dependency proposal: `ReadScope<'f>` is created for one describe invocation; `sample(&ReadScope, source)` returns a borrowed `Sample<'f,T>` and records `(source slot, revision)` in that scope. The result element is still frame-borrowed. Once the frame is lowered, retain only owned node IDs, typed ports and owned/shared payloads; no `Sample<'f,T>` crosses commit. A `Derived<InputPack, Output>` may instead declare a typed input pack and avoid dynamic tracking for hot stable components. Effects run outside memoized computations. Unknown `UnsafeCell`, global state, IO and nondeterministic calls are not memoized implicitly; when explicit source capture is absent, rerun the owner as a correctness fallback. A proc macro can rewrite selected syntax but cannot generally intercept arbitrary derefs through all traits or make references outlive the frame.

Borrow adversary: evaluate description, retain a borrowed child, then publish/mutate/drop owner before the child is lowered. The API must make this unrepresentable: higher-ranked frame closure, no references retained in node pages, explicit end-borrow before `&mut` commit, compile-fail tests, and Miri for unsafe arena operations. “Freeze” means immutable publication/lifetime, not permission for mutable aliases. Cross-thread readers consume immutable owned page roots or epoch-protected handles, never references into UI-owned mutable pages.

## Damage selection with compositing dependencies

Damage compression has two distinct stages: determine a conservative changed region; then choose how much to redraw/composite. The local 64-pixel bitset makes union bounded by viewport and deduplicates touched tiles ([damage.rs](/root/gpui-reactivity-tree/reactivity/crates/core/src/damage.rs)); it is a useful broad-phase representation, not a global optimum. Use a cost model:

```text
C(partial) = c_rect · submitted_rects
           + c_pixel · redrawn_pixels
           + c_draw · replayed_contributors
           + c_dep · expanded filter/blend dependency area
           + c_sync · target switches / fences / present overhead
C(full)    = same terms for whole target/layer
```

The coefficients are backend/device/scene measurements. Greedily merging adjacent rectangles or tiles is worthwhile when saved rect, layer and synchronization work exceeds the additional overdraw; recompute after each merge. A bounded greedy or tile cover is an approximation. Keep rect count, dirty area, contributors and dependent area; select full target/layer at a measured threshold and a kill switch. Include old and new bounds for movement. For each dirty output region, repaint all intersecting contributors in original painter order because unchanged lower layers may be revealed by a moved/removed upper layer. For a backdrop blur, destination-reading blend or filter, propagate invalidation through the region the operation samples; if that dependency cannot be bounded, redraw its containing isolated layer.

Platform interfaces constrain meaning. Vulkan incremental-present damage is a hint and the application remains responsible for correct presented pixels ([Vulkan `VK_KHR_incremental_present`](https://docs.vulkan.org/spec/latest/chapters/VK_KHR_surface/wsi.html)). DXGI dirty rects must be fully updated; scroll/dirty regions and swap-effect constraints matter ([Microsoft `DXGI_PRESENT_PARAMETERS`](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/ns-dxgi1_2-dxgi_present_parameters)). Wayland `damage_buffer` uses buffer coordinates and surface transform/scale ordering is part of commit semantics ([Wayland core protocol](https://wayland.freedesktop.org/docs/html/apa.html)). The backend adapter must map from logical surface to buffer/pixel coordinates and preserve full-image correctness. A “partial present” API does not guarantee the driver avoids full compositing.

| Differential Dataflow / DBSP / DBToaster | Incremental relational/recursive computations and indexed differences ([Differential, CIDR 2013](https://www.cidrdb.org/cidr2013/Papers/CIDR13_Paper111.pdf); [DBSP, PVLDB 2023](https://www.vldb.org/pvldb/vol16/p1601-budiu.pdf); [DBToaster, PVLDB 2012](https://www.vldb.org/pvldb/vol5/p968_yanifahmad_vldb2012.pdf)) | A separate data-query / virtual-list subsystem with large nested incremental queries | Their timestamps, indexes and difference algebra are not a compact replacement for a view dependency graph. UI values such as arbitrary closures and effects have no generic delta inverse. |

The dynamic tree candidates have another important scope boundary: link-cut trees aggregate root/path information; top trees aggregate dynamic clusters. Neither paper supplies a ready-made constant-size exact summary for the convex hull of arbitrarily transformed UI geometry. The affine support identity above supplies the algebraic query law, while bounded representation, error, merge, and workload behavior remain engineering hypotheses.

Include sparse cursor movement, 200 overlapping small changes, one huge transformed subtree, scroll, text reflow, opacity change, blur, backdrop, resize, scale, and device reset. Run on Metal, DXGI, Vulkan/Wayland and WebView hosting where available; report driver/backend and compositor.

## Surface sharing and the “GPUI inside GPUI” boundary

There are at least three distinct integration contracts, and “zero-copy” can only be stated for a specific device/process/API combination:

1. **Native in-process child view.** GPUI owns layout/event/focus boundary and embeds an OS-native view. Apple documents `WKWebView` as a view that can be placed in a host view hierarchy ([WKWebView](https://developer.apple.com/documentation/webkit/wkwebview)). On Windows, WebView2 composition controller attaches a web visual tree to a host visual target which positions and commits it ([ICoreWebView2CompositionController, versioned API](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2compositioncontroller?view=webview2-1.0.3912.50)). This is native composition, not necessarily a GPUI-owned texture. Focus, IME, accessibility and z-order remain platform protocols.
2. **Shared GPU allocation.** Apple IOSurface is intended for sharing image buffers between processes and graphics subsystems ([IOSurface](https://developer.apple.com/documentation/iosurface)); Metal shared texture handles are constrained to a compatible/same device and sharing mechanism ([MTLSharedTextureHandle](https://developer.apple.com/documentation/metal/mtlsharedtexturehandle), [makeSharedTexture](https://developer.apple.com/documentation/metal/mtldevice/makesharedtexture%28descriptor%3A%29)). Linux dma-buf import requires compatible format/modifier and synchronization; protocol support is negotiated ([linux-dmabuf](https://wayland.app/protocols/linux-dmabuf-v1), [explicit sync protocol](https://wayland.app/protocols/linux-drm-syncobj-v1)). Negotiate pixel format, plane layout, color space, protected content, fence semantics, ownership and release. A failed import needs a copy/composition fallback.
3. **Remote or WASM guest scene protocol.** Send versioned typed scene/resource deltas, input events, resize/scale, focus/IME and accessibility messages. Make ordering, resource generation, backpressure, timeout and stale-frame behavior explicit. This is cross-runtime synchronization, not pointer-sharing.

**Verified fact:** OS APIs expose different ownership/composition primitives and constraints. **Not verified:** any generic zero-copy promise across GPUI, a browser webview, arbitrary GPU, or process boundary. Build capability negotiation and trace actual copies/fences/latency. Prefer native child-view hosting for platform web content when the host system owns composition; use shared textures only where import and sync are explicitly supported; use remote scene protocol for independent guest runtimes.

## Four implementable experiments and go/no-go gates

1. **Support-summary page rope.** Prototype B=128/256/512 and F=8/16/32; exact four-direction path, m=16/32/64 bins, H=8/16 hull cap. Required result: no false negatives against exhaustive transformed vertices; transform-only metadata cost scales with rope height and does not touch leaf records; loose-bound/full-fallback rate stays below a workload-derived threshold. Include structural push-before-split/cut adversaries. Reject arbitrary-affine fast path if error quickly approaches viewport size.
2. **Shared skeleton plus sparse/dense overlays.** Use Roslyn/rowan-style immutable shape; overlay density representations switch with hysteresis. Required result: multi-instance bytes and first mount improve under realistic repeated components while focus/state/async identities remain instance-local; mutation and schema migration remain auditable.
3. **LCT affine path products.** Prove noncommutative forward/reverse folds, singular transform support, link/cut and reparent against a parent-chain oracle. Required result: local-matrix replacement avoids descendant refresh, p99 is acceptable, memory increase is offset by avoided work. Do not claim culling sublinear until joined with a valid dynamic subtree summary.
4. **Cost-aware compositing + surface capability matrix.** Add backend-retained group transform/layer flags to the packet contract. Required result: demonstrate a scene where subtree transform reduces end-to-end CPU/GPU work, not merely tree traversal; compare full, partial and group recomposition on each backend. If no backend supports the needed retained group action, leave metadata fast path experimental.

Add one integrated benchmark gate: mutate a 1M-node tree where a 250k-node subtree rotates/translates, insert one child under the lazily tagged subtree, cut and reparent a tagged child, and render with overlapping translucent/filter layers. Verify against eager scalar world transforms and full repaint. Record tree pages visited, nodes whose local/world records were touched, bound error and false-positive area, damage tiles, replayed draws, bytes copied/uploaded, allocations, and p50/p99 input-to-present. This single trace exposes the exact place where a promising data-structure result stops being a user-visible gain.

## Open questions

- Does the product require arbitrary affine changes to be sublinear, or is translation/scroll/group-scale the high-value case? The latter has a much simpler exact summary and API.
- Which rendering backends can retain group transforms or cached layer surfaces across frames, and when do isolation/blending rules force a rerender?
- Is convex support stored per page sufficient for actual scenes, or do common clip/filter/text behaviors require richer summaries? What error budget and rebase threshold keep false-positive work useful?
- What is the real overlay density distribution across repeated components? That determines whether bitmap+rank or sorted sparse patches beat dense per-instance columns.
- Should source dependency capture be explicit `ReadScope` for the first implementation, with a later derive, or generated static input packs for known hot components?
- What are the actual target OS/browser/GPU versions for surface-sharing guarantees, and which fallback copy path is acceptable?
