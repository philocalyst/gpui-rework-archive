# Text caret transaction frontier: structural options beyond the borrowed stream

This is a read-only design review for the reactivity text branch. I did not edit either worktree or run a build. The exact shipping review pin is `dded3dff54` (`shipping89ae`); the strongest current stream candidate is `81bd9e53b7a18161903dad3816d494ed1afdfce3`, with the matched indexed control at `1d5bc3061cce3beb3c4857102ed651da501b5cfd`. The candidate's final evidence and the one paired run are in `reactivity/evidence/monotonic-caret-stream/final-borrowed/README.md` and its `paired-run/README.md` in `/root/gpui-monotonic-caret-borrowed`.

## What the current code actually spends

At the candidate pin, `CursorGeometry::new` walks visible visual clusters, saves `{ClusterPath, f32 offset}` entries and fills a `u32` owner for each source byte. Its transient payload is 16 bytes per scalar-capacity entry plus four bytes per source byte ([geometry.rs](/root/gpui-monotonic-caret-borrowed/reactivity/vendor/parley/src/editing/geometry.rs:85)). For 32 KiB ASCII that is 655,360 requested payload bytes before capacity slack. The random API needs this shape because it answers arbitrary byte queries after construction.

The monotonic visitor already removes those two large arrays, but its public contract requires complete checked source-range admission before its first `FnMut` call ([geometry.rs](/root/gpui-monotonic-caret-borrowed/reactivity/vendor/parley/src/editing/geometry.rs:100)). It therefore scans lines, builds a per-line source-run map, visits all line graphemes to validate ranges and compute maximum RTL scratch capacity, then revisits line items for run origins, computes RTL visual prefixes, and visits source-ordered graphemes while consuming requests ([geometry.rs](/root/gpui-monotonic-caret-borrowed/reactivity/vendor/parley/src/editing/geometry.rs:128), [geometry.rs](/root/gpui-monotonic-caret-borrowed/reactivity/vendor/parley/src/editing/geometry.rs:411)). The second and third visits are structurally necessary for the current request/result order on RTL unless either the request order or the output representation changes. The first complete grapheme/range pass is the plausible transaction-boundary target.

Canvas gives a different ownership boundary. `Planner::shape` returns one `Result<TextLayout, Error>` and resets its reusable Parley layout after any error ([planner.rs](/root/gpui-monotonic-caret-borrowed/reactivity/crates/canvas/src/text/planner.rs:148)). During `shape_inner`, `glyphs` and `details` are local; `details` owns its `runs`, `lines`, and optional `carets`, and the only `TextLayout` is assembled at the successful end ([planner.rs](/root/gpui-monotonic-caret-borrowed/reactivity/crates/canvas/src/text/planner.rs:163), [planner.rs](/root/gpui-monotonic-caret-borrowed/reactivity/crates/canvas/src/text/planner.rs:245)). Thus carets appended before a later error are discarded with the unpublished plan. This is a real transaction boundary in this specific caller. It does **not** make a generic owned callback unobservable: `T` can contain `&mut`, `Rc<RefCell<_>>`, atomics, or perform I/O, and the public visitor can be observed before a later error. `ControlFlow` explicitly exists to expose visitor early exit and side effects ([Rust `ControlFlow`](https://doc.rust-lang.org/std/ops/enum.ControlFlow.html)). Keep the existing public visitor's checked-error-before-callback guarantee intact.

The GPUI consumer has a second, stricter publication boundary. At shipping pin `dded3dff54`, `present_inner` stages the completed text geometry vector into `TextResources::candidate` only near successful preparation's end, immediately before installing `Prepared` ([runtime.rs](/root/gpui-ce3/reactivity/crates/gpui/src/runtime.rs:3171)); exact ACK moves that candidate column into `presented` alongside the acknowledged node rows ([runtime.rs](/root/gpui-ce3/reactivity/crates/gpui/src/runtime.rs:2469), [text_geometry.rs](/root/gpui-ce3/reactivity/crates/gpui/src/runtime/text_geometry.rs:11)). A failed newer layout can therefore leave old P and eligible C intact; the checked-in owner fixture explicitly ACKs the old C after a failed L and checks the old geometry length ([text_geometry.rs](/root/gpui-ce3/reactivity/crates/gpui/src/runtime/text_geometry.rs:225)). The speculative Canvas sink must stop at the successful `TextLayout` result: only then can the complete map enter the local preparation vector, then C, then P on that exact ACK. It must never mutate the current L-owned site map or geometry columns directly. This preserves completeness and acknowledged P/C authority while allowing partial scratch inside one unpublished paragraph plan.

## Best structural experiment: a transactional Canvas sink with deferred admission

Add a narrowly scoped Parley streaming primitive used by Canvas planning. Keep `CursorGeometry::try_for_each_pair` semantically unchanged for generic callers. The new seam can be a `#[doc(hidden)]` public iterator because the crates are separate: something like `PairsEvent::{Pair { byte, pair }, InvalidLayout, UseIndexed}`. It yields source-ordered pairs, and explicitly permits a later `InvalidLayout`/`UseIndexed` event after prior pairs. Canvas consumes it immediately into its local `Stop` vector. An explicit partial-yield contract is essential for either an iterator or a visitor; it must not return an owned `Vec` of pairs. The implementation spike selects a synchronous borrowed visitor to share the current walk and avoid suspending its borrowed Run/Atom traversal. That is a candidate formulation, not proof that every fallible iterator must stage owned Clusters. The new API has an explicit partial-yield contract; no existing public API loses its atomic guarantee. Root reviewed the initial visitor/Canvas checkpoint source before focused qualification; the candidate is not yet adopted.

In Canvas, checkpoint `stops.len()` before consuming the new stream. For each pair, preserve the existing finite check and stop encoding. If a pair has non-finite geometry, set a local `invalid_geometry_seen` flag and continue draining the stream; do not return early. If the stream reports a source/font/range rejection, truncate to the checkpoint and run the existing indexed `CursorGeometry::new` path over a fresh `segment_str(content)` iterator. If the stream ends successfully, return `InvalidGeometry` when the flag was set, otherwise succeed. This preserves the old error precedence: `CursorGeometry::new` rejection (`InvalidFont`) precedes Canvas's finite-geometry error; ordinary geometry failure is reported only after all structural admission succeeds. The output transaction stays local and is published only when `shape_inner` succeeds.

The new stream can remove the full preflight cluster scan and its maximum-RTL-capacity census. It can grow one RTL `Vec<f32>` as each RTL run is reached, clear it for the next run, and produce each offset by the existing exact visual-cluster recurrence. This changes the timing of a possible allocation (it can occur after some stops were appended) but not retained output. It preserves the current output order and requests; no sorting or request copy is needed. It does not remove the RTL visual-prefix pass itself: source-ordered requests need each RTL cluster's visual prefix, while `f32` addition order must stay identical.

Structural anomalies discovered after writes need explicit handling. Today the preflight falls back to the indexed path before callbacks if source-run identities are duplicate/fragmented, or if a range is decreasing but potentially disjoint ([geometry.rs](/root/gpui-monotonic-caret-borrowed/reactivity/vendor/parley/src/editing/geometry.rs:136)). The transactional Canvas sink can return a distinct `UseIndexed` outcome; Canvas truncates to the checkpoint, recreates the ICU iterator, and invokes the existing indexed path. Do not turn a decreasing range into unconditional `InvalidFont`: the byte map can admit disjoint ranges in a non-monotonic order. Out-of-bounds, reversed, overlapping, or unrepresentable byte owners must still reject exactly as the index does. If there is any uncertainty whether the old index rejects or admits an anomaly, restart through that index rather than inventing a new policy.

The cleanest boundary is a crate-private *conceptual* seam, even though Parley and Canvas are separate crates. Practically this means a `#[doc(hidden)]` Parley iterator/result type with explicit partial-yield semantics, used only by the Canvas adapter; or move the transaction-aware lowering loop to a shared crate where the cursor internals are accessible. Do not disguise it as an internal certificate that callers can forge. Do not weaken the documented contract of `try_for_each_pair`.

### Why this is the best next candidate

It removes one full per-cluster pass plus eager maximum scratch sizing without adding a second output buffer. On long LTR it removes the full preflight work and avoids RTL scratch entirely. On RTL it still requires the exact prefix loop and the source-order emission loop, but avoids the prefix-capacity census and can grow only to the largest RTL run actually visited. Sparse inputs and short labels pay only a checkpoint integer and one bool. The existing `RunSlot` inline slot and spill table remain charged as in the current candidate. No retained Canvas or layout fields change.

Risks to price honestly: if malformed/private layout anomalies trigger restart, the indexed path allocates the old map after partial stop writes; `truncate` drops only plain `Stop` values but is still a second output mutation pass only for this exceptional fallback. Dynamic RTL growth can cause a reallocation while stops already exist. The stream must retain the same `> u32::MAX` guards, line/run ownership, empty layout treatment, full-slice range projection for line-scoped graphemes, gaps and empty runs, early break behavior where applicable, and source affinity policy. The `Planner` currently uses ICU grapheme boundaries as the only request source (`planner.rs:436-510`); do not substitute Parley graphemes for ICU boundaries. Unicode grapheme segmentation is a stateful Unicode rule system with contextual cases such as emoji ZWJ and RI parity, not a byte-local predicate ([UAX #29](https://unicode.org/reports/tr29/)).

## Other formulations, and why they are weaker

**Typed validated-layout borrow.** A non-forgeable `ValidatedLayout<'a>` could let the fast stream skip range validation only if the certificate is minted by the canonical shaped-layout/line-break producer after every mutating operation, and every public builder/mutator is audited. The audit starts favorably: `Layout`'s storage is `pub(crate)` ([layout.rs](/root/gpui-monotonic-caret-borrowed/reactivity/vendor/parley/src/layout/layout.rs:24)); external callers construct it through `RangedBuilder`, `StyleRunBuilder`, or `TreeBuilder` `build_into` paths ([builder.rs](/root/gpui-monotonic-caret-borrowed/reactivity/vendor/parley/src/builder.rs:93), [builder.rs](/root/gpui-monotonic-caret-borrowed/reactivity/vendor/parley/src/builder.rs:197)), then mutate line structure via public `clear`, `break_lines`/`break_all_lines`, `set_text_indent`, and `align` ([layout.rs](/root/gpui-monotonic-caret-borrowed/reactivity/vendor/parley/src/layout/layout.rs:51), [layout.rs](/root/gpui-monotonic-caret-borrowed/reactivity/vendor/parley/src/layout/layout.rs:199)). So an external caller cannot forge private range arrays directly, but a certificate must cover each of the three builder families, their source/style range checks, incremental line breaking, alignment, empty layouts, and every invalidation/rebuild path. It must also preserve current behavior for private malformed-layout tests. A certificate only moves the validation obligation; it removes a pass only after producer invariants prove bounds, disjointness, order, and integer limits for every covered route. Safer fallback is the transaction-aware stream above, which continues checking those conditions and handles late errors.

**Visual-order requests plus an index permutation.** This can avoid RTL prefix storage only if output can be placed at original request positions. It needs a per-boundary slot/index array or a second full stop representation, initializes slots, and later walks/reorders them. It adds a header plus at least one machine word per grapheme, often a full `Option<[BoundingBox;2]>`; it worsens source-order output and small/sparse cases. The ICU4X grapheme iterator is forward-only in this pinned dependency source (`GraphemeClusterBreakIterator` implements `Iterator`, with no `DoubleEndedIterator` implementation in `icu_segmenter-2.3.0/src/grapheme.rs:36-70`), so a backwards Canvas pass also needs collected boundaries or a second segmentation mechanism. Reimplementing grapheme rules to avoid that vector is not justified.


**Reverse emission and reverse the existing stops.** Parley has reverse logical grapheme traversal, and for a single RTL run this follows visual order ([run.rs](/root/gpui-monotonic-caret-borrowed/reactivity/vendor/parley/src/layout/run.rs:199)). But Canvas requests are ICU boundaries and the public stop stream is source ordered; ICU's iterator is not double-ended. Staging byte boundaries costs 8 bytes each before headers/slack and still needs special handling for same-byte upstream/downstream ordering when reversing. Mixed direction, line breaks, gaps, and paragraph concatenation add more paths. This is a separate experiment only if a reverse boundary iterator can be added to ICU without divergence and the existing `Stop` vector can be reversed in-place with exact within-byte order.

**Keep an atomic callback and pass an owned accumulator.** This does not make it unobservable: an owned accumulator can wrap shared interior mutability, a mutable borrow, or a writer. Restricting `T` to `Vec<Stop>` would couple Parley to Canvas and still expose partial mutation to an external holder if the Vec is shared. The safe generic contract is still preflight before callback.

**Unsafe uninitialized output slots / `set_len` / `MaybeUninit`.** Rejected. It introduces drop and panic-safety obligations, does not remove the need to preserve the final source order, and has no evidence of a measurable gain. The current savings are scratch bytes; unsafe output initialization would add proof surface for potentially zero-copy or no semantic benefit.

**SIMD for exact RTL prefix accumulation.** Rejected as a first formulation. Each prefix is defined by the prior rounded `f32` addition. A parallel scan, regrouped sum, reverse subtraction from run advance, or reassociation can change bits and signed zero. A SIMD pipeline could still help ICU boundary search or independent range/finite checks, but it cannot simply vectorize this recurrence while promising the exact current results. The desired fearless_simd style is appropriate where lanes are independent; cite no speed claim until a scalar-equivalent proof and whole-pipeline measure exist.

## Exact behavior and ownership proof obligations

Before implementation, pin the new type and method to one source revision and prove these obligations against the current direct and indexed oracles:

1. Existing `CursorGeometry::try_for_each_pair` invokes zero callbacks on every admission rejection. Its generic `FnMut` early-break result and repeated/decreasing request semantics stay unchanged.
2. Canvas speculative output is unreachable until the full `TextLayout` returns `Ok`. Every failure truncates speculative carets before fallback, and `shape` discards the reusable Parley layout on failure. No `P`/`C` publication or ACK state is coupled to a speculative stop vector; if the caller integrates shaped output with a prepare/commit owner, that commit still happens only after `Ok(TextLayout)`.
3. Error precedence remains structural/font rejection before `InvalidGeometry`, with existing earlier errors in `shape_inner` unchanged. The deferred geometry flag must continue validation after a non-finite pair; it cannot early-return.
4. Admission matches `CursorGeometry::new` for empty synthetic metrics clusters, source byte bounds, overlap, decreasing-but-disjoint ranges, run identity fallback, `u32` limits, and empty ranges. Use the old indexed builder on any ambiguous structural anomaly; do not assert that malformed private state cannot happen.
5. Geometry bits match both affinities, including byte zero/end, hard newlines, soft wraps, bidi aliases, whitespace, gaps, empty runs, RTL and mixed bidi. Retain the exact visual recurrence: each run prefix starts at the exact line/run origin and adds each `f32` cluster advance in the existing order. Do not synthesize a run start by subtracting a suffix from `run.advance()`.
6. Input remains ICU's grapheme iterator; partial traversal is monotone. If any reusable helper supports arbitrary iterators, decreasing requests must either preserve the existing fallback or be excluded by a narrowly typed monotonic source.
7. No additional per-boundary Vec, source map, cache field, global state, sort, or unsafe initialized-length trick appears. Record `size_of` for every local header/slot and `Vec` capacities for empty, one-run LTR, long RTL, many-run mixed, and sparse/tiny paths.

## Minimum decisive gates

The current stream remains **unadopted**: its one seven-pair local CPU0 capture found RTL slower in both scopes (+4.10% cold, +3.06% warm), mixed slightly slower, and a +4.22% one-long-grapheme cold result; Latin warm improved 3.23%. It does prove a real scoped allocation reduction on 32 KiB ASCII (655,360 transient requested bytes to zero) with unchanged retained bytes. It does not prove a universal speed win or a native-frame benefit (final paired-run README has full limits and all samples).

For the transaction candidate, the smallest useful correctness gate is differential testing of the full public API guarantee plus Canvas output/error transcript. Include valid producer layouts and malformed private cases: out-of-bounds, reversed and overlapping ranges; duplicate/fragmented run ids; non-monotonic but disjoint source ranges; empty synthetic layout; >u32 admission guards; non-finite geometry before a later structural fault; callback early-break/error; and decreasing/repeated direct requests. Compare complete `f32::to_bits()` for x/y/width/height and exact `(byte, x bits, affinity)` stop order.

Then measure one pre-registered matched control/candidate campaign, pinned binaries and compiler, with no timing threshold shopping: tiny one-run labels, long LTR ASCII, Latin, long RTL, mixed bidi with many runs, wrapped paragraphs, and fallback-heavy text. Capture per-case allocation calls, requested/live/peak bytes, retained `TextLayout` bytes, and release assembly/code size. The decisive structural proof is one fewer full grapheme/range pass on admitted LTR and no per-boundary map; the decisive adoption proof is no material universal latency regression and expected retained/transient memory gains on realistic text. Preserve every sample, including losses. Do not resample an unfavorable cohort to make a threshold pass.
