# Accessibility projection: exact sparse updates without a second tree

Research pass: 2026-10-21. This is a read-only review of `/root/gpui-ce3/reactivity` and the pinned AccessKit source at commit [`ce8164ba92995cfa86005b6259115e08c8244253`](https://github.com/AccessKit/accesskit/tree/ce8164ba92995cfa86005b6259115e08c8244253). It focuses on the next implementation seam: consume the acknowledged presentation (`P`) to publish native accessibility, with no retained GPUI-side semantic mirror.

## Recommendation

Ship the first native bridge with the safe behavior already accepted by the integration work: do no AccessKit node construction while the adapter is inactive; answer each activation with a complete tree from the latest acknowledged `P`; publish a complete tree for each changed `P` until sparse updates are validated; send an empty-node update with the latest valid focus when only focus changed. This establishes activation, live updates, native geometry, and action delivery before optimizing the adapter boundary.

There is a narrower exact sparse path that adds no retained diff tree and no per-node hash. The existing `present_inner` pass already walks every candidate node to construct `Prepared.nodes`. While appending each candidate, compare it with the prior `Presented` at that output slot and tentatively collect only the changed AccessKit nodes. Enable this path only if the old and new sheets have equal length and every slot has the same stable identity and parent identity. If one slot differs—including because list clipping changed the realized subset—discard the tentative delta and emit a full tree for that presentation. In the stable-structure case, parent child lists and their order are unchanged, so a changed leaf can be emitted alone. This is exact and conservative; it does not claim to eliminate the existing O(N) presentation walk or AccessKit's required adapter-owned tree.

Do not derive semantic publication from `Runtime.nodes`, `Runtime.list_rows`, `source_epoch`, `complete_epoch`, or `topology_changed` alone. `acknowledge` is the exact authority transition: it has old `P` and candidate `Prepared` together before replacing the former. Failed preparation leaves old `P` queryable while logical source state can be newer. Resize, focus and realized-list membership can also change native semantics without a source epoch change.

## Source audit and exact update rules

In the checked runtime, `Presented` is a preorder vector with stable node identity, parent index, role-kind, optional text, local rect, flat node-to-window transform, viewport-clipped bounds, hit eligibility and action bits. `Prepared` owns the candidate vector. `Runtime::acknowledge` takes `prepared`, then assigns `self.presented = prepared.nodes`. The old sheet is therefore available for one exact comparison at the only moment when a native update should be prepared. Building an independent mutable `A11yTree`, a per-node tracker, or a second persistent identity map duplicates state and creates another lifetime to synchronize.

For an initial activation, build a complete `TreeUpdate` from the current acknowledged `P`, even if the app normally sends deltas. AccessKit's `ActivationHandler` explicitly requires a full tree for every activation request; activation may happen repeatedly without a deactivation callback. Its `TreeUpdate` owns a `Vec<(NodeId, Node)>`. A node listed in an update is replaced, so all of its unchanged properties must be repeated. Adding an element requires both the child and updated parent child-list; deleting a subtree requires omitting the removed child from its surviving parent's children and omitting the deleted subtree from the update. AccessKit requires the newest focus ID on every update, including an update with zero changed nodes. [AccessKit `ActivationHandler` 0.25.1](https://docs.rs/accesskit/0.25.1/accesskit/trait.ActivationHandler.html), [AccessKit `TreeUpdate` 0.25.1](https://docs.rs/accesskit/0.25.1/accesskit/struct.TreeUpdate.html), [pinned schema source](https://github.com/AccessKit/accesskit/blob/ce8164ba92995cfa86005b6259115e08c8244253/accesskit/src/lib.rs).

The current AccessKit worktree's first projection maps `Role::Text` to AccessKit `Role::Label`, but supplies its text through `Node::set_label`. The pinned AccessKit schema says text content for a `Role::Label` node is its `value`; AccessKit Consumer's `labelled_by` tests construct label nodes with `set_value`. Change this before claiming linked label semantics, and assert the consumer-resolved name. For a standalone GPUI text node, either map it to `Role::Label` plus `value`, or use a role whose name comes from `label`; do not populate both just to hide a role/schema mismatch.

For the stable-slot path, equality must cover every emitted field: role; name, description, value and placeholder; state and action capability; ordered children; relations; full exposed bounds; and text metadata when implemented. Compare semantic values exactly. A hash may be an optional rejection hint, but cannot be the correctness test. `Presented` action flags are frozen with `P`; focused state is live and may update without a new `P`. If the latest logical focus no longer names a node in published `P`—for example after a description edit whose presentation failed—send the root focus or retain the last focus that is valid in that native tree. Never serialize a current-S target that has not appeared in acknowledged P.

Stable-slot equality makes the sparse child-list rule especially simple: if every identity and parent identity is unchanged, every ordered parent-to-child list is unchanged. A changed nonleaf node still needs its complete unchanged child list because AccessKit overwrites the whole node; regenerate that list from the existing preorder range. For a changed leaf, no child vector is needed. If identity or parent identity differs at any slot, fall back to a complete projection in the first version. A later structural-delta path may mark the old and new parents for a reparent, the surviving parent for insertion/deletion, and the ordered parent for reorder. Deleted nodes and descendants must not be sent. Do not use `topology_changed` as the only guard: it compares logical `Runtime.nodes`, while list presentation can omit rows as clipping and realization change.

One practical implementation has no temporary index map:

1. During candidate presentation, compare candidate slot `i` against old `P[i]`; append changed node records to a temporary vector.
2. Mark the vector structurally untrusted if an identity or parent identity differs, or if the final candidate length differs.
3. At acknowledgment, if the structural check passed, publish the changed records plus latest valid focus. Otherwise drop the tentative records and publish the complete candidate tree.
4. Move the candidate into `P` only after the update payload has been constructed. Apply the platform update and raise native events after releasing the mutable window borrow, because providers can reenter during event delivery.

The comparison belongs in the existing candidate traversal, not in `acknowledge` as a second O(N) walk. The full-tree fallback is necessary to make the optimization safe. On list-scroll or reorder workloads it can lose: most rows may change geometry, identity, or membership, and a complete projection could be faster than comparisons, branches, and repeated child-list construction. Measure both paths and preserve the fallback unless the sparse path wins on a named workload.

### Epochs, focus, and actions

AccessKit's consumer applies a `TreeUpdate` to a specific previous tree; the sender and receiver must stay in sync. The consumer's `update_and_process_changes` retains old/new snapshots to derive node changes and focus events. Consequently, the UI runtime's `presentation_epoch` is useful as a publication cursor but is not a semantic diff: equal epoch values do not mean equal focus, and newer source state does not mean newer published geometry. Source proof: [pinned `accesskit_consumer::Tree::update_and_process_changes`](https://github.com/AccessKit/accesskit/blob/ce8164ba92995cfa86005b6259115e08c8244253/accesskit_consumer/src/tree.rs).

Native actions should remain commands admitted to the existing owner input barrier. The pinned AccessKit `ActionHandler::do_action` callback returns `()`, so an adapter cannot be told that a bounded GPUI queue was full and truthfully propagate Busy. Activation is idempotent and can use a dedicated pending bit plus wake; invoke, focus and set-value are occurrences and cannot be collapsed. With a bounded queue, nonblocking callbacks and an arbitrary arrival rate, lossless admission cannot be guaranteed. Keep the accepted overflow policy observable and fail closed; do not describe it as UIA Busy or exactly-once. Callbacks must only transfer owned bounded action data and wake the owner, not borrow `Win`, `Part`, or application state.

There is one necessary action cancellation race to specify: a callback can observe `active=true`, then deactivation can clear it, then the callback can successfully `try_send`; owner drain will see inactive and discard the queued action. This is a valid cancellation-at-deactivation policy, but queue admission does not mean eventual `Win::perform`. Document and test this interleaving so an accepted command is not misdescribed as exact-once.

There is no safe blanket rule that rejects every action because `P` advanced. A stable, still-live target can have an older displayed action capability while current logical state has changed; `Win::perform` should revalidate namespace, current target membership and current interaction eligibility at the owner barrier. For list reveal/realize actions, keep stable row key separate from currently actionable `Target`; reveal the key, present and acknowledge, then issue a fresh target. This avoids resurrecting stale targets.

## No-hot-field semantic annotations

The current borrowed `Part` distinguishes text, name, value, actions, focus, role and bounds, but explicit input labels, descriptions and relationships are not implemented. `Part::name()` currently treats text as the name for every non-input and deliberately does not infer an input name from its edited value. Preserve the last rule in the native projection: an input's `value` is not its accessible name. A generic text payload is also not automatically the name for every future generic/container role.

AccessKit distinguishes `label`, `description`, `value`, and placeholder. It supports `labelled_by`, `described_by`, `details`, `error_message`, `active_descendant`, and other relationships. Its consumer resolves `labelled_by` through the actual related Label nodes; a label node's text is its `value`. A reusable framework API should therefore let authors connect an input to an explicitly labeled sibling, add an override name or description, and set role/state independently. The [egui API](https://github.com/emilk/egui/blob/main/docs/accessibility.md) is a compact precedent: visible labels can be linked with `.labelled_by(label.id)`, while custom widgets provide explicit role/enabled/name; its AccessKit-backed test harness tests the same role/name that a screen reader consumes. Slint exposes separate accessible label, description, role, value, and IDs rather than conflating them; see the pinned [Slint 1.18.1 AccessKit projection](https://docs.rs/crate/i-slint-backend-winit/1.18.1/source/accesskit.rs). The [WAI-ARIA 1.2 Recommendation](https://www.w3.org/TR/2023/REC-wai-aria-1.2-20230606/) is the semantics reference; the AccName algorithm has precedence and reference traversal rules, so a framework should not invent a generic “text wins” rule.

To keep common persistent `Node`/`Presented` size unchanged, put only explicitly-authored semantics in a sparse cold sidecar attached to `Prepared` and moved to acknowledged `P`. Store records sorted by presented index or stable identity; only annotated nodes occupy entries. Keep role/state/action overrides as packed values, reference related IDs through existing stable target identities, and share text via the existing `Arc<str>` until native projection has to make AccessKit-owned strings. Empty sidecars should be absent (`None`), not one heap object per node. The cold sidecar must be built before presentation and published only when that P is acknowledged; do not read annotation/list data from current logical S when an older P remains visible. Benchmark the sparse cases (one annotated node in a large sheet, annotations on every node, and all realized list rows) against adding a field to every node before choosing a representation.

Virtual-list metadata needs the same P lifetime. `Runtime.list_rows` is rebuilt during description and can already describe different logical S when a presentation fails. Freeze the stable row key, list identity, one-based position and total/unknown count into the candidate P representation. The checked configured item cap is 1,000,000,000, so a one-based index/count fits `u32`; this avoids widening the hot row struct solely for native a11y. A changed total count dirties every exposed row's `size_of_set`; reindex/reorder dirties each affected row's `position_in_set`, even when its text and bounds did not change. Position/count lets a screen reader announce “N of M”; it does not make all virtual rows independently addressable. UIA's `ItemContainer`/`VirtualizedItem` path and reveal behavior are additional work. [Microsoft virtualized-item guidance](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-workingwithvirtualizeditems), [WAI-ARIA `aria-posinset` and `aria-setsize`](https://www.w3.org/TR/2023/REC-wai-aria-1.2-20230606/#aria-posinset).

### Text selection and IME are a separate semantic phase

AccessKit supports `SetTextSelection`, `ReplaceSelectedText`, and text-run metadata. Its `TextPosition.character_index` indexes the editor's `character_lengths` entries, not Unicode scalar values or UTF-8 bytes. The pinned consumer example models a multiline input and a child `TextRun`, selected range, placeholder, per-character lengths, positions and widths. Windows and macOS adapters expose native text-selection operations through this model. GPUI currently has committed text/value and basic key editing, but its key type explicitly lacks selection/IME state and the native Winit path does not publish preedit composition. Do not advertise text selection or replace-selection until the owner stores and commits selection ranges, has a defined grapheme/selection-unit mapping, carries IME preedit/commit, and can correctly map native text positions back to the owner. [Pinned AccessKit text schema](https://github.com/AccessKit/accesskit/blob/ce8164ba92995cfa86005b6259115e08c8244253/accesskit/src/lib.rs), [consumer multiline-input example](https://github.com/AccessKit/accesskit/blob/ce8164ba92995cfa86005b6259115e08c8244253/accesskit_consumer/src/node.rs).

## Adversarial conformance and performance gates

Build a headless oracle before optimizing. From a fixed acknowledged P, produce a complete AccessKit tree; apply each candidate sparse update using the pinned `accesskit_consumer::Tree::update_and_process_changes`; independently rebuild the full tree from the new P; compare normalized role, name, description, value, states, actions, relationships, ordered children, focus and physical bounds. Exercise: leaf rename; role/action/state change; add/delete subtree; reparent; sibling reorder; focus-only update; resize/scale; list scroll with same visible count but new IDs; changed total count with same realized rows; failed presentation after logical list/label/focus changes; repeated activation; deactivation; and updates with no active adapter. Also test namespace separation and old-P actions after current logical state disables or removes the target.

Use separate inactive, initial activation, sparse stable update, structural fallback, and high-churn list-scroll profiles. Record allocations/bytes, candidate comparisons, AccessKit nodes converted, tree nodes touched by the consumer, native events raised, and p50/p95/p99 owner-turn time. Gates:

- Inactive: zero AccessKit node conversions, node allocations, or adapter projection calls over paint-only frames.
- Activation: complete tree from acknowledged P with no view/description/paint/app callback. Measure 10k and 100k nodes; report latency and peak temporary bytes.
- Stable sparse update: a 100k-node sheet with one leaf rename converts one node, not 100k; emitted tree after consumer application equals full rebuild. A focus-only update has `nodes=[]` and correct focus.
- Structural fallback: one insertion/deletion/reorder with unchanged suffix IDs must never produce a malformed sparse tree; it may deliberately convert all nodes in version one.
- Losing workload: 10k/100k realized rows scrolling by one viewport, both stable and newly realized keys. Keep the full-tree route if sparse comparison/materialization does not lower total owner-turn time and allocations; do not count the traversal already required for layout/paint as saved work.
- Saturation/reentrancy: activation while FIFO is full still returns a full tree; full action FIFO raises the documented overflow; callbacks never hold the owner borrow; a native event that reenters queries sees a coherent P.

Consumer tests prove schema and delta validity, not OS providers. Separately exercise real UIA clients on Windows (including `WM_GETOBJECT`/nested provider calls), VoiceOver on macOS, and AT-SPI on Linux, with screen-reader/provider versions recorded. A native action or event-generation test is not proven by a successful headless AccessKit tree test.

## Read sources and what they do—and do not—prove

- **AccessKit 0.25.1, commit above.** Read `TreeUpdate`, `ActivationHandler`, node relationships, text-selection schema, `Tree::update_and_process_changes`, and the Windows adapter. The consumer explicitly stores old/new states to emit changes; sparse sender updates are required for low work, but the adapter still owns a full accessible tree. [Pinned schema](https://github.com/AccessKit/accesskit/blob/ce8164ba92995cfa86005b6259115e08c8244253/accesskit/src/lib.rs), [pinned consumer](https://github.com/AccessKit/accesskit/blob/ce8164ba92995cfa86005b6259115e08c8244253/accesskit_consumer/src/tree.rs).
- **Slint 1.18.1, Winit AccessKit source.** Read the full `accesskit.rs` and `event_loop.rs`: it keeps a `CachedNode`/property tracker and child cache, sends changed properties sparsely, rebuilds after structural changes, carries item index/count into list semantics, and defers an action until after adapter borrowing. This validates the shape of the update and callback ordering, not a zero-cache design. The large-list issue [#3867](https://github.com/slint-ui/slint/issues/3867) reports user-observed accessibility cost; it is not a portable benchmark result. The 1.18 changelog fixes list-position and traversal regressions, which makes the list-scroll case mandatory in the gate. [Pinned 1.18.1 source](https://docs.rs/crate/i-slint-backend-winit/1.18.1/source/accesskit.rs), [event loop](https://docs.rs/crate/i-slint-backend-winit/1.18.1/source/event_loop.rs), [changelog](https://github.com/slint-ui/slint/blob/v1.18.0/CHANGELOG.md).
- **egui Accessibility guide.** Read the label-link, explicit custom-role/name, and `egui_kittest` examples. This demonstrates a public author API and same-tree testing. It does not define GPUI storage costs. [Official guide](https://github.com/emilk/egui/blob/main/docs/accessibility.md).
- **DBSP, PVLDB 16(7), 2023.** Read the stream-differentiation model and delta maintenance formulation. The helpful principle is to maintain a derived view from the actual committed state transition, not guess from an epoch number. The limitation matters: a UI presentation includes geometry/clipping and a side-effecting native consumer, so relational delta operators do not provide this runtime's exact publication diff automatically. The slot-by-slot comparison above is justified by the concrete `Prepared`/`Presented` vectors, not by claiming DBSP directly incrementalizes arbitrary view closures. [Paper PDF](https://www.vldb.org/pvldb/vol16/p1601-budiu.pdf), [arXiv record](https://arxiv.org/abs/2203.16684).
- **WAI-ARIA 1.2 and UIA virtualization.** Read the normative position/size properties and Microsoft realization guidance. Position/count describes currently exposed items; it is not a virtualized-item implementation. [WAI-ARIA Recommendation](https://www.w3.org/TR/2023/REC-wai-aria-1.2-20230606/), [UIA virtualization guidance](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-workingwithvirtualizeditems).

The previous research note [`accessibility-frontier-luna.md`](accessibility-frontier-luna.md) records the exact `accesskit_winit 0.34.1`/Winit 0.30 compatibility, lazy activation and Linux AT-SPI worker/thread floor, geometry coordinate contracts, and bounded-action overflow limitation. This report adds the committed-P delta algorithm and metadata lifetime requirements; it does not change those platform conclusions.
