## What a81 already removed

The candidate already uses retained per-renderer packet storage and word-level dirty envelopes (`crates/gpu/src/renderer.rs:133-171`), affine/material planes and two-word placements (`:121-124`, `:186-194`), packed image bytes in the same GPU word buffer (`crates/gpu/src/renderer/images.rs:1-3, 145-183`), a direct uniform-tile path and opaque prefix (`crates/gpu/src/shader.rs:431-464`), and owner/token-gated redraw or paint-only submission in shipping `crates/gpui/src/native.rs:270-294`. They do not make arbitrary changed text/image frames incremental: those still rebuild CPU tile counts/references, resource metadata, and the complete target.

## Candidate A — remove the canonical-group counting pass

The current GPU packet is laid out as paint prefix, all affine common words, all material common words, then all placements. The shader computes `material_base = state_base + Globals.material_offset` (`crates/gpu/src/shader.rs:50-67`), so `render_observed` first walks every group to count compact common rows and discover the plane offset (`crates/gpu/src/renderer.rs:738-753`), then walks groups again to fill those rows and placements (`:778-849`). The canvas already presents canonical painter-ordered groups and each group's placement slice (`crates/canvas/src/canvas.rs:720-754, 899-907`).

**Formulation:** retain the paint prefix; emit each group's common record as four adjacent words `[affine-x, affine-y, clip, color]`, followed immediately by its placement records. A compact group emits four shared words plus `2*n` placement words; an unpacked group emits `6*n`, exactly the same payload count as today. Store each common-record base in the existing placement metadata. Then `load_draw`/`load_paint` use `state_base + 2` for clip/color and remove `material_offset` from shader `Globals`; calculate `word_count` only after emission. Reserve with the safe upper bound `bank_words + 6 * draws` (checked arithmetic), but keep `records.len()` equal to actual payload. This deletes the `scene.groups().map(...).sum()` traversal and its global plane-offset dependency; no new persistent state, allocation, resource identity, or pass is introduced. Reverse traversal can reconstruct addresses from the final length using each group's existing compact predicate, preserving CSR order and correction/resource patch order.

**Mixed content and exactness:** keep image bytes after the emitted record prefix; `images::prepare` already takes actual `draw_words` and detects prefix relocation (`renderer/images.rs:59-96, 145-183`). Mask/image records retain the current resource encoding, and text placements remain ordered exactly as `PreparedScene::groups()` exposes them. All common and placement words remain bit-exact. CPU admission stays before the resource/queue preparation boundary; preserve packet revocation at render entry and only reinstall it after `submit` (`renderer.rs:665-690, 855-863, 973-1053`).

**Price / reject cases:** the current two-plane order keeps common-state and placement dirty ranges independently uploadable (`renderer.rs:758-759, 985-992`). Interleaving means two independent changes can span unchanged words between groups; one dirty envelope would transfer those bytes. A transform-only update to one very early and one very late group can therefore upload a large middle section, while the existing planes may upload two narrow bands. It also changes the paint word address calculation and must retain the `PaintRenderer` observer contract (`renderer/paint.rs:153-175`). Avoid reserving the worst-case `6*n` capacity permanently: compact-heavy scenes would waste up to four words per draw. The lower bound `4*group_count + 2*draw_count` is exact for compact groups; uncompact/rounded-image groups can grow the retained vector on demand, with a checked reserve at that group. This trades the first such growth for avoiding a mandatory count traversal. It is most plausible for full scene rebuilds with many groups and infrequent partial updates; reject if realistic paint/geometry edits show the enlarged upload envelope or growth cost outweighing the removed O(groups) pass. Falsify with: 65k singleton groups; one transform-only edit at each end with unchanged placements between; compact shared text runs; rounded-image groups that force unpacked records; an image-prefix relocation; and a failed admission followed by `redraw` (which must remain `None`).

## Candidate B — fold tile statistics into the CSR prefix scan

There is a second full tile-array walk that computes only diagnostic counters. The candidate first normalizes counts to end offsets and encodes the constant/opaque bits (`renderer.rs:865-883`), then walks all tiles again to calculate `uniform_tiles`, `sample_evaluations`, and `sample_draw_evaluations` (`:936-953`). The count/tag, cursor, tile dimensions, and surviving range are all available in the first loop.

**Formulation:** accumulate the three counters while each tile is normalized. The uniform case contributes one tile and no samples. Otherwise, after adding `count` to the running offset, use that tile's area, `constant` tag, and whether `cursor != 0` to add exactly the current expressions: `samples = area * (constant ? 1 : 16)`, `draw_samples = area * prefix + samples * (count - prefix)` for nonempty ranges. This deletes one O(tile-count) pass and no state or allocations. It applies unchanged to text/image tiles because diagnostics count planned evaluations, not material type; mixed sources remain in CSR and shader evaluation.

**Price / reject cases:** a few branches and area calculations move into the prefix scan. Max canvas pixels are 16M, hence at most 65,536 16x16 tiles, so this is bounded and low risk but also a modest absolute ceiling. Falsify by exact field equality against the current second scan for empty, direct-uniform, constant-coverage, opaque-prefix-only, partial-edge-tile, and ordinary sampled tiles, including counts equal to the opaque prefix boundary. Keep diagnostic field semantics unchanged.

## Why not delete the reverse tile visit / CSR

The forward visit both validates and counts/records the opaque cutoff (`renderer.rs:778-849, 1153-1194`); after count normalization, the reverse visit fills a contiguous per-tile CSR while preserving painter order and omitting predecessors before the cutoff (`:887-935`). Replacing it with “scan every draw for this tile” removes CPU reference materialization but makes per-fragment traversal O(draws) rather than O(tile references); at the admitted limits that can become 65,536 draws per pixel versus a 4M-reference cap (`renderer.rs:18-27`). A forward-built append list would need per-reference links or per-tile tail state and makes shader traversal less contiguous. Neither is an unconditional work reduction for mixed text/image scenes.

The CPU's retained Canvas already owns exact commands, order, resources, and compact groups, while GPU `RendererState` accepts a borrowed `PreparedScene` whose public header can be changed; each new full render intentionally discards redraw eligibility before admission (`crates/canvas/src/canvas.rs:845-939`; GPU `renderer.rs:665-690`). Thus reusing old bins for arbitrary new input requires a trustworthy scene/version certificate and invalidation rules for size, clear, color mode, geometry, image leases, and failed preparation. The existing same-token `redraw` and slot-patch ownership are such certificates for their narrow cases; do not infer general identity from the borrowed `PreparedScene` pointer or scene shape.

## Suggested gates

1. Prototype only Candidate B first: compare counters against the present equations in focused tests, without changing rendering semantics.
2. Evaluate Candidate A only with exact buffer-byte accounting on transform-only, geometry-only, slot-patch, mixed text/image, and resource-relocation frames. Keep it only if CPU pass deletion is demonstrated without materially inflating common update bytes or complicating the observer/address contract.
3. Preserve explicit packet revocation before any mutation or queue write and success-only packet restoration; existing paint/slot commit guards revoke before writes (`renderer/paint.rs:345-372`, `renderer/slots.rs:155-173`).
