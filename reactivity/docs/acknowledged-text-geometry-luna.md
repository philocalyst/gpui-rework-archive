# Acknowledged text geometry: ownership and implementation plan

Research is read-only against `/root/gpui-ce3/reactivity`. I did not edit production, build, benchmark, or launch agents. This note distinguishes current behavior from the proposal below; none of the cost estimates are measurements or performance claims.

## Recommendation

Keep one canonical, immutable geometry payload derived by Canvas shaping, attach it to the exact candidate and acknowledged presentation, and expose it through the existing borrowed `Part`/semantic query surface. Have both public queries and the AccessKit projector read that same payload. Do not let a geometry query resolve through the current mutable `TextSite` cache.

For the smallest correct slice, I recommend a refinement of formulation 1: split the immutable run/line/caret details from the paint-only glyph/font data, and share that details allocation with a private `Arc` lease. `TextLayout` methods and a new borrowed `Part::text_geometry()` view would call the same Canvas geometry routines over those details. P and C sidecars would retain only the immutable geometry lease plus the text origin. This keeps old P geometry while allowing old glyph buffers and font leases to drop when L changes. It retains one atomic lease per C/P text entry and one shared-details allocation per geometry-bearing layout; it avoids copying a full `TextLayout` into P.

If changing Canvas’s internal details ownership is too large for the first correctness slice, use `Arc<TextLayout>` in the same sparse P/C sidecars as the conservative implementation. Treat the layout as immutable and replace it on reshape; do not call `Arc::make_mut` in frame preparation. The existing `discard_interaction` mutation must be removed from the GPUI lifecycle or isolated behind an explicit deep copy. Full-layout Arc retention is safe and simple, but it keeps glyph vectors and font leases alive for old P/C even though P geometry does not need them.

A slot arena is a credible later replacement if measurements justify removing Arc allocation and atomic traffic. It is more complex and may cost more in a low-text or one-live-presentation case. Native prepared arrays alone cannot satisfy the public query and late-activation contract unless GPUI also retains those arrays in P; that retained common geometry then becomes another form of the canonical geometry sidecar.

The minimum ownership boundary is:

```text
L TextSite cache ─┐
                  ├─ immutable geometry payload
C Prepared sidecar┤
P presented sidecar┘
```

Keep the P/C geometry columns aligned to their own `Presented` node order, with sparse entries only for text-bearing rows. Store the paragraph origin `(padding.left, padding.top)` in each entry: the P `Presented` record retains bounds and an absolute node-local-to-window-physical transform, but it does not retain text padding. A `Part` must borrow the geometry through its acknowledged row index and the same `Context` as its text, transform, selection, and bounds. The public API and AccessKit projection then read exactly the same P lease. No per-`Node` or per-`Presented` field is needed.

## What is implemented now

- [STATUS.md](/root/gpui-ce3/reactivity/STATUS.md) records `TextLayout = 56 B`, `TextSite = 80 B`, `Presented = 80 B`, and `Node = 40 B` on the measured 64-bit build. It lists acknowledged text geometry as missing.
- [`runtime.rs`](/root/gpui-ce3/reactivity/crates/gpui/src/runtime.rs:308) stores `Shaped { width, layout: TextLayout }` inline in the mutable dense `TextSite` lane ([TextSite](/root/gpui-ce3/reactivity/crates/gpui/src/runtime.rs:463), [shape cache](/root/gpui-ce3/reactivity/crates/gpui/src/runtime.rs:593)). `shape_for` replaces this one current layout on width/interaction changes.
- [`Presented`](/root/gpui-ce3/reactivity/crates/gpui/src/runtime.rs:693) retains identity, text lease, local rect, transform, clipped bounds, action bits, and role. It has no text layout, caret map, paragraph origin, or text-run geometry. `Prepared` ([definition](/root/gpui-ce3/reactivity/crates/gpui/src/runtime.rs:704)) has the candidate node vector and damage only.
- `present_inner` shapes text while laying out/painting, then installs `Prepared`, metadata candidate, selection candidate, and other candidate columns only after fallible preparation finishes ([preparation](/root/gpui-ce3/reactivity/crates/gpui/src/runtime.rs:2409), [commit](/root/gpui-ce3/reactivity/crates/gpui/src/runtime.rs:2985)). On ACK, it takes that exact `Prepared`, moves its node rows to P, and separately advances metadata and selection ([ACK](/root/gpui-ce3/reactivity/crates/gpui/src/runtime.rs:2349)). This is the right lifecycle boundary for a geometry column: publish it only with the same `Prepared` that owns the rows.
- `TextSite` can be overwritten by a successful shape during a preparation that later fails. The prior P and prior eligible C survive. The ACK path can then accept that older C. A P query therefore cannot infer geometry from the current `TextSite` by identity or equal string value.
- [`Part` and `Context`](/root/gpui-ce3/reactivity/crates/gpui/src/runtime/query.rs:12) already provide a borrowed, allocation-free semantic/testing surface over P. `Part` exposes the acknowledged string, selection, transforms, bounds, and unclipped bounds; it deliberately has no layout. [`Editing`](/root/gpui-ce3/reactivity/crates/gpui/src/runtime/editing.rs:22) separately freezes logical, candidate, and presented selection. Reuse this surface for geometry instead of adding an AT-only query engine.
- Canvas already owns the hard geometry algorithms. [`TextLayout`]( /root/gpui-ce3/reactivity/crates/canvas/src/text/layout.rs:68) stores shaped glyphs, fonts, visual runs/lines, and optional grapheme caret stops. Its public `runs`, `lines`, and `caret_bounds` are in [layout.rs](/root/gpui-ce3/reactivity/crates/canvas/src/text/layout.rs:150); `position_at` and `selection_rects` borrow the same map in [interaction.rs](/root/gpui-ce3/reactivity/crates/canvas/src/text/layout/interaction.rs:126). They already handle bidi, soft wraps, hard breaks, empty paragraphs, affinity, and grapheme-safe byte offsets. A second algorithm in `native/accessibility` would duplicate the most delicate part.
- Interactive maps are currently opt-in. Only the selected input requests `shape_interactive`; selection retirement calls `discard_interaction`. `TextSelection` uses UTF-8 byte offsets at ICU grapheme boundaries. Canvas `Glyph.cluster` and glyph-source ranges are not selectable units: multiple glyphs can belong to a shaped cluster, and one selectable grapheme can span multiple scalars/bytes. The map is the source for character geometry; glyph indices are not.
- [`native/accessibility/text.rs`](/root/gpui-ce3/reactivity/crates/gpui/src/native/accessibility/text.rs:372) currently creates one AccessKit `TextRun` per hard line. `text_run` fills grapheme byte lengths, but sets no text direction, character positions, or character widths ([construction](/root/gpui-ce3/reactivity/crates/gpui/src/native/accessibility/text.rs:378)). `Cohort` maps native offsets by hard-line ID and grapheme index ([position mapping](/root/gpui-ce3/reactivity/crates/gpui/src/native/accessibility/text.rs:331)). Wrapped visual lines and directional subruns cannot be represented by that current partition.
- [native-text-selection evidence](/root/gpui-ce3/reactivity/evidence/native-text-selection/README.md) correctly documents older P/C text and selection surviving failed newer preparation, and says wrapped TextRuns, character geometry, magnifier/caret rectangles, and geometric hit testing remain. It proposes shared immutable/COW `TextLayout` as a seam, but does not price or validate the geometry-only arena and native-preparation alternatives here.
- The older [accessibility text follow-up](/root/gpui-ce3/reactivity/docs/accessibility-text-virtualization-luna.md) has useful Chromium and Qt comparisons, but its statement that the editor uses scalar selectable units is stale. Current integrated editing/native code uses grapheme boundaries and the private AccessKit extension represents one selectable unit per grapheme, including CRLF and long clusters. Use the current `TEXT_SELECTION.md`, native-text-selection evidence, and source as the contract.

## The canonical public surface and platform contract

Expose a borrowed `Part::text_geometry()` (or equivalent) in `visit`, `query`, and `semantics`, sourced from P. It should provide the same canonical content-coordinate operations already implemented by Canvas, plus a placement view that knows P’s text origin and transform:

- visual runs with source byte range, line index, and direction;
- line ranges, local bounds, baseline, and height;
- grapheme character advance/extent, caret bounds with upstream/downstream affinity, and range rectangles;
- hit-to-text position in content-local coordinates and a P placement helper that first maps window physical points through the inverse P transform and subtracts the retained text origin.

Keep units explicit in names and docs: a `TextOffset` is UTF-8 bytes; a caret position is a legal extended-grapheme boundary; glyph clusters and glyph indices are shaping output; AccessKit `character_index` is a selectable-unit index; Apple uses UTF-16 `NSRange`; AT-SPI reports Unicode scalar/USV offsets through the current AccessKit conversion. Do not pass any of these integers across layers without converting them.

Primary API contracts confirm why the content geometry needs lines and directions. AccessKit’s [`character_positions` and `character_widths`](https://github.com/AccessKit/accesskit/blob/ce8164ba92995cfa86005b6259115e08c8244253/accesskit/src/lib.rs#L2374-L2444) are one-dimensional positions/advances relative to a text-run bounds and direction, with one entry per selectable unit. The AccessKit Consumer derives hit positions and range boxes from these arrays ([pinned consumer source](https://github.com/AccessKit/accesskit/blob/ce8164ba92995cfa86005b6259115e08c8244253/consumer/src/text.rs#L730-L995)). Its Windows provider routes `RangeFromPoint` and `GetBoundingRectangles` through that Consumer geometry ([provider source](https://github.com/AccessKit/accesskit/blob/ce8164ba92995cfa86005b6259115e08c8244253/adapters/windows/src/node.rs#L1432-L1475), [range source](https://github.com/AccessKit/accesskit/blob/ce8164ba92995cfa86005b6259115e08c8244253/adapters/windows/src/text.rs#L494-L520)). UIA asks for one rectangle per visible or partially visible text line, and its point query returns the nearest degenerate text range ([GetBoundingRectangles](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomationtextrange-getboundingrectangles), [RangeFromPoint](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomationtextpattern-rangefrompoint)).

Apple requires `accessibilityFrameForRange:` and `accessibilityRangeForPosition:`; `NSRange` is UTF-16 and the current AccessKit macOS adapter converts through the consumer’s UTF-16 conversion helpers ([Apple protocol](https://developer.apple.com/documentation/appkit/nsaccessibilityprotocol?language=objc), [position method](https://developer.apple.com/documentation/appkit/nsaccessibilityprotocol/accessibilityrange%28for%3A%29-1iudm?language=objc), [pinned adapter conversion](https://github.com/AccessKit/accesskit/blob/ce8164ba92995cfa86005b6259115e08c8244253/adapters/macos/src/util.rs#L12-L50)). AT-SPI defines text character extents, range extents, and offset-at-point ([Text interface](https://gnome.pages.gitlab.gnome.org/gtk/atspi2/iface.Text.html), [character extents](https://gnome.pages.gitlab.gnome.org/gtk/atspi2/method.Text.get_character_extents.html)); the checked-in AccessKit Unix bridge returns USV/scalar positions after translating AccessKit selectable units ([local conversion](/root/gpui-ce3/reactivity/vendor/accesskit_atspi_common/src/node.rs:1543)). These APIs specify distinct coordinate and offset contracts; AccessKit Consumer tests alone do not prove VoiceOver/UIA/Orca geometry.

Chromium’s primary architecture documentation uses internal inline text boxes split by single line, direction, and contiguous text, then stores each box’s bounds plus per-character widths to recover range/caret geometry without one full rectangle per character ([pinned Chromium overview](https://chromium.googlesource.com/chromium/src/%2Bshow/3376a4f83a973d9804e861d79cf43ae93e35feec/docs/accessibility/overview.md)). That is the right native lowering shape for GPUI: emit one TextRun per wrapped visual line and direction-compatible contiguous source range. Line breaks must remain atomic; a hard break’s position/width must match the canonical selection-marker policy. Confirm every split is on a legal grapheme boundary. If shaping produces a directional boundary inside a grapheme, coalesce or otherwise define the grapheme’s single accessible geometry rather than splitting its selectable unit.

The current AccessKit tree is already a separately retained native structure. Its character-length vectors are present today; geometry adds position and width arrays for every selectable unit. Charge those approximately `N` bytes plus `4N + 4N` bytes per run, with overflow payloads and each run/property/vector’s headers and capacity. The Consumer/adapter tree and GPUI P geometry are separate owners. Do not call the adapter arrays free because they were copied from GPUI.

## Ownership formulations and costs

| Formulation | What P/C retain | Main retained/alloc cost | Correctness and likely losing case |
| --- | --- | --- | --- |
| Full `Arc<TextLayout>` / COW | An Arc lease per text row in C/P sidecars; `TextSite` retains its current Arc. | One Arc allocation per newly shaped layout version (in addition to glyph/detail payloads); atomic inc/dec when C/P columns clone/drop. `TextSite` replaces its 56-byte inline layout with a pointer and width, saving roughly 48 bytes at the site, but P/C need sparse `(row index, Arc, origin)` entries: about 24 bytes per text row per epoch on 64-bit, plus one Vec header per C and P and capacity slack. Old P/C Arcs retain the full glyph Vec and font-set lease. | Simplest correctness story and matches the existing native-text note. COW must not mutate in place: `Arc::make_mut` can deep-clone glyphs, runs, lines, and stops. Loses when old frames are common, layouts are large, or many text sites create maps; it is not a measured CPU win. |
| Owner-local dense layout arena | L/C/P store private `u32` slot refs; C/P sidecars add row index + slot + origin (about 16 bytes per text row per epoch). Arena owns each TextLayout once and a private L/C/P use mask. | Runtime arena header (24 bytes if a `Vec`), one directory/use record per high-water slot, dense TextLayout storage with spare capacity, P/C sidecar Vecs, and remap scratch/work if compacted. Replacing inline layout may save 48 bytes in `TextSite`; actual TextLayout bytes move to arena. No outer Arc allocation or atomic reference-count traffic. | Best when multiple epochs share stable slots and history pressure matters. Must account for slot directory, high-water holes/fragmentation, arena Vec slack, P/C indexes, first empty/first text arena allocations, compaction remapping, and every owner transition. A stable `u32` is valid only as a private index into this one Runtime; it cannot be stored in a Target/native ID or escape the borrowed Part. A plain dense index needs compaction to visit/remap every TextSite/P/C reference; a stable slot table avoids that traversal but costs directory/free-list space. Likely loses for small trees, one P/C lifetime, low text density, or if use-count and compaction machinery exceeds saved Arc cost. |
| Prepare-time native geometry | Candidate/P retain an immutable geometry projection, not a GPUI TextLayout clone; ACK moves C geometry to P with Prepared. | A geometry sidecar must still exist in P for public queries and late activation. Native output adds retained `character_positions` and `character_widths` arrays to AccessKit’s existing text lengths/tree; count both. Rebuilding arrays for every C is O(N) work/allocation unless the geometry backing is shared/reused. | A temporary-only candidate array is incomplete: late AT activation after failed L/C has only old P, and public headless Part cannot read it. If the compact sidecar is the shared canonical API for both Part and AccessKit, it is viable and may drop P’s glyph/font payload; it is then a geometry-owner design (Arc/arena or immutable column), not a native-only shortcut. |

The sidecar arithmetic above is representation-level accounting, not a full layout ledger. For the Arc route, the C/P entry needs its own P-row index because the geometry cannot be placed in every `Presented`; it also needs the local text origin. For the arena route, those same fields are row index and slot ID. Count the `Prepared` and P column headers, P/C vector capacities and allocator size classes, as well as `Arc` headers or arena directories. Current `TextLayout` `Details` already owns line/run/stop vectors, and existing native lengths already own arrays; compare actual requested bytes and peak live bytes rather than just `size_of`.

Completeness changes the baseline materially. Every text layout exposed by `Part::text_geometry()` must be shaped with the interactive map before its P is prepared, even while the native provider is inactive. A late provider must be able to enumerate geometry from the old P that survived a failed newer shape; it cannot wait for a newer frame without withdrawing geometry. `Stop` is 24 bytes by its current `u32 + Rect + affinity` layout, usually near one stop per grapheme boundary and sometimes two at bidi/wrap aliases. At the 32 KiB ASCII text limit that is roughly 32,769 × 24 bytes (~786 KiB) in stop payload before vector slack. For >8 graphemes, the vendored Parley `CursorGeometry` used during stop generation has transient capacity of 16 bytes per source scalar entry plus four bytes per source byte; a 32 KiB ASCII example is roughly 640 KiB of temporary index storage before shaping scratch/glyphs. The local source documents that exact index shape in [`vendor/parley/src/editing/geometry.rs`](/root/gpui-ce3/reactivity/vendor/parley/src/editing/geometry.rs). These are bound-derived payload estimates, not allocator/RSS measurements. Stop/map costs and AccessKit arrays must be included in every formulation; they dominate small Arc/slot headers for long paragraphs.

A compact immutable geometry data type can reduce P retention without inventing another engine: move `TextLayout`’s `Details` behind `Arc`, make the run/line/caret routines operate on that same data, and let P/C hold that Arc plus origin. `TextLayout` keeps its glyphs/fonts only in L; when a new layout replaces L, old P/C retain the exact map but not the old glyph buffers. A borrowed `Part::text_geometry()` view uses those same Canvas routines. This is my preferred first Sol slice because it preserves one geometry algorithm, does not grow Node/Presented, follows existing P/C ACK rules, and lets us compare actual payloads before adopting a slot table. It still pays the stop map, C/P sidecar vectors, Arc atomics, and AccessKit arrays. If full glyph-run queries must be exposed from P, this compact split is insufficient and full `Arc<TextLayout>` retention must be costed instead.

## Epoch and lifecycle invariants

| Event | Required geometry result |
| --- | --- |
| Paint-only same-S update | C reuses the exact L/P geometry lease and origin where shape/placement is unchanged. Replacing C releases the old C lease only after the new prepared candidate is complete. |
| Selection-only publication | P selection advances with the candidate, while the geometry lease remains the same. Geometry is always interactive, so selection changes do not reshape or discard stops. |
| Failed shape/layout/scene prepare | P and the previously eligible C columns remain unchanged. L may hold a newer shaped layout; no P query or native projection reads it. An unsuccessful pass does not register a replacement C column. |
| ACK of older C after newer failure | Move that C’s geometry column to P with that C’s node vector, text leases, size/scale, selection, and semantic sheet. Do not combine it with L geometry or the later failed style/padding. |
| Resize/DPI/font/width change | New candidate captures the exact new TextLayout map, content origin, absolute transform, and physical size. Old P’s map/origin/transform stay valid until ACK. A layout width is logical; the P transform carries the scale factor to window physical space. |
| Virtual rows and row reuse | Index C/P geometry by that sheet’s published row position, not the current logical node index. Only text rows actually present in P get entries. A row leaving P loses its P use only at ACK; a new visible row gets its own current geometry. |
| Transform, clip, hit | Apply P text origin and P’s absolute node-local-to-window-physical transform once. Keep full text geometry separate from clipped element hit bounds. The Part query must document full versus visible extents; hit-to-text must follow the exact clip/hit policy. Do not read current viewport offsets for old P. |
| Source/identity rebind | P’s string and geometry remain tied to the old immutable text lease and node identity. The existing native action source-authority check may withdraw actions while still allowing old P geometry. Equal bytes do not authorize using current input field/layout data. |
| Provider activation/deactivation/reactivation | Initial full tree is lowered from the currently acknowledged P geometry, including when P is older than a failed L/C. Deactivation drops adapter cohort/native tree ownership only; P geometry remains. Reactivation is a full P projection. Linux’s existing inactive worker/startup cost is separate from geometry materialization. |
| Cancel, drop, repair | Release C/P/L geometry leases in the same lifecycle as their owners. Reuse arena slots only after every L/C/P bit retires. On drop, all slots die with their Runtime; a numeric slot is never a cross-window handle. Repair creates a coherent new C and transfers it only at ACK. |

For an arena implementation, use mutually exclusive owner-level use bits (L, C, P) on private slots; one bit per category is sufficient only because the runtime admits one L, one C, and one P ownership set. C replacement clears the old C bit after the new column is complete. ACK drops old P ownership and transfers C to P without an externally visible gap. Failed prepare never updates either mask. Slot reuse is allowed only at mask zero. A `Part` borrow prevents mutable arena compaction/reuse for the duration of a geometry query; do not return slot IDs from public methods. Add assertions that all sidecar slots are live and match their P text/site. Do not use `Rc`, `RefCell`, `Cell`, raw pointers into L, or generation-less IDs outside this owner proof.

For the recommended Arc-details version, the Arc itself handles reclamation: TextSite, C, and P each retain a strong reference, and candidate replacement/ACK/drop release the right reference. The same source/identity/placement rules still apply. Make details immutable after shape; if `Arc::make_mut` is used for an API-compatible `discard_interaction`, measure its deep clone. Rust’s standard docs describe Arc clone/drop ownership, atomic reference counting, and the deep clone behavior of `make_mut` ([Arc](https://doc.rust-lang.org/std/sync/struct.Arc.html)).

## AccessKit projection and ID blockers

The current `Cohort` counts hard-line `runs(value)` and assigns one monotonically allocated ID range per input/text source. It has no geometry version. Wrapped directional lowering changes both child count and byte-range partition when font, width, scale, or source changes. The native delta observer currently compares `Presented` rows and semantic metadata, not a text geometry lease, so a text geometry-only change with same node bounds/value must be visible to the observer.

The projector needs these changes with the geometry feature:

1. Count the same canonical P geometry runs in its preflight and output pass. Emit a TextRun per wrapped visual line and direction-compatible contiguous source range, with source bytes and per-grapheme positions/widths. Set each run’s local bounds/direction; child order and range mapping must follow AccessKit’s text ordering while geometry follows visual lines.
2. Add the geometry partition/version to the source-qualified native cohort. When a layout changes the number or boundaries of text runs, reserve a fresh monotonic run-ID range and retire the old range. Reusing run ID N for a different source-byte partition lets a stale `TextPosition` name a different grapheme. Map each run ID plus its selectable-unit index back through the exact P run range.
3. Make `Observer::compare` notice the geometry column even if `Presented` node fields, string lease, and selection do not change. A geometry delta emits the input and any affected parent child list, and its native update is built from that candidate/P geometry only.
4. Keep selection-only update behavior separate from immutable character arrays when text geometry does not change. The input node’s TextSelection can update without rebuilding TextRun values, lengths, positions, or widths.

These are source changes beyond adding `Part::caret_bounds`: `Cohort::text_count`, `Cohort::append`, `replacement`, `update_delta`, and the observer’s same-row comparison all assume the existing hard-line-only TextRuns. A resize can require new native IDs even with unchanged text; ID monotonicity already avoids retaining retired history, but report that ID churn and test provider staleness.

Native projection must also preserve full transformed text coordinates and line visibility. Current `Presented` stores clipped and unclipped element bounds separately through derivation; it does not retain the original clip chain in every P row. The current native nodes use full unclipped bounds and rely on clip-bearing ancestors for lists/scrolls. UIA specifies visible-line rectangles; AT-SPI only promises meaningful character extents for visible/showing text. Confirm how per-run rectangles intersect viewport/list clipping on each real provider. Do not substitute clipped element AABBs for exact hit clips under shear/reflection.

## Smallest Sol slice and evidence gates

1. Canvas: factor the existing private `Details`/interval routines into an immutable geometry backing retained for every text-bearing site. Add a borrowed/opaque geometry view and a character-advance/extent accessor derived from grapheme interval stops. Always shape that map before C preparation. Do not implement a second native hit/selection algorithm.
2. GPUI: add sparse `Prepared` and P geometry columns keyed by presented row index, each with the exact text origin. Route `Part::text_geometry()` through those columns; make the P geometry query available in the same `visit/query/semantics` path. Candidate geometry advances only with `Prepared` on exact ACK. Leave Node and Presented strides unchanged.
3. Native: lower the same `Part` view into AccessKit line/direction TextRuns and per-grapheme positions/widths; make cohort IDs and sparse observer deltas geometry-version aware. Keep selection action admission separate from geometry availability.
4. If full `Arc<TextLayout>` is used for step 1, measure P/C old-layout retention and include glyph/font bytes. If the old-epoch glyph retention is material, switch the shared backing to geometry-only details before considering a full slot arena. Adopt an arena only after its exact directory, sidecar, capacity, and compaction costs beat the Arc-details form on both sparse-text and dense-text cases.

Adversarial public fixtures: narrow wrapped Latin with leading/trailing spaces; mixed LTR/RTL Arabic/Hebrew and isolates; `ffi` ligatures; decomposed marks; emoji ZWJ and a >255-byte grapheme; CRLF, blank lines, and trailing newline; empty string; hard-break marker width; selection direction reversal; collapsed carets with both affinities at wrap/bidi joins; transformed padded text under fractional DPI, shear/reflection and viewport clips; window-point hit mapping and outside-point policy. Compare every legal grapheme boundary and every visual run against Canvas’s canonical `TextLayout` routines and an independent position/range oracle. Check text origin separately from node origin.

Adversarial epoch fixtures: P0/C1, then S2 changes source, width, font or padding and fails after `TextSite` reshapes; query exact P0 geometry and activate the provider; ACK old C1 and verify C1 geometry/text/selection match; repair and ACK C2; repeat with selection-only change, same-S paint-only change, failed resize/DPI, equal-byte source rebind, identity rebind, virtual row leaving/reentering, and cancellation/drop. Assert failed candidate geometry never reaches P, no current L data is consulted by P query, and old native run IDs fail after their partition is retired.

Adversarial native fixtures: compare AccessKit Consumer range boxes, character hit, and TextPosition round trips to public `Part` geometry for each wrapped directional run; real AT-SPI `GetCharacterExtents`/`GetOffsetAtPoint` with USV offsets; Windows UIA `RangeFromPoint`/`GetBoundingRectangles`; macOS range frame/point methods with UTF-16 selection boundaries. Keep Xvfb/AT-SPI results labeled as Linux runtime evidence; Apple/Windows cross compilation does not prove VoiceOver/UIA behavior. Verify that P geometry remains available through late activation but action capabilities remain withheld when the current source lease is invalid.

Exact gates: `size_of`/alignment for Node, Presented, TextSite, Runtime, Prepared, geometry-ref record, arena slot/directory and AccessKit Node/PropertyValue; vector `len/capacity` bytes for each owner; requested allocation count/bytes for first simple label, one wrapped paragraph, selected input, C creation/replacement, P ACK and old P/C overlap; peak live bytes and drop timing for L/C/P versions; per-grapheme canonical stop/map bytes and transient CursorGeometry/shaper scratch; native characters arrays and TextRun allocations; exact candidate-to-ACK slot/Arc ownership events; zero per ordinary node or inactive AT geometry adapter allocation; unchanged selection-only geometry payload; no source read from L during P query. Bench both a 100k-node tree with sparse text and text-dense paragraphs. No speed or memory winner should be claimed until these are captured with a matched allocator/build.

Relevant design literature is directionally useful, not a substitute for those gates. Chromium’s inline-box representation supplies a tested GUI example of one-line/single-direction runs plus widths rather than full per-character rectangles. Parley 0.12 exposes cursor-from-point, cursor geometry, and selection geometry directly on its canonical layout ([Cursor](https://docs.rs/parley/0.12.0/parley/editing/struct.Cursor.html), [Selection](https://docs.rs/parley/0.12.0/parley/editing/struct.Selection.html)); GPUI’s vendored `CursorGeometry` is a scoped temporary bulk index with explicit bytes/scalar and bytes/source storage, not a retained P cache. Hixie’s *Building a UI Framework* discusses page-oriented arenas as a memory/lookup tradeoff at tree scope ([design paper](https://software.hixie.ch/ui-frameworks.pdf)); it supports accounting directory/traversal costs, not a claim that this text-layout arena wins. The DBSP incremental-view-maintenance paper is relevant only to separating changed outputs from unchanged outputs; it does not establish UI layout or provider lifetimes ([PVLDB paper](https://www.vldb.org/pvldb/vol16/p1601-budiu.pdf)).

## Appendix: validate decoded lengths once without changing Node

The private `DecodedCharacterLengths::new` in [`vendor/accesskit/src/text_lengths.rs`](/root/gpui-ce3/reactivity/vendor/accesskit/src/text_lengths.rs) scans the complete raw unit vector on every `Node::decoded_character_lengths()` call. It checks overflow structure/canonical escapes, checked cumulative lengths, UTF-8 boundaries, exact value-byte coverage, and full overflow consumption. The iterator then decodes again as callers walk it. Consumer filters and position/range conversion can request this multiple times for one unchanged TextRun. Current evidence explicitly defers normalization-once.

Do not add a proof bit or `OnceCell` to every AccessKit `Node`: it grows the ordinary-node header and derived Eq/Clone/serde semantics become tricky. Do not serialize a “validated” marker; malformed snapshots could forge it. The safe sparse design is a private text-run sidecar in the immutable `accesskit_consumer::TreeState`, populated when a TextRun Node enters the tree. Validate the actual value/length/overflow arrays then and construct an unforgeable private `ValidatedTextRun` containing cumulative `u32` UTF-8 byte ends (`N+1` words). Consumer conversions borrow that sidecar. This is about `4*(N+1)` payload bytes plus one sparse text-run entry/header/capacity; the public Node and ordinary-node headers remain unchanged. A marker-only variant can save the validation scan but leaves later unit-to-byte iteration O(N); byte ends enable binary-search/range conversion but cost the extra array. Measure both before choosing.

Rebuild or remove the sidecar whenever a TreeUpdate replaces a node’s value, raw CharacterLengths, extended overflow payload, or TextRun role; invalidate by every changed NodeId, even when ID and text length remain equal. Reusing the witness merely because the NodeId is stable is invalid. Tree deletion/reparent/role change removes its witness. The proof type constructor stays private and absent from serde; every deserialized/malformed Node must pass the same full validator before a witness is created. Keep `Node`’s own Eq, Clone, and serde representation unchanged; clone the Consumer’s sparse sidecar together with its tree. Public `Node::decoded_character_lengths()` can remain the defensive validating API for non-Consumer callers, while Consumer queries use only the private validated view. This appendix is independent of the geometry ownership choice and should not delay correct P/C geometry.

## Root review and implementation disposition, 2026-10-22

This report is research against its stated source. The concrete Sol proposal is
pinned to integrated source `6d77c71c1227bd2609518cc5f3a49e37fc176f82`.
Canonical immutable geometry with shared Details is approved as the first
correctness control; it is not yet integrated or a measured memory winner.
The full-layout arena remains an alternative, not a second shipping subsystem.

Four ownership categories are required for an arena: **L/T/C/P**. A fallible
replacement T coexists with the previously eligible C. Failure clears only T;
success replaces C after T is complete. The three-category shorthand above is
insufficient for this runtime. Native refresh may miss several ACKs, so reusable
slot indices also require a checked serial to prevent cohort ABA. Never count a
bare slot index as a native geometry version.

Canvas nearest-caret and AccessKit containing-unit point queries have different
policies. Expose both from the common geometry rather than silently treating
midpoint snapping as containing-character hit testing. Current native parents
have physical AABB bounds with identity transforms: child run geometry must use
the exact P local-to-physical affine and text-origin translation, including shear
and reflection, without applying DPI twice. Full and clipped bounds remain
separate contracts.

Measure stop-map and scoped CursorGeometry costs before selecting handles. The
current 24-byte stop payload may dominate every Arc-versus-slot difference.
Always-interactive completeness is not a free baseline: record no-text, short
labels, wrapped paragraphs, 32 KiB ASCII, long graphemes, failed replacement and
old P/C overlap separately. An analytic or compressed canonical map must retain
exact affinity, bidi, wrap and grapheme behavior before it can replace the
control. The native-only temporary projection cannot satisfy late activation.
