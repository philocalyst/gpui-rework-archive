# Adversarial review of the clean-room design

Reviewed DESIGN.md, GRAPHICS.md, concurrency-research.md, the governing final/00-model.md, and the statutes cited below on 2026-10-20. The clean-room documents are materially more candid than the earlier model: they separate experiments from a proposed integration and name important fallbacks. The main problem is now contract divergence. Several choices in the proposed runtime are not implementation details: they alter publication atomicity, changed, frame construction, rollback, and therefore the model's laws. Those changes need a versioned amendment to final/, not only a paragraph in the clean-room design.

Severity means: **Blocker** = cannot implement or prove the advertised contract as written; **High** = likely observable correctness or asymptotic failure without a specified resolution; **Medium** = required before claiming the behavior or budget; **Low** = documentation/maintenance defect.

## Blocker — the current and proposed atomicity contracts conflict

DESIGN.md lines 215–253 says a normal arbitrary owner invocation commits its source mutation; downstream derivation/cycle/equality/budget problems become typed Fault outcomes at that source epoch. It further keeps an old presentation sheet while logical state advances (lines 228–242). final/08-runtime.md lines 58–68 says the opposite for a logical settle fault: the sparse LogicalDraft is dropped and source revisions, structure, ports, and event ownership remain unchanged. Its presentation-fault behavior already preserves the old sheet after logical commit. Thus the design combines two distinct transaction cuts and changes which one commits on a derived failure.

This is not a wholly new departure from the constitution's paragraph: 00-model §2 says effects are in changed, while 08-runtime.md lines 44–48 explicitly rejects general rollback for an arbitrary mutable handler. The precise amendment is instead the proposed **source-commit-before-derive** rule replacing the existing *atomic logical publication* rule. That distinction matters: the existing model permits handler mutation to be non-rollbackable on panic, while still requiring a derived-settle fault to discard its not-yet-published source draft. Calling both rules “no rollback” obscures the contract.

**Required correction:** choose one of these as the authoritative contract and amend 00-model, 01-state, 04-reactions, 05-async, 08-runtime, and the replay/history laws together. If adopting source-commit-before-derive, state that input mutations, accepted completions, entity lifecycle, effects, and Handoff consumption each have an exact commit point; define which faults leave those commits intact and how recovery is represented. If retaining atomic logical publication, arbitrary &mut Self work must run against a transactional source representation or explicitly be outside that transaction (and not be described as the failing logical draft). A typed Fault alone cannot reverse arbitrary mutations.

There is a second direct conflict: DESIGN.md lines 262–274 replaces the inverse layout journal with a private mutable Cephal workspace whose touched caches are invalidated/discarded after failure. final/08-runtime.md lines 70–76 makes the inverse-operation journal the specified rollback mechanism, with dirty-subtree fallback. The replacement may be simpler, but it is an amendment and needs a proof that cache invalidation restores the workspace's future answers and side-effect/resource invariants. A poisoned adapter is not equivalent to a recoverable transaction.

## Blocker — frame construction still has no implementable Rust path

The governing contract is a generative frame borrow: 00-model.md lines 179–186 requires a universally quantified scope that prevents El<'f> escaping its frame. DESIGN.md lines 49–52 says borrowed descriptions and scratch are temporary; lines 143–147 require a “typed owner-relative projector” or stable source capability. But the advertised View::view(&self) -> El<'_> in the constitution has no frame/carrier argument. Ordinary safe Rust cannot make that method allocate into an independently owned per-call bump arena while retaining references to the arena in its return value. An associated lifetime on El does not produce a frame token, and covariance does not create a generative brand.

The companion PLAN.md already recognizes this problem (“view(&self) has no frame argument”), but DESIGN.md gives no final resolution. The candidates each change a public promise: (a) change to fn view<'f>(&'f self, frame: &'f mut Frame<'f>) -> El<'f> or a scope closure that generatively brands the frame; (b) use owned/inline-spill description values and retract the claim that every element is borrowed from a per-turn arena; or (c) use a compiler/runtime transformation with an explicit safe interface and prove it. Merely saying the method “lowers” to a capability is not a Rust signature.

**Required correction:** add one compilable minimal API (including View, a branching builder, nested children, El<'f>, Frame, and a compile-fail escape test) before selecting the memory estimates that depend on it. Keep the actual ordinary DerefMut signature in view: it must return &mut T, not a custom drop guard. If revision increments happen before the borrow, specify checked overflow/rebase semantics, panic behavior, and whether merely obtaining &mut T counts as publication. The design's eight-byte local Signal<u32/bool> result is only a datum; it does not include a destination/source index or retained old value.

## High — source publication does not yet preserve the old delta/Handoff laws

DESIGN.md lines 161 and 243–248 explicitly changes delta discovery to O(wired fields in changed owners) for ordinary fn(&mut Self) handlers, with exact recursive old/new only when operations capture or persist values. The statutes instead promise lazy log assembly O(publications this turn), never O(fields) (01-state.md lines 235–240), and changed runs at most once per turn with the composed typed publication log (04-reactions.md lines 145–159). This also weakens 00-model.md L13 (macro changes invocation counters only) and L14 (mechanisms strictly replace equivalent costs). It is acceptable to choose the owner-scan fallback, but record the amended laws and define precisely when field revisions are sampled and how nested Entity/plain-field deltas recurse.

The proposed commit point has a particularly sharp Handoff counterexample. Handoff is a durable occurrence source; give/crash/restore must retain an untaken payload, gives are FIFO unless declared latest-wins, and the take is the acknowledgement (01-state.md lines 151–185). If a handler gives a Handoff and then panics, the owner is poisoned/dropped (DESIGN.md lines 221–226). Is the give committed to the durable occurrence journal before panic, or lost with the owner? If retained, does it route to a parent whose source owner was removed? If not retained, the durability contract has an exception. Staging every give until normal return preserves that one guarantee but still does not make prior arbitrary field mutation atomic. Specify the Handoff journal/ack boundary and failure matrix.

Likewise, “one owner invocation commits” (line 221) leaves “turn” underdefined. changed is at most once per turn and queued deliveries are FIFO; effects of event N settle before event N+1 (04-reactions.md lines 145–159; 08-runtime.md lines 50–54). Define whether event handler, all changed rounds, worker admissions, and resulting effects share one source epoch or several; how repeated writes coalesce; when observers see old/new; and whether a loop/budget fault stops later queued commands. Without this, event order and user-visible effect order cannot be proven.

## High — two epochs need an interaction policy, not only a sheet pointer

The design's split between current logical state and old presentation is a useful failure-containment approach (DESIGN.md lines 228–242), but it introduces a real “semantic now / pixels later” state. It says key/focus follow current logical state and coordinate input waits, but does not define pointer capture, drag continuation, wheel/scroll targeting, hover, IME caret/selection geometry, accessibility bounds/actions, semantic-tree announcements, or test query consistency during a prolonged presentation fault. Some operations target stable logical capabilities; others depend on old geometry. A single blanket rule is not sufficient.

**Required correction:** define an operation matrix keyed by input modality and epoch (logical vs presentation). State what is queued, rejected, routed against the old sheet, or allowed against new logical focus; specify stale-generation checks, cancellation, and recovery. The cap/exhaustion “diagnosed failure surface” at lines 236–242 must specify whether it preserves interaction, drops owners, or terminates the window. Test a persistent layout error while a focused text field is removed and the user continues typing/clicking.

## High — the shared-template / typed-reflection promise needs a realizable ABI

The architecture is compelling: immutable topology plus instance identity, sparse deviations, dynamic regions, and a shared layout solution (DESIGN.md lines 25–39, 54–96). The design also correctly refuses TypeId/function addresses as template ABI (lines 92–96). But “one typed property declaration” currently combines default, allowed operations, validation, equality, reset/merge semantics, phase impact, serialization, inspector metadata, and behavior wrapping (lines 119–147) without defining stable identifiers or version migration for any of them. The inspector/remote/history pipeline later depends on these identifiers (lines 379–406). A TypeId is process-local, a hash alone is not identity, and a &'static str route ID can collide or change meaning across schema versions.

Style/behavior override is also underconstrained. A theme replacing declared values is straightforward; wrapping an activation behavior may add effects, change ordering, bypass authorization, or alter focus/Handoff semantics. “Reset, composition order and precedence are specified once” (line 131) is an intent, not that specification. Define per-property stable field ID/schema version, authorized operations, override order (base → theme → instance → accessibility state, for example), merge/reset law, validator failure, and whether wrappers can emit only declared typed operations. Include migrations and unknown-field roundtripping. Keep arbitrary private component fields opaque.

For code generation, the design correctly says arbitrary aliases cannot be inferred and convenience spelling needs compiling signatures (lines 143–147). Do not imply macros provide zero boilerplate if an application must hand-write every field descriptor. Publish one explicit manual form, generated form, and diagnostics test, and measure descriptor/code-size overhead. It remains a hypothesis that a library-owned schema delivers near-zero authoring boilerplate.

## High — shared layout caching can be correct only with full transitive inputs

The document now names many necessary cache-key components, including actual measured content, definite-size flags, shaping revisions, scrollbar environment, and inherited solver-visible parameters (DESIGN.md lines 283–310). The risk is that “measured content signature” is not a complete dependency protocol. A custom measure function can read external model state, locale, image/video intrinsics, parent data, available inline object metrics, or mutable font services. A key must capture every value read, with revisions, not merely the function identity or output size. Otherwise two different contents with equal size can collide while producing different baselines, line breaks, hit geometry, or accessibility bounds.

Define the cache API as a typed dependency capture (or disallow shared caching for opaque custom measurement). Include nested child solution IDs, content generation, font DB/face/fallback versions, features/variations, text shaping and line-break inputs, locale/writing mode, scale/rounding, scrollbar/safe-area, viewport/constraints, inline objects, and every user-measure read. Validate the key before admitting a cache hit. Test adversarial equal-size strings, same metrics/different semantics, late font fallback, animated intrinsic image size, and a custom measure that reads a changing external value. “Hundreds of identical rows” at lines 285–288 is a plausible benchmark hypothesis, not yet an observed memory or latency win; report solution storage, ref/placement overhead, lookup cost, collisions, cache churn, and eviction bytes against cold layout.

## High — exact translations, support queries, and graphics must share numeric rules

The design makes the right rejection: f64 affine multiplication/addition is not associative, so query-time link-cut/splay aggregation cannot silently reorder composition (DESIGN.md lines 326–341). Its translation specialization still needs its proof stated as enforceable bounds: max local fixed-point coordinate, maximum depth, aggregate i128 range, conversion/rounding rule, viewport-origin subtraction range, and overflow fallback. “Bounded node count” only proves no overflow if maximum translation magnitude and fractional quantization are also bounded. Keep arbitrary affine composition in a deterministic parent-order path; do not let the tree summary become the source of pixel/hit truth absent a certified error bound.

The support-function identity at lines 343–363 is mathematically sound and avoids iteratively rotating an AABB, but a bounded sampled-direction hull is only conservative if its construction and outward rounding are proven. Record the exact representation (vertex hull, support directions, or both), tolerance in device-space units, repeated-transform drift budget, rebase condition, and fallback. For transformed shapes, support bounds can be tighter than AABB, but they do not themselves solve clipping, exact hit testing, or filter sampling. Structural tags must be pushed/transferred before split/insert/cut (lines 365–372); add adversarial tests where tags are pending across all four edits and where a moved child is inserted into a differently transformed parent.

GRAPHICS.md correctly calls source-over associative only over real arithmetic and requires finite-precision order (lines 41–56), and correctly rejects “SDF = exact AA” (lines 78–112). Do not make damage sublinear solely from a conservative AABB that grows after rotation; use the bounded canonical local support / hull summary, keep exact old and new support, and let uncertainty choose a larger redraw. Validate numerical behavior against a high-precision oracle under deep transforms, near-singular maps, giant scroll offsets, tiny features, fractional translation, clip edges and filter tails. The color and coverage formulae should also be tested in the actual shader precision and selected blend/color-space pipeline, not inferred from real-number algebra.

## Medium — “one pipeline” needs a typed envelope with domain-specific admission

DESIGN.md lines 379–406 gives the right central dispatcher and already forbids coalescing non-coalescible text/click/key transitions. It also lists substantially different producers: direct control, inspector, accessibility, test, worker, remote, and history. These have distinct capabilities, order, trust and retry semantics. Define a common typed envelope such as {origin, owner_generation, source_epoch, FieldKey, operation, impact, admission_stamp, idempotency_key?} with closed payload families and per-origin validation. A remote command is not trusted merely because it deserializes; accessibility actions and tests must resolve capabilities against a committed generation; worker completion needs request stamps; history needs a declared inverse; arbitrary callbacks need conservative invalidation. Unknown schema versions must not be treated as current field IDs.

The live source epoch, logical epoch, presentation epoch, and resource lease generation are four distinct version domains in these documents. Add one diagram and state their relations/monotonicity and conversion points. Every queued item needs a “valid at epoch” rule and ownership of its payload across candidate retry. The concurrency research's excellent worker-lease and bounded-queue analysis does not, on its own, prove this dispatch/admission protocol.

## Medium — geometry-sharing and backend-preservation claims are conditional

DESIGN.md lines 312–377 openly says transform update savings require a backend that retains group transforms or local primitives; it correctly requires flatten/repack accounting. GRAPHICS.md lines 27–39 and 212–233 also describe native layers/webviews as negotiated capability, not a general promise. Preserve that conditional phrasing in all summaries. End-to-end evidence must include scene serialization, driver upload, target repair, GPU fence, OS compositor copies and actual presentation. The 4K RGBA8 byte count in GRAPHICS.md lines 235–247 is an arithmetic lower bound for one image, not a total window-memory estimate; include swapchain count, staging, cached groups, glyph atlases, imported surfaces and in-flight leases in the memory ledger.

Damage's region hierarchy (rectangles → touched-word tiles/rows → full redraw) is a plausible policy, not an optimum established by the cost model. The model at GRAPHICS.md lines 174–210 needs calibration by backend and device, while the fallback must remain conservative. Gaussian truncation needs a numerical tail-error definition in output color/coverage and composition; the phrase “declared tail-error bound” is insufficient until sigma, cutoff, quantization, and accumulated effects specify how it is maintained.

## Medium — document status and proof boundary

DESIGN.md lines 15–20 links a STATUS.md that does not exist under /root/gpui-ce3/reactivity/. Add it or remove the link. State prominently on both design docs which numbers are measured local microbenchmarks and which are unvalidated architecture hypotheses. For example, 0.625 bytes/node topology is payload only and excludes headers/slack (DESIGN.md lines 62–69); Signal size is local-layout only (151–155); Cephal sizes exclude other per-instance costs (306–310). These are useful measurements, but no cited figure establishes end-to-end application memory, frame latency, or native-driver benefit.

## End-to-end omissions that need canonical expansion

Before implementation lock, expand the canonical design to cover these as cross-cutting contracts rather than isolated storage mechanisms:

1. **One API contract:** frame/token construction, handler signature, typed property/source declaration, operation schema IDs, and exact compile-fail cases. Link a minimal compilable prototype and keep its signatures synchronized with the design.
2. **One publication protocol:** source mutation, changed deltas, Handoff, effect queues, derived outcomes, logical commit, presentation commit, focus, and recovery. Define every epoch boundary and amend the old laws explicitly.
3. **One owner/identity protocol:** instance and target generation, template revision, dynamic List slot transfer, worker request, resource lease, schema identity and restored domain ID. State ABA bounds/retirement and stale-command behavior at each crossing.
4. **One cache-validity protocol:** transitive measure/shaping/style/environment dependencies, immutable shared result lifetime, memory/eviction cap, and cold-oracle comparison.
5. **One numerical contract:** fixed-point bounds and overflow, affine parent order, support-summary outward error/rebase, coverage error, clip/filter support, color transfer and blend order, singular handling, and cross-backend tolerance. Every approximation must widen damage/hit conservatively or fall back.
6. **One resource/presentation protocol:** target age, per-target repair history, CPU/OS/GPU release, device loss, native/webview import, queue limits, and counted full-copy fallback. A renderer that re-flattens every primitive must be included in the end-to-end result.

## Recommended adjudication order

1. Resolve the source/logical atomicity amendment and layout rollback amendment against final/08-runtime.md; do not implement both interpretations.
2. Settle the frame construction API with compiling and compile-fail examples.
3. Amend delta and Handoff contracts for coarse owner scanning/commit behavior.
4. Specify epoch routing while presentation lags, then test pointer/keyboard/IME/a11y during persistent presentation failure.
5. Specify schema and cache dependency identities, then validate shared-template and shared-layout adversaries.
6. Freeze numeric and damage error contracts before claiming logarithmic update or sublinear rendering.
7. Benchmark complete app-visible paths and report the bad regimes and memory high-water marks as well as the winning regime.

The main risk is not that any one proposed data structure is too unusual. It is that source, derivation, layout, interaction and display each currently have a different plausible commit story. A compact representation becomes useful only after those stories agree on one owner, one set of versioned inputs, and a clear rule for which coherent state every observer sees.
