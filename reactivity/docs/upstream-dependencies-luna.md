## What this means for the cleanroom

There is no named-dependency version update to make: every requested family is already at its current stable release in the audited lock. Do not describe Winit `0.31.0-beta.3` as a stable upgrade. The precise actionable distinction is **release freshness versus source provenance**: Parley/Engine, Fontique, fearless_simd, WGPU, Winit, and the vendored AccessKit packages have release-source commits that can be compared directly; Cephal's source is intentionally a named branch snapshot with GPUI patches, and its live upstream branch tip was not established here.

The release pin does not make the local archives identical to upstream behavior. The audited workspace patches WGPU, Core/HAL, Winit, Parley/Engine, and AccessKit base/consumer/macOS/Unix/AT-SPI-common by local path. Their local patch ledgers are part of the real dependency contract: see `reactivity/vendor/{parley,parley_engine,wgpu}/GPUI-PATCHES.md`, the matching AccessKit patch ledgers, and `reactivity/vendor/PROVENANCE.md` at the audited commit. In particular:

- Parley 0.12 is not a drop-in continuation of the old 0.11 adapter assumptions. The local Parley ledger records the current character-based `ClusterPath`, source-range/glyph lowering, cursor ownership, and batching repairs. The 0.12 Engine docs still describe correct line reshaping as in progress and recommend breaking at `Atom`/`ShapedCluster` boundaries. The local Engine ledger pins HarfRust 0.12 because 0.14 removed buffer/cache APIs used by this release; blindly updating transitives would require a separate shaper migration. [Engine API notes](https://docs.rs/parley_engine/latest).
- `fearless_simd` 1.1.0 has runtime x86 multiversion dispatch and scalar fallback support. The Canvas manifest deliberately enables `force_support_fallback`; production code dispatches through `Level`/`dispatch`, while tests exercise the fallback. Upstream documents additional x86 code-size from multiversioning. This pin is current, but future SIMD API work should keep scalar fallback and the workspace's platform targets in its compatibility matrix. [Feature and dispatch documentation](https://docs.rs/crate/fearless_simd/latest).
- WGPU 30.0.1 is both current stable and the exact upstream source commit used by the local archive. The local WGPU/HAL shader and presentation seams are authored deltas on that base, not an upstream API guarantee. Updating later requires replaying those deltas and retesting backend/device feature admission, error scopes, and platform presentation lifetimes.
- AccessKit's lockstep versions are important: local exceptional-unit/schema behavior spans base, consumer and native adapters. The local provenance explicitly warns that upstream-only readers cannot interpret the private encoding; a future refresh must update the coordinated packages and revalidate all patched adapters together.
- Cephal's latest release line is current by version, but the code the cleanroom actually builds is the specifically archived `perf/cold-layout` tree plus a handful of local patches. “Latest Cephal” therefore cannot be reduced to just changing a version number. The upstream manifest declares Rust 1.90; `reactivity/Cargo.toml` has no workspace `rust-version`, so this minimum is not expressed centrally.

The published release source SHAs above are frozen provenance markers. GitHub's current branch-history endpoints did not provide a verifiable moving HEAD in this pass; no claim is made that a release SHA is today's `main`/`trunk` tip. This matters especially for Cephal, where the report keeps its exact pinned branch revision separate from the latest registry version.
