# Proposed constant-range tile subtype: review and gates

Status: **proposed, not implemented**. This is a code-path/design review of `/tmp/gpui-uniform-packet-root/reactivity` (the inspected source has `MAX_DRAWS = 65,536`, `MAX_REFERENCES = 4,194,304`, and `UNIFORM_TILE = 1 << 31`). No builds, tests, benchmarks, or speed claims were made for this proposal.

## Candidate and representation

The current fragment shader has one direct-tile fast case: `range.y & 0x80000000` returns `load_draw(range.x).color`; ordinary tiles use a 4×4 sample lattice and ordered source-over (`crates/gpu/src/shader.rs:421-460`). The CPU currently gives that marker only to a final single opaque full-tile draw; otherwise it constructs CSR ranges and counts 16 sample evaluations per pixel (`crates/gpu/src/renderer.rs:860-933`). `full_tile` is a conservative coverage certificate: solid source, alpha exactly one, sign-safe color, clip containment, and canonical plus packed-f32 transform margins (`renderer.rs:1228-1298`).

Add a *constant-range* subtype for tiles whose retained list consists only of draws certified to cover every lattice sample with a solid color. Keep the current direct single-opaque encoding. For the new subtype use the existing high bit on `range.y` and a nonempty CSR endpoint: `range = [start, end | UNIFORM_TILE]`; the current direct marker remains `[draw_address, UNIFORM_TILE]` whose low endpoint bits are zero. Since every nonempty CSR endpoint is at least one, the shader can distinguish direct from constant-range as `high && low_endpoint == 0` versus `high && low_endpoint != 0`. The constant branch loops `INDICES[start..end]`, loads each draw color, and performs exactly the same ordered `source + dst * (1 - source.a)` recurrence once per pixel, without geometry, clip, mask/image, or lattice work. Empty remains `[0,0]`.

The classification must use the existing `full_tile` certificate, and only `full_tile` may discard the earlier prefix / move `cursors[tile]`. A merely full-tile translucent solid proves sample independence, but does **not** prove independence from the prior backdrop. It can join an already constant suffix; it cannot reset that suffix to itself. A later non-full draw forces the tile back to the sampled path while retaining the current safe opaque cutoff. Do not admit images, masks, rounded rectangles, or other geometry through this subtype.

## No-allocation classification in the existing CSR word

During forward binning, `ranges[tile][1]` is currently just the reference count. Its high bit is spare while this temporary count is live: the code asserts `MAX_REFERENCES < 1<<31` and `MAX_DRAWS < 1<<31` (`renderer.rs:18-27`). Use that bit temporarily as `SAMPLED_REQUIRED`:

- Increment the low 31-bit count for every retained draw.
- On any draw that fails `full_tile`, set `SAMPLED_REQUIRED` and increment the low count.
- On a `full_tile` draw, preserve the current reset `[address, 1]` and `cursors[tile] = ordinal + 1`, which also clears the sampled tag. A later full-tile solid does not set it; a later non-full draw does.
- In normalization, extract `count = y & !SAMPLED_REQUIRED`, preserving the existing one-opaque direct marker when `cursor != 0 && count == 1`. Assign ordinary CSR offsets as today. After reverse filling, set the high bit on the final endpoint only when the sampled-required tag was clear; otherwise leave it clear.
- In reverse fill, mask the temporary high bit for count/mode tests. Keep the cursor cutoff unchanged. Set final constant endpoint bits only after reverse filling, so reverse writes use the existing start cursor unchanged.

This adds no per-tile array, header, or allocation. It does add a tag test/set to each visited tile during forward binning, mask/branches in normalization/reverse fill, and a distinct shader branch plus a CSR traversal for constant ranges. The high-bit dual use is phase-local and should be documented in named helpers/constants; do not let a tagged temporary count reach a shader buffer. Assert `MAX_REFERENCES < UNIFORM_TILE` and that all nonempty end offsets remain below it. The direct marker and constant CSR range are distinguishable only because nonempty endpoints cannot be zero.

A useful control is **not** to attach the constant tag if the retained suffix has any non-full draw. Once tagged, a later non-full draw clears constancy; a later full-tile draw cannot restore it unless it is the opaque `full_tile` reset, because the earlier partial draw still affects some samples.

## Arithmetic and numerical boundary

For a constant certified suffix, every one of the 16 samples starts with the same clear and processes the same ordered solid colors. Thus all 16 per-sample results are equal componentwise. In the existing reduction (`anchor` is sample 0; each `delta += (color-anchor)*0.0625`; final `anchor+delta`), equal values make each difference zero and the accumulated delta `+0` under ordinary IEEE round-to-nearest. The proposed one-pixel result is therefore `color + (color - color)`, not bare `color`, to preserve the final addition's zero normalization on targets where signed zero is observable.

The host admits at most 65,536 draws (`renderer.rs:18,703`), source RGB magnitude at most `1e20` and alpha in `[0,1]` (`canvas/src/color.rs:92-110`; renderer clear is also bounded at `renderer.rs:710`). For each component, let `M=1e20`, `B_n` bound the current destination, and `u=2^-24`. The source-over factor `q=1-alpha` stays in `[0,1]`. With normal-result relative rounding and a conservative absolute underflow allowance `eta`, one recurrence is bounded by

`B_(n+1) <= (1+u) * (M + (1+u)*B_n + eta) + eta`.

At `n <= 65,536`, the multiplicative rounding growth is below about `1.01`; even the coarse `n*M` bound with this headroom is below `7e24`, far below f32 max (`~3.4e38`). Taking `eta` as the f32 smallest normal to cover flush-to-zero, its accumulated contribution over all steps is negligible versus that bound. Alpha stays bounded in `[0,1]`. Consequently no admitted source-over intermediate can overflow to infinity/NaN, so `color-color` is not `inf-inf` or `NaN-NaN`. Subnormal RGB inputs/results do not invalidate the magnitude bound; FTZ can turn them into signed or unsigned zero and so does matter to exact output bits.

This is a finite-range proof, not a cross-driver bit-identity proof. WGSL defines f32 values as IEEE binary32, but permits implementations to ignore the sign of zero and flush eligible subnormals; it also leaves rounding mode unspecified. WGSL's f32 `+`, `-`, and `*` are specified as correctly rounded, yet actual shader compilers may simplify `x + (x-x)` under their legal target assumptions. See [WGSL §15.7.2 and §15.7.4](https://gpuweb.github.io/gpuweb/wgsl/#floating-point-evaluation). Therefore retain the expression only if exact current-vs-candidate GPU readbacks pass for +0/-0 clear, negative zero color, positive/negative subnormals near the FTZ boundary, and ordinary finite HDR values on each supported backend. If a backend's output contract requires bit equality that WGSL cannot guarantee, keep the old reduction for that backend or reject the subtype; do not claim the formula alone proves bitwise equality.

## Work removed, work retained, and statistics

For a tile pixel with `N` retained full-tile solids, today the shader evaluates coverage/sampling and source-over 16 times per draw (the implementation shares decode over each sample row but still has 16 point samples and 16 recurrences; `shader.rs:434-449`). The candidate keeps the ordered `N` source-over recurrences per output pixel and removes the 16 sample/coverage evaluations and 15 duplicate recurrences per draw/pixel. It does not remove the per-pixel output or the per-pixel loop over `N` colors, does not allocate a retained high-resolution texture, and does not reduce CPU bin visits. It may save most when many pixels share a tile with several uniform solids; for `N=1`, it is a modest sample/coverage simplification beyond the current direct opaque path (and still needs one index for a translucent singleton).

The current `sample_evaluations` and `sample_draw_evaluations` stats (`renderer.rs:921-933`) should count only the sampled path. Add a separate constant-composition count (tile pixels × retained draws) or rename/document counters; otherwise the stats misleadingly report zero shader work for constant tiles. Count `constant_tiles` separately from the existing `uniform_tiles` (which currently means one direct opaque draw). Report fallback/sample-work shares in the validation fixture, but treat these as work counters, not timings.

## Falsifying cases and gates

- Exact GPU readback against the existing shader for: all-equal positive zero, negative-zero clear and source channels, +/- smallest and near-smallest subnormals (including FTZ), alpha 0 and 1, and finite HDR extrema; run on all supported shader backends.
- Every prefix/suffix state transition: empty; translucent full-tile singleton over nonzero clear; multiple full-tile solids; partial then full opaque reset; full opaque then partial then full translucent; full translucent then partial; clipping exactly on tile edge; transform margin just inside/outside `full_tile`.
- Prove constant mode never contains a non-full draw and that only the existing opaque `full_tile` reset changes `cursors` or discards a prefix. Add debug assertions over tagged count/end bounds and guarantee temporary tags never reach `TILES`.
- Check that constant branch uses same draw order and f32 color decode as sampled branch. Do not shortcut with the last color or reorder/aggregate colors: f32 source-over is order-sensitive.
- Reject the subtype if shader branch/code growth or CPU classification raises baseline costs for the important fallback mix; decide from measured runs only after exact readback gates.

## Addendum: reuse the opaque-prefix cursor as a sampled-tail seed

This is a second, independent subtype bit proposal; it reuses information already established by `cursors[tile]` and needs no new coverage walk or tile buffer. In the current source `bin_draw` sets `cursors[tile] = ordinal + 1` only when the draw passes `full_tile`, has alpha exactly one, and has no negative-sign zero/subnormal channel (`renderer.rs:1158-1171`). Normalization preserves that cursor and uses it to omit all earlier ordinals; the reverse CSR walk retains precisely `reverse_ordinal + 1 >= cursor` (`renderer.rs:863-871, 914-920`). Therefore, for any non-direct range with `cursor != 0`, its first CSR index is the certified safe opaque draw at ordinal `cursor - 1`. Reverse fill writes references in ascending painter order; the first surviving draw lands at `range.x` after the decrements. This relation should be asserted/tested, because the optimization depends on both CPU walks continuing to share that ordinal convention.

Reserve bit 29 as `OPAQUE_PREFIX` on the final `range.y`, alongside `CONSTANT_TILE` bit 30 and `UNIFORM_TILE` bit 31. The maximum CSR reference count is only `4,194,304`, so it fits in 29 bits; add a compile-time `MAX_REFERENCES < (1<<29)` assertion and mask final endpoints with `0x1fffffff`. Set `OPAQUE_PREFIX` during normalization for a non-direct range when `cursor != 0`; leave the current direct single-opaque marker unchanged. Do not set it from `full_tile` alone during binning: only a retained safe opaque reset (which sets the cursor) certifies the prefix.

For an opaque-prefix **sampled** range, fetch the first reference once, initialize all four sample-row accumulators to that opaque color, and iterate source sampling from `start + 1`. This removes the opaque prefix draw's clip/geometry test and blend from all 16 sample points per pixel while preserving the tail's sample positions and order. For a constant range, initialize the one-pixel recurrence from the same prefix color and iterate its constant-solid tail from `start + 1`. A constant range with a direct-only one-draw suffix still uses the existing direct marker; an opaque prefix plus later draws has at least two references and is represented as a range. Empty ranges have no cursor and are unaffected.

The sign restriction remains important. Replacing the opaque prefix recurrence with its source color is safe only because the cursor is set by alpha=1 and excludes negative-zero / negative-subnormal source components; a merely opaque-looking but unsafe-sign color must leave `cursor` zero. Earlier content remains discarded only under this existing rule. Tail sampling remains unchanged, including masks, images, rounded shapes, clipping, transforms, and HDR colors.

### Color-only load path

The current `load_draw(address)` fetches placement metadata, local rectangle, both affine words, clip, material color, and decoded resource (`shader.rs:50-62`). The constant-tile loop currently calls `load_draw(...).color`, so it needlessly carries local/affine/clip/resource data for a schema that has already proved every retained draw is solid and full-tile. A prefix fast seed has the same opportunity. A small `load_draw_color(address)` can fetch `WORDS[address + 1]` only for its `.w` common-state pointer/slot flag, compute `state_base + GLOBALS.material_offset`, and use the existing `load_color(material_word, atlas.w)` helper (`shader.rs:38-42, 50-60`). This preserves both inline and paint-bank resolution without duplicating bank/material decode. For compact groups, the existing placement metadata already points to the group's shared common block and carries the slot flag, so it follows the same helper path.

This removes per-pixel reads/decodes of local rectangle, inverse rows, clip, and resource variants for every draw in a constant range, and removes those reads for the one prefix draw in a sampled range. It still reads placement metadata and the shared material word (plus bank payload for slot colors); it does not remove the constant range's per-pixel ordered loop or the sampled tail's per-sample geometry work. Shader compiler inspection must verify that selecting `.w` from the metadata word avoids fetching/keeping the other placement lanes in the target backend; source-level field selection alone does not prove storage transaction width.

### Counters and falsifiers

For a sampled tile with an opaque prefix and `T` tail draws, charge one prefix color evaluation per output pixel and 16 source/coverage evaluations per tail draw per pixel; the prefix contributes zero `sample_draw` calls. For a constant tile with an opaque prefix, charge one prefix color evaluation plus one color fetch/composition per tail solid per pixel, not one per lattice point. Keep the direct one-draw opaque statistic as-is. The current counters (`renderer.rs:925-938`) should split prefix color loads from sampled-tail source evaluations rather than silently counting the skipped prefix as either 16 calls or zero work.

Falsify with: cursor=0 ordinary ranges; direct single opaque range; partial draws before safe opaque reset; safe opaque then partial tail; safe opaque then translucent full-tile tail; constant translucent prefix with no opaque cursor; banked and inline prefix colors; compact-group prefixes; signed-zero and subnormal channels on the opaque source; and exact shader readback comparison to the unseeded path. In every non-direct cursor case, assert that `INDICES[range.x]` resolves to the draw at ordinal `cursor - 1`, and that the decoded prefix color matches the sampled shader's first-draw color at all 16 lattice points. Keep the current compiler/HDR exactness controls: this proposal removes an operation sequence and relies on the already-enforced opaque-prefix bit contract, so readback remains required across target backends.
