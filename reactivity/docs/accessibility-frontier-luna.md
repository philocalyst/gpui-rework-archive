# Accessibility frontier: concrete work removals and failure gates

Research pass: 2026-10-20. Read-only against `/root/gpui-ce3/reactivity` and primary framework/specification sources listed below. Target design is the exclusive `&mut Win<M>` owner, borrowed `Part<'a>` over an acknowledged `Presented` sheet, stable window-qualified non-reused `Target`, and explicit source/prepared/presented epochs. The report does not change production code.

## Recommendation

Keep accessibility inside the existing committed-presentation protocol. The `Presented` sheet already supplies the correct logical place for semantic queries, focus synchronization, and native tree updates. Build one bridge-facing AccessKit update from that sheet and its impact log; do not introduce a second toolkit-owned semantic tree. Let AccessKit’s adapter retain its required native-side tree. Construct the full initial tree only when an assistive-technology activation asks for it, and queue native actions into the ordinary `Win` input barrier.

For lists, distinguish a stable application `RowKey` from a currently actionable `Target`. Publish accurate set size and item position for realized rows. On UIA, represent non-realized rows through `ItemContainer`/`VirtualizedItem` support; `Realize`/`ScrollIntoView` must queue a list reveal and wait for an acknowledged presentation before a fresh actionable target is issued. This supports access to a large data set without creating 250,000 row elements or making an old target live again.

The highest-risk contract gap is geometry. `Presented` currently stores viewport-clipped physical bounds for hit and semantic query use. UIA requires an element’s full transformed screen rectangle even if it is partly offscreen, with visibility reported independently. Keep that distinction explicit. Given the current flat local-to-window transform, emit transformed, unclipped window-physical bounds with no AccessKit node transform; putting every absolute node transform into AccessKit would transform descendants a second time.

## What the sources establish

AccessKit is a good native boundary, not a free compact semantic store. Its architecture uses renderer-pushed full initial state followed by incremental updates; only its platform adapter must retain the complete tree. Its `TreeUpdate` is a `Vec<(NodeId, Node)>`. The docs advise sending only changed nodes and say adapters suppress needless events but still pay to process and replace nodes included in updates. Every update also carries the latest focus node. Thus an inactive bridge can avoid tree allocation and conversion, but an active incremental update should be sparse and must include the root focus value. The `Node` API includes position-in-set and size-of-set semantics for virtualized members. [AccessKit architecture](https://github.com/AccessKit/accesskit/blob/main/ARCHITECTURE.md) and versioned [`TreeUpdate` 0.25.1](https://docs.rs/accesskit/0.25.1/accesskit/struct.TreeUpdate.html), [node schema source 0.25.1](https://docs.rs/accesskit/0.25.1/src/accesskit/lib.rs.html).

Activation and action callbacks are platform-dependent. AccessKit explicitly permits asynchronous initial-tree delivery by the next refresh and says queuing actions asynchronously is preferred to blocking. The Windows adapter supports lazy activation; its docs warn that constructing it inside `WM_GETOBJECT` can cause nested `WM_GETOBJECT`, and its action handler may run on a non-window thread. Apple’s AppKit adapter implements `NSAccessibility`; AccessKit’s architecture notes that adapter threading models differ by platform. [Activation handler 0.25.1](https://docs.rs/accesskit/0.25.1/accesskit/trait.ActivationHandler.html), [action handler source 0.25.1](https://docs.rs/accesskit/0.25.1/src/accesskit/lib.rs.html#3361), [Windows adapter 0.35.1](https://docs.rs/accesskit_windows/0.35.1/accesskit_windows/struct.Adapter.html), [macOS adapter 0.27.1](https://docs.rs/accesskit_macos/0.27.1/accesskit_macos/).

Slint’s current Winit integration demonstrates both a useful incremental strategy and its price. It keeps a `CachedNode` per semantic node with a property tracker and child-ID vector; dirty semantic properties emit just changed nodes, but a structural change rebuilds the whole tree. Its node IDs combine component ID and item index, and it forwards item count/index as AccessKit set size/position. Its event loop first drops the adapter borrow, then invokes a deferred accessibility action. The same source has special text-input child IDs and retained text-input state so IDs survive edits. This is strong evidence for stable IDs and deferred actions, and a warning against copying a per-node tracker/child-vector cache wholesale into a design that already has precise publication deltas. [Slint 1.18.1 Winit source](https://docs.rs/crate/i-slint-backend-winit/1.18.1/source/accesskit.rs), [Slint 1.18.1 event loop source](https://docs.rs/crate/i-slint-backend-winit/1.18.1/source/event_loop.rs). Slint’s 2023 issue documents substantial accessibility overhead in a large-list workload, and its 1.18 changelog reports later fixes for large-list positions and slow focus traversal; treat these as workload evidence, not a universal measured regression rate. [Large-list performance issue #3867](https://github.com/slint-ui/slint/issues/3867), [1.18 changelog](https://github.com/slint-ui/slint/blob/v1.18.0/CHANGELOG.md).

Xilem/Masonry confirms that a renderer and accessibility are separate passes. Masonry calls each widget’s `accessibility` method to fill an AccessKit node and explicitly supports scheduling an accessibility pass without paint. Its `WidgetMut` model also keeps mutations within an explicit owner. It is a sound model for phase separation, but the documented pass is per-widget and does not itself prove subtree pruning or zero work for a clean tree. [Masonry 0.4.0 Widget](https://docs.rs/masonry/0.4.0/masonry/core/trait.Widget.html), [Masonry 0.4.0 `request_accessibility_update`](https://docs.rs/masonry/0.4.0/masonry/core/struct.RawCtx.html), [Masonry architecture](https://github.com/linebender/xilem/blob/main/masonry/ARCHITECTURE.md). Vello is the rendering engine beneath Masonry/Xilem; it provides no semantic tree or native action protocol. Accessibility should remain in the platform/runtime layer rather than be added to draw packets. [Xilem project architecture](https://github.com/linebender/xilem/blob/main/ARCHITECTURE.md), [Vello architecture](https://github.com/linebender/vello/blob/main/ARCHITECTURE.md).

Bevy puts an `accesskit::Node` directly in its `AccessibilityNode` ECS component, with explicit `AccessibilityRequested` and update-management resources. This makes semantics composable in Bevy’s ECS, but it stores the large AccessKit node value per semantic entity and is a poor fit for GPUI’s “no cold per-node object” goal. Bevy 0.19’s `AccessibleLabel` mixin exists because requiring all accessibility data inside one node component was a usability problem for composing reusable templates. [Bevy 0.19 `AccessibilityNode`](https://docs.rs/bevy/0.19.1/bevy/a11y/struct.AccessibilityNode.html), [`AccessibilityRequested`](https://docs.rs/bevy/0.19.1/bevy/a11y/struct.AccessibilityRequested.html), [Bevy 0.19 release note](https://github.com/bevyengine/bevy-website/blob/main/content/news/2026-06-19-bevy-0.19/index.md). Iced’s upstream issue #552 still records accessibility as a large missing cross-platform feature, so it does not offer a mature native design to borrow. [iced issue #552](https://github.com/iced-rs/iced/issues/552).

For virtual lists, two layers are needed. WAI-ARIA’s normative semantics say that when only a subset is present, each exposed member needs a one-based position and the total set size. AccessKit exposes the matching fields. That lets a screen reader announce “item N of M,” but it does not create addressable nodes for all unmaterialized rows. Windows UIA separately defines `ItemContainer` and `VirtualizedItem`: providers can return a placeholder, then `Realize` creates a full element; clients may separately call `ScrollIntoView` because `Realize` alone is not guaranteed to scroll. [WAI-ARIA 1.2 `aria-posinset`](https://www.w3.org/TR/wai-aria/#aria-posinset), [WAI-ARIA 1.2 `aria-setsize`](https://www.w3.org/TR/wai-aria/#aria-setsize), [Microsoft virtualized-item guidance](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-workingwithvirtualizeditems). Do not claim that position/count alone solve find/realize/navigation for every platform.

Geometry contracts differ from the current hit sheet. UIA demands the full screen-space bounding rectangle; no clipping is required for partly obscured/offscreen elements, and `IsOffscreen` reports actual visibility. AccessKit expects physical-pixel coordinates relative to the tree container, top-down Y; its optional transform applies to that node and descendants. AppKit exposes an accessibility frame in screen coordinates, while view layout uses point units. [UIA `get_BoundingRectangle`](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationcore/nf-uiautomationcore-irawelementproviderfragment-get_boundingrectangle), [AccessKit geometry schema](https://docs.rs/accesskit/0.25.1/src/accesskit/lib.rs.html#2506), [Apple `NSAccessibilityFrameInView`](https://developer.apple.com/documentation/appkit/nsaccessibility-swift.struct/screenrect%28fromview%3Arect%3A%29?language=objc), [Apple `NSAccessibility`](https://developer.apple.com/documentation/AppKit/NSAccessibilityProtocol?changes=__3_6_8_3&language=objc). UIA and AccessKit do not mean “clip the bounds to the viewport.”

## Five implementable removals

### 1. Cold-start native accessibility on activation

**Mechanism.** Keep semantic query data available in the acknowledged sheet, but leave native adapter state inactive until the OS asks for accessibility. When activation arrives, walk the current acknowledged epoch and synchronously materialize the complete initial AccessKit tree if allowed by that adapter; do not call app `view`, rerun description, paint, or read mutable source state. Thereafter use `update_if_active` and skip all AccessKit node construction when inactive. AccessKit allows deferred initial-tree delivery within the next refresh when synchronous construction is not supported, but the bridge must not send a fake application placeholder.

**Why this can win.** Ordinary users who never turn on a screen reader avoid the full native-tree allocation, string conversion, node construction, adapter cache, and event generation. This matches Bevy’s `AccessibilityRequested` signal at the whole-app level and AccessKit’s lazy activation path, while leaving the GPUI semantic sheet queryable for tests/inspectors.

**Retained/setup cost.** Keep one bridge-active bit and the already-required epoch/delta state. A cold activation performs O(number of exposed semantic nodes + child links) conversion and temporary allocation; AccessKit’s adapter then owns its required tree. Do not retain a second GPUI `Vec<accesskit::Node>` mirror. If the OS requires updates before activation, record only the current committed epoch/change cursor, not one unused node per element.

**Adversarial case.** A 100,000-element static canvas or list receives activation while the app is otherwise idle. Deferring tree setup to a later paint would leave accessibility blank or stale indefinitely; blocking the UI thread for an unbounded initial tree violates responsiveness. Virtualized containers and a bounded, measured activation path are required.

**Gate.** With bridge inactive, run 1,000 paint-only frames on a 100,000-node retained fixture: require zero a11y-node conversion, zero allocations attributable to native projection, and zero semantic node visits. On 10,000 semantic nodes, activation must return a complete tree from the latest acknowledged presentation without describe/paint/app callbacks and meet a 16.7 ms p95 conversion target on the documented reference machine; report p50/p95/p99 and peak bytes. If this timing is not met, retain correctness and measure a tighter activation representation rather than claiming “immediate.”

### 2. Use the acknowledged sheet plus its impact log as the only GPUI semantic authority

**Mechanism.** Preserve the current `Presented` vector as the shared source for borrowed `Part` queries and platform projection. Feed changed semantic records from the same prepared/presented publication log that drives other incremental phases. Emit only changed semantic nodes, changed parent child lists, and the current focus ID. For the first AccessKit activation, emit all nodes once. Let AccessKit retain its required consumer tree; don’t also retain a separate mutable `A11yTree` or per-node property tracker in GPUI.

**Why this can win.** This removes a second identity map, second semantic diff, second tree lifetime, and per-node observer/cache state. It also keeps the exact same acknowledged epoch visible to tests and assistive technology. AccessKit’s documented design is renderer push + adapter-owned complete cache; its `TreeUpdate` docs explicitly warn that included unchanged nodes are still processed/replaced. Slint shows how a private `CachedNode`+tracker+children representation works, and exposes the cost/complexity that the existing publication log may avoid.

**Retained/setup cost.** A bridge needs a compact activation/update cursor and must transform changed records into `TreeUpdate`’s owned vector. Initial activation owns O(N) conversion; a changed node with no structural change should visit only the changed node and semantic ancestors whose children/derived state changed. Text conversion may clone/refcount retained `Arc<str>` or allocate at the boundary; measure it. Do not clone every unchanged `Node` into an update.

**Adversarial case.** Rename a leaf under a 5,000-child container while AccessKit has already initialized. The leaf’s name changes; no ancestors’ child lists do. A generic tree rebuild, whole-parent rewrite, or a flat all-node serialization can cause O(N) allocations and unnecessary provider events. Conversely, deleting a subtree does require updating its parent child list; sending just a remove-node marker without the parent is invalid under AccessKit’s update contract.

**Gate.** With an active adapter on 100,000 semantic nodes, one leaf name/value update must convert exactly one node and allocate no full-tree vector; adding/removing one child converts that child plus its structurally changed parent, with no unrelated node visits. The emitted update, after applying it to an AccessKit consumer, must equal a from-scratch projection byte-for-byte for role/name/state/children/focus/geometry. Benchmark allocations, bytes, nodes converted, event count, and p50/p99 native update time.

### 3. Store semantic support compactly and pay for text only at the boundary

**Mechanism.** Make standard role and default actions derive from the existing compact `NodeKind`/interactive descriptor. Store a one-byte action mask only when support cannot be derived from `NodeKind` and handler presence. Reuse the already-retained input/text value for accessible name/value where semantics require that relationship; keep `name`, `description`, `value`, and `placeholder` as distinct fields semantically, but represent absent fields as absent and reuse/refcount an existing string when possible. Do not allocate an empty AccessKit `Node`, empty `String`, empty `Vec`, action vector, or per-node `HashMap` for every ordinary visual node. Keep focus as one tree-level focused ID, and derive parent from existing topology. Carry `Part` as a borrow of the acknowledged record and derive `Target`, parent, focus, and supported actions through methods when they are requested.

**Why this can win.** Most nodes are not interactive; some containers have no accessible name/description; the average hot path should not pay one heap allocation or a wide semantic object per visual node. Bevy shows the compositional convenience of a full `accesskit::Node` per semantic ECS entity; Slint shows string conversion and per-node cached state. Those are reasonable choices for those architectures but violate the no-hot-unused-tax objective here.

**Frozen 1-byte action flags critique.** A one-byte mask is a plausible compromise for custom actions and may fit existing struct padding. Don’t reject or approve it from the source declaration alone: assert `size_of::<Presented>()` and `align_of`, record `Vec<Presented>` capacity bytes and cache misses at 100k/1M nodes before/after. If it consumes padding and avoids an identity-map lookup into logical `Node` for every projected node, it likely wins on bridge conversion. If action support is entirely implied by `kind` and mounted handler shape, the byte is redundant and can disappear. Keep dynamic enabled/disabled/value/focus in the acknowledged data model; an action-support mask is not a substitute for those states.

**Adversarial case.** A disabled button has the same “click supported” action capability as an enabled button in some semantic schemas, but cannot currently invoke. A text input has a value that must not be used as its name. A focus update can happen before a new presentation; reading `Runtime::focused` while walking an older acknowledged `Presented` sheet mixes epochs. Keep `name` and `value` distinct; use a tree-level focus field from the epoch the adapter is told to publish; revalidate current operation permissions when a queued action reaches the owner.

**Gate.** Measure retained bytes for 100k generic visual nodes, 100k labels sharing text storage, 100k buttons with default actions, and 100k custom-action controls. Require zero per-node heap allocations for absent semantic text/relationships and no `String`/`Vec` allocation for a present name that can reuse an existing `Arc<str>`. Report `Presented` stride and bytes/node. On a warmed bridge-inactive tree, semantic-only fields must add no allocations or traversals during paint-only publication. Run a separate benchmark where all nodes are interactive to show the losing/dense case rather than extrapolating from sparse controls.

### 4. Make virtual list semantics a keyed virtual-item protocol

**Mechanism.** Retain only realized visible rows and bounded prefetch rows as ordinary `El`s and `Target`s. Expose list `size_of_set` and each row’s one-based `position_in_set` on the currently published visible semantic items. Keep the row’s stable domain `RowKey` for source identity and anchoring. Keep a different, never-reused `Target` capability for each visible retained row lifetime. Native virtual placeholders carry list incarnation + row key, not a stale `Target`. A UIA `Realize`/`ScrollIntoView` request queues `scroll_to_key(RowKey)` through the owner; when the new presentation is acknowledged, the system returns a fresh visible target and routes a further focus/invoke only after revalidation. Do not infer row identity from ordinal or resurrect old `Target`s when the same key returns onscreen.

**Why this can win.** A 250,000-ID list can expose meaningful location/set-count while preserving the list API’s bounded materialization. AccessKit and WAI-ARIA define position/set-size metadata for subsets. UIA’s `ItemContainer`/`VirtualizedItem` are required for querying and realizing elements absent from the tree; `posinset` alone is not equivalent. UIA says `Realize` may not scroll, so explicitly support `ScrollIntoView`.

**Retained/setup cost.** O(N) data IDs or an app index may already be owned by the application, but no O(N) visual elements, targets, row handlers, or accesskit nodes. One list descriptor stores count, key resolver, scroll anchor and source incarnation. Platform virtual placeholders need a stable source key and a way to detect removal/replacement. Other platform adapters need mapped list protocols; do not promise every native stack has UIA’s exact placeholder pattern.

**Adversarial case.** The list is sorted or prepended while a screen reader holds a provider for row K; K’s ordinal changes, K is deleted and a different row takes its old index, or K is removed and later reinserted. Reusing a row-index node ID or reviving `Target(K)` would retarget an old action. Validate key+list incarnation at reveal and mint a new target only for the newly acknowledged visible row. Empty lists and unknown/streaming lengths need the platform’s explicit unknown-set-size representation, not a fabricated count.

**Gate.** For 250,000 unique IDs, 480px viewport, 32px rows, and bounded overscan, require row-builder calls and visible row nodes `<= 15 + 2*overscan`; list size reports 250,000, visible row positions are one-based and correct, and no offscreen/prefetch row is in hit-test or ordinary visible `Target` queries. Request `Realize` and `ScrollIntoView` for row index 200,000: after acknowledged presentation it is visible and focused through the normal barrier, with no more than visible+overscan elements created. Delete K before queue drain and assert the action fails stale; prepend/sort with K surviving and assert K’s data identity remains but the old `Target` stays stale. Compare full row construction against virtual construction at N=100, 1k, 10k, 250k, including cold activation, scroll jumps, key lookups, allocations, and native AT discoverability.

### 5. Keep full native geometry and clipped hit visibility as two meanings over one compact basis

**Mechanism.** Do not store both clipped and unclipped full rectangles per `Presented` node. Preserve the existing local rect, flat node-local-to-window physical transform, parent/clip ancestry, and current clipped hit bounds if ordinary input requires them. For AccessKit, transform each local rect to an axis-aligned unclipped window-physical `bounds` rectangle and omit `Node::transform`; AccessKit’s transform property is inherited, and the current transforms are already absolute to the window. For UIA, return the same full screen-space bounding rectangle and calculate `IsOffscreen` separately from exact intersection with the inherited clips and viewport. AppKit conversion must map physical pixels to its required screen-coordinate/point units in the platform adapter. Pointer activation still checks the original local point through inverse transforms against the original clip chain, not a narrowed approximate AABB.

**Why this can win.** It avoids a second retained full-bounds field while satisfying the OS geometry contract. It also avoids the current clipped rectangle shrinking an offscreen element’s UIA bounds. AccessKit and UIA disagree with using clipped visibility geometry as the semantic bounds. A cached axis-aligned intersection alone cannot provide exact hit membership for arbitrary transformed clips.

**Retained/setup cost.** AccessKit `TreeUpdate` owns the transformed rectangles while the native adapter owns its tree; that is a necessary boundary copy, not a second GPUI cache. Computing transformed AABB is constant work for one node. Checking full clip ancestry costs O(depth) only when requested; for full tree conversion, fold the flat transform/clip state during one ordered traversal. If exact clip shape tests are expensive, cache a compact clip-chain identifier/summary only after measurement and prove the summary is conservative.

**Adversarial case.** A control extends from x=-10 to x=20 and is clipped at x=0; UIA still gets its full bounds (-10..20), `IsOffscreen=false`, while pointer action only accepts points inside the viewport and all original clipping ancestors. A fully clipped control reports `IsOffscreen=true`, but its full element bounds are preserved. A rotated or sheared child under a clip shows why testing a few integer lattice points or clipping only its AABB can accept a representable fractional/continuous pointer point outside the true clipped polygon. A singular parent transform shows why reconstructing relative transforms with parent inverse is not a valid general conversion.

**Gate.** Test translations, negative screen positions, fractional DPI scales, 90° rotation, shear, singular transform, transformed parent/child, nested rectangular clips, and viewport edges. For UIA compare `BoundingRectangle` to the full transformed bounds and `IsOffscreen` to a high-precision polygon/clip oracle. For hit tests, enumerate a dense off-grid representable `f32` point grid around every clip edge and compare to inverse-chain exact membership. Require zero false-positive hit points and no per-node retained full-bounds increase; report bounds conversion ns/node at depth 1/8/32 and full-tree activation cost.

## Critique of the proposed `Part` action context

A borrowed `Part<'a>` is the right shape for semantic queries and adds no per-node object when it is created only during a visitor. The current API proves the pattern: one `&Presented` reference backs role/text/bounds. Extending it with methods for `target`, `parent`, `focused`, supported actions, `name`, and `value` remains compact if each answer comes from the acknowledged record or an existing same-epoch structure. Be careful about `Part` holding copied `Target`, parent `Target`, focus state, and value as separate fields at construction time: that increases visitor scratch size and risks reading logical focus/value newer than the presentation being visited. Prefer accessors; use the target ID already in the node and resolve parent through the existing parent index. Keep `name` absent explicitly when it is not supplied; input text is a value and must not become a label by accident.

Supported action metadata is useful to the bridge. It should mean “this node’s semantic role exposes this operation,” not “this request is guaranteed to succeed now.” A disabled state, row removal, changed domain data, or stale presentation can invalidate execution after the AT request. Normalize native action variants to the same operation/arguments used by ordinary input, enqueue them without holding a `Part` or adapter borrow, then validate window namespace, row/list incarnation, current logical node, and documented epoch barrier inside `&mut Win`. Return a disposition for stale/unavailable actions. No native or app callback runs reentrantly while the bridge/provider is borrowed.

A frozen `u8` mask in `Presented` may be a good store for supported actions if custom actions are not derivable from kind/handler shape. It costs no extra stride if it occupies existing padding, but still has write/cache effects; check measured `size_of::<Presented>()`, vector bytes/node, and native projection lookup cost before choosing. If one extra byte rounds the struct to another alignment bucket, it is a real per-node cost. The important design distinction is static action *support* in the acknowledged epoch versus dynamic action *execution permission* after the request reaches the owner.

## Suggested platform contract amendments

For `07-platform.md §5`, clarify that the committed accessibility projection uses the same acknowledged presentation sheet as semantic test queries; native bridges may lazily materialize on activation; incremental native updates contain only changed semantic nodes/changed parents and always carry current tree focus; all AT actions enqueue through the ordinary owner/input barrier; and native bounds use full transformed geometry with visibility/offscreen separate from hit clipping. “Every standard element has default semantics” should state that accessible name, description, and value are different semantic slots, with no text-input value-to-name fallback unless a widget explicitly declares it.

For `07-platform.md §8` and `10-quality.md`, add separate gates for activation/no-tax, sparse update correctness, native action reentrancy/staleness, virtualized list realization, and full-bounds versus clipped-hit geometry. Existing T1 (activation completeness) and T5 (role/name/action audit) remain, but they do not currently measure allocations, stale provider actions, list realization, or geometry semantics. Register permanent IDs before using them; a proposed naming sketch is `T6` activation/no-tax, `T7` virtual list, `T8` bridge action lifecycle, `T9` geometry. Each gate needs a backend reference machine, enabled/inactive states, screen-reader smoke testing, and a rebuild-from-scratch oracle for the AccessKit projection.

## Scope and losing cases

A native AccessKit adapter necessarily stores a native-facing complete tree after activation. The recommendation removes a redundant GPUI mirror and inactive-period construction; it does not eliminate the adapter cache. Any action invoked by assistive technology must cross an asynchronous/queued boundary on platforms where the callback can be off-thread; an extra small command packet is correct ownership transfer, not allocation to optimize away without evidence. A 1-byte action lane is likely a useful fast field only if stride/cache measurement supports it. At small node counts or with every node richly semantic, full AccessKit construction may beat a complex packed sidecar. Virtualization benefits only lists whose realized work is a small fraction of total row count; ordinary short lists should keep the simple path. Accessibility should remain correct when inactive and must be testable with a screen reader, not inferred from an inspector tree alone. AccessKit itself warns that inspectors can mislead about screen-reader experience. [AccessKit application testing notes](https://github.com/AccessKit/accesskit/blob/main/README-APPLICATION-DEVELOPERS.md).

Comput. 31(3), 2001, DOI 10.1137/S0097539799364092 (static-tree succinctness result); Navarro & Sadakane, “Fully-Functional Static and Dynamic Succinct Trees,” ACM TALG 10(3), 2014, DOI 10.1145/2601073, arXiv:0905.0768 (dynamic operations and space/time tradeoffs): https://epubs.siam.org/doi/10.1137/S0097539799364092 ; https://arxiv.org/abs/0905.0768. These establish compressed representations, not that they beat the existing mutable page/tree index in a dynamic GUI. Keep succinct shape for a frozen template/snapshot experiment, not the active semantic store without a matching query/update benchmark.
- Incremental view-maintenance boundary: Budiu et al., “DBSP: Automatic Incremental View Maintenance for Rich Query Languages,” PVLDB 16(7), 2023; the relational delta algebra is a useful model for sparse semantic updates but does not supply a generic delta for arbitrary UI closures/actions or OS provider lifetimes: https://www.vldb.org/pvldb/vol16/p1601-budiu.pdf ; https://arxiv.org/abs/2203.16684.
