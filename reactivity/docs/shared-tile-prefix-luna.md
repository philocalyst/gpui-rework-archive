# Deep CPU binning work deletion: exact limits and one concrete candidate

Read-only review of shipping `/root/gpui-ce3/reactivity` and GPU candidate `/tmp/gpui-uniform-packet-root/reactivity` at `a81bc7536b002b1f81e1b36137c1c4de543e2204`. No repository edits, builds, tests, or measurements. The strongest implementable deletion I found is an **ordered shared full-bounds prefix** for sampled draws; it uses the existing index vector and does not alter the affine/material planes. The remaining proposals below either reduce only a component of a loop or lose against exactness/output costs.

## Current work and invariants

The candidate admits at most 65,536 draws, 16M pixels, and 4M logical draw/tile references (`crates/gpu/src/renderer.rs:18-27`). A tile is 16×16; each draw's conservative integer bounds determine a rectangular tile visit in `visit` (`:1242-1245, 1327-1333`). Forward `bin_draw` visits every candidate tile to count it, classify full-tile proof/opaque cutoff, and update per-tile range state (`:1153-1194`). Reverse group/placement traversal visits again to fill contiguous per-tile references in painter order, skipping prefixes before each tile's opaque cursor (`:887-935`). This is the exact CSR structure that prevents a per-fragment scan of all scene draws.

The proof path is intentionally narrow: `full_tile` immediately rejects non-solid sources and otherwise checks clip containment plus the four sample-domain corners in both canonical f64 and the packed-high f32/error envelope (`:1262-1325`). `bin_draw` only keeps constant-coverage or opaque-prefix proofs for a `Solid`, and opacity additionally excludes negative non-normal channels (`:1171-1191`). Text masks, images, and rounded sources therefore never establish those certificates. Their per-sample behavior is meaningful: `sample_draw` handles clips, correction near geometry/texel boundaries, image transfer/sampling, masks, and rounded containment (`crates/gpu/src/shader.rs:178-196, 204-272, 274-379`).

Shipping native already bypasses all scene preparation for a same-token redraw and admits paint-only packet edits before falling back to a full render (`crates/gpui/src/native.rs:270-294`). The proposal targets changed scenes that still contain large sampled draws; it does not duplicate those existing shortcuts. Failed scene attempts revoke replay eligibility before preparation (`renderer.rs:665-690`); retain that order and install a packet only after successful submission (`:973-1053`).

## Candidate 1 — share an initial full-bounds sampled prefix across tiles (recommended spike)

At present, a full-canvas-bounds image or mask in the initial painter prefix is appended once per tile by forward counting and again visited per tile by reverse CSR fill. Its content still has to be sampled at all 16 points per pixel, so an opaque/background shortcut is unsafe. But its address list is identical for every tile, and the current per-tile CSR stores the same ordered prefix `T` times.

**Recognition without a new pass:** after validating scene headers and before tile initialization, inspect the first `PreparedDraw`. Only open this path if its clipped integer `bounds` exactly span `[0,width)×[0,height)` and `!source.is_solid()`. In the existing forward placement loop, continue this prefix while each next draw has the same full-bounds/non-solid property; close it permanently at the first failure. Full bounds here means “must be considered in every tile,” not “covers every pixel”; actual clip, affine geometry, rounded corners, masks, and image alpha remain decided by `sample_draw`. `PreparedScene::groups()` is the canonical ordered draw partition (`crates/canvas/src/canvas.rs:755-817, 899-938`), and the placement word addresses advance in painter order (`renderer.rs:776-849`), so the resulting shared list is already sorted by the same key as local CSR entries.

**Storage and order:** use the existing `references` Vec as `[global-prefix addresses][local tile CSR]`; add no map, buffer, retained scene, or full texture. Count each shared draw's *logical* references as `tile_count(draw)` for the existing 4M limit/stats, but do not call `visit` for it. Start the per-tile prefix-sum offset at `global_prefix_count`; each tile range then points directly into the local suffix after the shared prefix. In the existing reverse walk, shared-prefix records are written backward into the vector prefix (decrementing a scalar cursor); local records use the existing reverse CSR fill. Resource correction and image/mask address patching still run for all records at `renderer.rs:889-935`, and image/atlas preparation remains unchanged (`renderer/images.rs:59-183`, `renderer.rs:1196-1238`).

**Shader order and exactness:** for each sample row, initialize the four sample colors from clear, then apply every global-prefix draw in order, then every local CSR draw in order. This is exactly the old per-tile draw sequence split at a prefix boundary: same draw addresses, sample points, `sample_draw` result, and f32 source-over recurrence. There is no O(P×N) new scan: the shared G draws were already present in each affected tile's range. When `OPAQUE_PREFIX` is set for a tile, skip the global prefix and retain the current clear-based first-opaque operation; the opaque cutoff has already made that prefix dead for that tile, and using the global backdrop there could change signed-zero results. Likewise, keep the existing direct `UNIFORM_TILE` return for a later opaque singleton. A shared non-solid prefix invalidates the initial `CONSTANT_TILE` assumption for every tile, so initialize that tag false when the first draw qualifies; later opaque-solid resets may reestablish it. The empty-local-range fast return must continue through sampling if a global prefix exists. These three branches are essential, not optional cleanup.

`sample_evaluations` / `sample_draw_evaluations` must include G×16 prefix `sample_draw` calls per pixel on tiles that do not discard them through `OPAQUE_PREFIX` or the direct uniform path; a sampled prefix is not the once-per-pixel opaque-solid shortcut. Thus even a tile with no local refs has `area*16` samples and `area*16*G` draw evaluations when the prefix is active. For a tile with `OPAQUE_PREFIX`, use the existing formula and omit G because the global prefix is discarded; a direct uniform tile likewise has zero sample evaluations. Preserve the old logical `original_tile_references` definition (`renderer.rs:80-101, 1054-1077`) separately from actual index words uploaded; do not silently redefine either diagnostic.

**Cost and break-even:** with T tiles, G initial full-bounds sampled draws, and R suffix references, current work/materialization is roughly `2*G*T` tile visits and G*T repeated indices, plus suffix work. The shared prefix removes those visits and leaves `G+R` actual indices; GPU still evaluates the same G+local sequence per sample. At T=1 it saves no repeated references and adds a prefix branch, so skip. At 65,536 tiles, one such draw changes 65,536 address words (256 KiB) into one word, and removes 131,072 forward/reverse visits. Logical reference limits must remain `G*T+R`, so this is not permission to admit previously rejected large scenes.

**Why this covers mixed text/image scenes:** a full-window background image, full-window mask, or rounded sampled source followed by ordinary glyph-mask tiles enters the shared prefix; glyphs remain in local CSR. If the first draw is solid, not full-bounds, or any later draw fails the prefix condition, the renderer falls back to its existing path from then on. This is compatible with paint-slot updates because the prefix still points at the same record/color-bank word; no record is removed. `GpuSurface::render_paint` still owns packet-token validation and revokes before writes (`gpui/src/native.rs:276-294`).

**Falsifying cases:** full-window RGBA image with alpha 0/partial pixels, linear sampling, Display-P3/linear pixels, rounded image, and a mask whose coverage is not full; follow each with local glyph masks and with an interleaved later full-bounds draw (which must stay local). Compare exact HDR/SDR readbacks with proofs on/off. Include suffix solid opaque coverage on one tile to prove global prefix suppression under `OPAQUE_PREFIX`, direct `UNIFORM_TILE`, and exceptional signed-zero paint. Include a valid prefix followed by a later invalid draw and confirm the old packet remains revoked. Test prefix-only scenes and tiles with no local refs. Keep `MAX_REFERENCES` based on logical fan-out.

## Candidate 2 — full-bounds draw sharing with an arbitrary-order merge (more general, probably not worth it)

If a full-bounds sampled draw occurs after local draws, it cannot join the prefix without reordering. One can put all full-bounds addresses in a scene-wide ordered stream and all other addresses in per-tile CSR, then merge the two streams by the placement record address in the fragment shader. Addresses are monotone because placements are emitted in scene order; no additional ordinal lane is needed. This still uses the existing indices buffer, but adds a two-stream merge per draw per sample row and changes the proof protocol. A later solid opaque cutoff must suppress all global addresses before its cutoff. That requires an address cutoff visible to the shader or a different per-tile header; current `cursors` is CPU-only and current uploaded `range` has both CSR offsets plus proof/end bits. The simpler safe mode is to disable tile proofs whenever merge compression is active, but that can turn a one-sample/direct-uniform tile into 16-sample rendering. If all scenes are restricted to sampled non-solid sources, there are no such cuts, yet the merge branch still costs on every fragment. Use this only if workloads have many interleaved full-bounds images and index memory/CPU binning is the measured bottleneck; do not make it the first spike.

## Candidate 3 — row-interval certificates for affine full-tile coverage

For one fixed draw, each local coordinate is affine in device `(x,y)`. At a fixed tile row, the full-tile tests in `full_tile` reduce to four inequalities per local axis on the two horizontal sample extremes; clip containment is also a row/x interval. In principle, solve a conservative x-tile interval per row, then verify its first and last tile with the existing f64/f32 certificate. The current margin is linear in `|x|` and `|y|`, which are nonnegative within the viewport; split only where coefficient signs choose different extreme corners. This can replace repeated coefficient narrowing, eight corner-dot evaluations, clip checks, and error arithmetic for interior opaque-rectangle tiles.

It **does not remove the tile visits needed by CSR**: even certified opaque interiors must update per-tile count/cursor and eventually produce a tile-specific suffix list. A bulk slice fill still stores O(T) range/cursor words; a lazy 2D range-assignment tree adds state and must be materialized before the fragment shader can use the current direct tile lookup. If certificate classification becomes an interval mask, retain exact fallback for edge/boundary tiles and for near-guard/cancellation cases; never replace current proof with a raw transformed AABB. This is a plausible arithmetic reduction for many overlapping opaque solid rectangles, but it does not help text/image, because `full_tile` rejects their source kinds before any affine math. The global sampled prefix above deletes actual draw×tile visits without replacing this proof math.

**Adversaries:** rotated thin rectangles have little or no full-tile interior; near-edge affine cancellation makes conservative intervals empty; small glyph-like rectangles are masks and never use the proof; and high-overlap groups may pay interval setup per draw while still visiting every tile. A falsifiable prototype should count removed full-tile evaluations separately from unchanged tile visits and prove endpoint monotonicity for both canonical and packed-f32 envelopes.

## Candidate 4 — 2D difference-array tile counts (valid only as a narrow no-proof path)

For a draw's rectangular tile bounds `[x0,x1)×[y0,y1)`, four signed corner updates in a `(columns+1)×(rows+1)` difference grid, then a 2D prefix sum, recover conservative bbox-hit counts in O(draws+tiles) instead of O(R). In `tile_proofs=false`, there are no opaque resets/cursors; this can replace the forward count writes, while the reverse walk still enumerates each tile reference to fill CSR. Counts can reuse `ranges[].x` if arithmetic is checked; right/bottom edge updates outside the real grid can be omitted, but signed accumulation and scan order need explicit bounds.

For the default proof path this does not solve the hard part. `bin_draw` visits each draw/tile in painter order to test `full_tile`, set the latest opaque cutoff, and maintain constant tags. A rectangle difference array is additive and cannot represent those ordered per-tile resets; a range-assignment surface plus a separate suffix-count pass would add a data structure/pass, while CSR fill remains Ω(number of surviving references). A full-canvas draw in a 65,536-tile scene saves no work if prefix-sum O(T) replaces one O(R) pass only when proofs are off; with sparse tiny draws, O(T+4D) is worse than O(R) and the final reference pass remains.

**Adversaries:** T=65,536 with a handful of one-tile glyphs (`R≈D`, scan grid dominates); ordinary default proofs enabled (still must visit every R); and an opaque solid late in the painter order (simple counts overestimate surviving CSR after per-tile cuts). This is a diagnostic-only/thresholded optimization, not a general scene algorithm.

## Related primary work and limits of the analogy

Linebender's current architecture describes Vello CPU/GPU as flattening paths, binning them into tiles, and representing them as sparse horizontal strips; fully covered regions are compact while boundary coverage is retained. That is a real broader redesign, not a replacement of this renderer's current reference array: [Vello architecture](https://github.com/linebender/vello/blob/main/ARCHITECTURE.md#sparse-strips-renderers). Its tracking description calls out tile generation, sorting, and run-length-compressed path coverage, and explicitly frames conflation-free compositing as a separate goal: [Vello sparse-strip path-rendering issue](https://github.com/linebender/vello/issues/670). The sparse-strips README identifies its implementation as under active development, so it is an idea source, not a dependency recommendation: [pinned Sparse Strips README mirror](https://skia.googlesource.com/external/github.com/linebender/vello/%2B/08576de9df7d4b8f4108fe4fd5a436bd69146c43/sparse_strips/README.md).

A closer precedent is Vello Hybrid's attempted full-viewport background optimization: it proposes piggybacking a qualifying rectangle on clear, but the discussion explicitly says blending makes that transformation less straightforward and reviews conditions around order/transform. This review's shared sampled prefix does **not** replace a draw by clear; it only deduplicates its per-tile address references and leaves the sample/compositing operation in place: [Vello PR #1622](https://github.com/linebender/vello/pull/1622). The thesis linked from Vello's architecture discusses sparse strips as a separate CPU/GPU pipeline, not a local CSR trick: [ETH Zürich thesis PDF](https://ethz.ch/content/dam/ethz/special-interest/infk/inst-pls/plf-dam/documents/StudentProjects/MasterTheses/2025-Laurenz-Thesis.pdf).

No proposal here claims measured speed. Candidate 1 is the one that is structurally attractive enough to spike first: it has no new allocation or retained state, preserves the existing uniform planes and exact pixel recurrence, and removes both CPU tile visits and repeated index words for a useful sampled prefix.
