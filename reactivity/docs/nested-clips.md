# Nested analytic clipping

`El::clip()` declares descendant clipping by the element's local rectangle and uniform corner radius. `clipped(...)` admits literal, direct and mapped bool values. The closed property catalog exposes this as `property::CLIP` (code14, existing Flag family, Geometry destination); inspector overrides and source updates use the same authority as radius. Canvas capabilities remain internal to ordinary applications.

The lower-level Canvas API creates immutable parent prefixes with `create_clip(parent, ClipShape, transform)`. Rectangles and uniform rounded rectangles are the complete closed shape domain. Draw methods accept either the previous canvas-space Rect or a ClipId. Clear, replacement and aborted candidates invalidate their capabilities. A checked monotonic owner identity cannot wrap or reuse a pointer address; a NonZeroU64 also keeps optional handles 16 bytes. A parent must belong to the current owner and have an older index. Depth 64 and 16,384 nodes are checked before resource allocation.

Canonical geometry lives once in an optional arena within the existing image/resource extension. Each 104 byte node stores the local rectangle, admitted f64 inverse, conservative bounds, a separate certified raster rectangle, authored radius and packed parent/depth. There is no per-draw copied clip vector or added ordinary draw/common/placement field. One closed NaN marker in the private scope rectangle refers to the arena; authored input remains finite by admission. Public PreparedDraw/PreparedGroup clip rectangles remain finite conservative bounds. Borrowed clip-chain views carry the analytic geometry separately.

Axis-aligned rectangle-only prefixes lower through the existing sampled_rect_clip helper. That proves equivalence only at the fixed 4x4 raster lattice. Continuous point queries continue to evaluate the admitted geometry, including points between lattice sites. Other prefixes retain the general path. A primitive mask is ANDed with every ancestor mask before blending; separately filtered coverage alphas are never multiplied. Identical nested rounded clips therefore preserve exactly the same boundary coverage as one clip. Opaque full-tile and lowered-solid certificates decline complex chains.

The GPU consumes a material-independent five-word (80byte) node record in the existing WORDS prefix, before immutable image/material tails. Draw and common packet strides, material bits and storage bindings remain unchanged. Parent addresses refer strictly backwards; preparation enforces the same node limit and a 1,310,720 byte clip packet budget. Certified rectangular prefixes can terminate traversal. The bounded general shader performs up to 64 ancestor predicates at each actual sample. CPU/Fearless use ordered f64 arithmetic; WGSL retains the existing compensated-pair rounded predicate and its precision admission. This does not prove every possible CPU f64/WGSL circle tie equivalent, or admit geometry rejected by the existing GPU precision/FTZ safeguards. The CPU renderer remains the fallback for such admission failures.

Acknowledged GPUI geometry stores the clipping flag in the existing sparse radius record's closed marker, preserving the radius's author bits and full identity in one 16 byte record. GeometryStyle grows 4 to 8 logical bytes; sparse `(identity, GeometryStyle)` entries remain 16 bytes. Ordinary Node 40, Presented 64, Style 88 and El 176 byte headers remain unchanged. Decoration, ElementExtra and image declaration padding carries their flags. A transient optional ClipId column costs 16 bytes per mounted node only while a clipped scene is prepared. No extra P/C Arc snapshot or per-draw/frame clip Arc increment is introduced.

Continuous GPUI own-shape and viewport hit testing now uses Canvas's existing rounded predicate even when radius is zero. The old subtract-first rectangular inverse could disagree at a tie: scale f32(0.1), translation f32(0.3), point.x=translation produced local0 in Core but a tiny negative local coordinate in Canvas. These ties now follow the existing paint predicate. Outer rectangle edges remain half-open and circular edges closed; no raster snapping enters input geometry.

Native projection remains in flat window-physical coordinates. One optional typed AccessKit HitTestShape carries local f32 bounds/radii and the frozen inverse in 72 bytes, leaving native rectangular extents and text coordinates intact. Own radius and descendant radius may differ, preserving a rectangular scrolling viewport with rounded paint. The common consumer checks clips_children during descendant traversal and checks clipping ancestors when a point query starts at a subtree. ExcludeNode still allows descendant traversal; ExcludeSubtree blocks it. Unix AT-SPI, macOS and Windows provider source paths all call this consumer. Local execution evidence must be distinguished from cross-platform source/dependency inspection.

Ordinary AccessKit indices use one more byte (87 to 88); this occupies previous alignment padding. Node 128, Properties 112 and PropertyValue 40 byte headers are unchanged. Shape values are sparse boxed allocations on rounded/clipping/transformed projected nodes. They are part of the normal source-qualified projection, not a second GPUI snapshot or a native wire-protocol field.

The feature has real retained and preparation costs. The Canvas/DisplayList headers remain 488/288 bytes, but an existing resource extension grows 80 to 88 bytes even for image-only scenes. A clip arena adds 32 bytes. Current Vec growth initially reserves four 104 byte nodes: one root costs three allocations requesting 536 bytes, including 312 bytes of spare node capacity. Clear/rebuild releases this arena; these costs recur on a rebuilt scene. PreparedDraw and the private borrowed CPU command each grow 16 transient bytes; the public Clip argument grows 8 over Rect. The GPU stores 80 bytes for every canonical node whenever a general chain is used, including unused nodes; axis-only draws need no GPU clip table. Qualification records exact current capacities and ordinary/cold headers rather than claiming a universal memory or allocation improvement.

This bounded implementation retains O(depth) continuous ancestor queries and O(depth*16) general raster predicates per visited pixel, plus O(nodes) scene preparation and GPU clip-word packing. It does not implement paths, independent per-corner radii, inverse masks or arbitrary clip Boolean operations. It also does not implement speculative convex-row compression. The material-independent resource boundary can support a later proved coverage representation without changing declarative clip ownership or acknowledged hit authority.
